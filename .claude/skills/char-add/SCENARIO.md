# 단계 1·3 — 시나리오 작성

> char-add 워크플로우의 절차 문서. 진입점·게이트 규칙은 `SKILL.md`.
> 아래 **Step 1~8은 이 문서 안의 작업 순서**다 — 워크플로우 **단계 1~4**와 다른 층위다.

캐릭터 한 사이클 동작 시나리오 작성. 두 모드가 워크플로우의 서로 다른 단계다:
- **단계 1 — 초안 모드**: 파싱 *전*. 원본 스킬 텍스트로 메카닉 이해·모호 점 질문·검증 스쿼드 결정. 결과는 단계 2(`PARSE.md`)의 입력.
- **단계 3 — 보강 모드**: 파싱 *후*. 파싱 결과로 효과 요약 표·타임라인·체크리스트를 stat 단위로 정밀화. 결과는 단계 4(`IMPL.md`) Phase D와 이후 버그 수정의 검증 기준.

---

## 모드 판별

`data/parsed_skills.json` 해당 캐릭터 항목 존재 여부로 결정한다.
- 없음 → **초안 모드**(단계 1). `scraper/nikke_scraped.json [캐릭터명].스킬` 원본 텍스트 사용.
- 있음 → **보강 모드**(단계 3). parsed_skills + 기존 시나리오(있으면) 양쪽 사용.

`scraper/nikke_scraped.json`에도 없으면 멈추고 `char-scrape` 스킬을 안내한다.

---

## Step 1 — 자료 수집

공통:
1. `data/parsed_nikke.json`의 해당 캐릭터 — 무기 유형, 본인 버스트 쿨다운, 버스트 단계.
2. `context/GAMEPLAY.md` §스쿼드 구성 + §트리거 발동 의미 (필수). §트리거 발동 의미는 이미 확정된 일반 규칙 — 그 안에 답 있는 항목은 모호 점 후보에서 제외.
3. **작성 사이클 수**: 본인 쿨 20s → 1사이클, 40s → 2사이클.

초안 모드:
4. `scraper/nikke_scraped.json [캐릭터명].스킬` 원본 스킬 텍스트·values·쿨타임.

보강 모드:
4. `data/parsed_skills.json`의 해당 캐릭터 모든 효과.
5. `context/scenarios/<이름>.md` 초안(있으면) — 검증 스쿼드·모호 점 답 재사용.

---

## Step 2 — 검증 스쿼드 결정

GAMEPLAY.md §표준 테스트 스쿼드에서 본인 버스트 단계·쿨다운 맞는 템플릿 1개 기본 선택.

**조건부 효과 스캔 → 추가 스쿼드 필요 여부 판단**:

초안 모드에서는 원본 텍스트의 자연어 조건 단서를 찾는다 (예: "기본 버스트 단계가 Step 1인 아군이 없다면", "후열에 배치됐을 때", "특정 무기/클래스/코드 아군"). 보강 모드는 parsed_skills의 condition·target 필드로 정확 매칭:

| 패턴 (보강 모드 키) | 초안 모드 텍스트 단서 | 추가 스쿼드 |
|---|---|---|
| `no_burst1_ally`/`has_burst1_ally` (등 N=1,2,3) | "기본 버스트 단계가 Step N인 아군이 없다면/있다면" | 양쪽 |
| `back_row` | "후열에 배치됐을 때" | 본인 후열 위치 변형 |
| `allies_weapon:X` / `allies_class:X` / `allies_code:X` | "X 무기·클래스·코드 아군에게" | 해당 아군 포함 변형 |
| 모드 전환·게이지가 특정 캐릭터 행동에 의존 | 트리거 캐릭터 명시 텍스트 | 트리거 캐릭터 포함 변형 |

대부분 캐릭터는 표준 1개로 끝. 추가 후보 발견 시 유저에게 "이 효과 검증 위해 추가 스쿼드 N개 제안: ..." 형태로 컨펌. 모호하면 묻고 진행.

확정 목록은 시나리오 "## 검증 스쿼드" 절에 기록.

## Step 3 — 효과 요약 표

초안 모드 (스킬 단위 자연어):

| 스킬 | 출처 텍스트 요약 (블록별) | 핵심 메카닉 키워드 |
|---|---|---|
| 스킬1 | "■ ... 시 자신에게 [...] [10초 유지]" 자연어 요약 | 모드 전환/스택/조건부 |

stat 키는 미기입. 원본 `■` 블록 단위로 1행씩. 메카닉 키워드 칸에 "모드 전환", "스택 누적", "본인 한정 캐스터" 같이 분류 단서를 적어 다음 단계 파싱·질문에 활용.

보강 모드 (효과 단위 stat 키 포함):

| ID | 출처 | 트리거 | stat / 효과 | 대상 | 지속 |
|---|---|---|---|---|---|
| <효과명(parsed_skills key)> | 스킬N | <timing+condition JSON 키> | <stat: 값> | <self/target/aoe/...> | <초/영구> |

`parsed_skills.json` 효과를 1행씩.

## Step 4 — 타임라인 작성

표 형식 이벤트 순서. 빈 칸은 유저 질문 대상.

| t (예상) | 이벤트 | 발동 효과 | 대상/지속/스택 | 비고/의문점 |
|---|---|---|---|---|

최소 이벤트:
- `t=0` battle_start / passive 발동분
- 1·2·3버스트 사용 시점 (스쿼드 템플릿 기준)
- 풀버스트 진입 (대략 `t≈10s`)
- 풀버스트 중 누적 변화(스택, 게이지)의 시간별 윤곽
- 풀버스트 종료 (`t≈10s + full_burst_duration`)
- 사이클 종료 / 다음 사이클 진입 조건
- 2사이클 작성 시 본인 버스트 미사용 사이클의 빈 슬롯 명시

검증 스쿼드 여러 개면 각 스쿼드별 타임라인 별도 (소단원).

초안 모드는 이벤트·자연어 동작 중심. 보강 모드는 효과 ID·stat 키 포함.

---

## Step 5 — 스킬 간 상호작용 정리

타임라인이 *언제* 발동을 보여준다면, **어떤 스킬이 어떤 스킬에 어떻게 의존하는지의 메커니즘 그래프**는 별도. 다음 패턴 발견 시 시나리오 "## 스킬 간 상호작용" 절에 풀어 적는다:

| 패턴 | 단서 |
|---|---|
| 버프 → 대미지 스케일링 | `atk_caster_based_pct`·`atk_buff_mag_pct`·`dmg_scale_mag_pct` 또는 원본의 "공격력 ▲"+"추가 대미지" 결합 |
| 스택 생성 → 소비 | `buff_stack_add`/`self_stack_above:N`/`buff_stack_remove`, 원본의 "N 중첩"+"중첩 복사"/"삭제" |
| 모드 전환 → 무기/스킬 변경 | `weapon_change`/`burst_stage_override`, 원본의 "버스트 단계 변경"/"무기 변경" |
| 게이지 충전 → 소비 | `gauge_charge`↔`gauge_consume`/`gauge_above:N`, 원본의 "게이지" 명시 |
| burst_cast 보류 대미지 | `bonus_damage` + `timing: burst_cast` |
| 풀버스트 진입 1회 평가 | `fullburst_duration` 등 진입 시점에만 읽히는 값 |
| 본인 한정 캐스터 조건 | `target: self` + 캐스터 의존 버프 |
| 순환 강화 | A 발동 → B 트리거 → B가 다시 A 조건 충족. 무한 루프 점검 |

작성 형식:

```
- **<효과 X>의 값은 <효과 Y> 활성 여부에 따라 달라짐**
  - 경로: 효과 Y(stat: ..., timing: ...) → 효과 X 계산 시 합산/곱
  - 시점: Y가 X 발동 직전에 활성이어야 함
  - 위험: Y 만료 후 X 발동 시 약화. 검증 항목으로 둘 것
```

**특수 메카닉(모드전환·게이지·스택·무기변경·순차공격 등) 보유 캐릭터는 필수** — 특히 **동일 timing에 복수 효과가 발동하면 실행 순서를 여기서 명시 해소**한다(Step 6 최빈 사각지대와 직결). 진짜 단일 효과 캐릭터만 생략 가능.

## Step 6 — 모호 지점 유저 질문 (필수)

텍스트만으로 명확하지 않으면 묶어서 질문:
- 모드 전환 트리거가 모호한 경우
- 같은 효과 중복 발동 시 갱신/병행/스택
- "본인이 1버스트일 때"처럼 캐스터 조건이 있는 듯한 효과
- 스택 누적 조건이 텍스트로 불분명
- 풀버스트 진입 시점 1회 평가 vs 매 프레임 평가 모호
- 게임 내 실제 사용 패턴이 텍스트와 다를 가능성
- **효과 실행 순서(동일 timing 내)** — 같은 시점 여러 효과의 순서가 결과를 바꾸는가: 충전→발사→소비 / 버프→대미지 / 폭발→제거 / 스택읽기→제거. *(최빈 사각지대. 기계적 트립와이어·회귀 스냅샷으로 안 잡힘 — 반드시 능동 점검)*
- **파싱 오역/누락** — 절대값 vs 비율, `배율 N%▼`=×(1−N), 스케일링 항 누락, 한 clause의 복수 효과 분해 등 텍스트→키 오독. *(최빈 사각지대)*

유저 답변은 시나리오 "## 유저 확인 사항"에 그대로 기록.

**일반 vs 특이 분류 (답 받은 직후 필수)**: 각 답이 이 캐릭터에만 해당인지 모든 캐릭터 공통 일반 규칙인지 판별. 일반 규칙이면:
- 시나리오 유저 확인 사항에 기록 (유지)
- **추가로** `context/GAMEPLAY.md` §트리거 발동 의미 해당 timing/condition 아래 한 줄 누적. **효과 실행 순서·파싱 오역 클래스도 일반 규칙이면 §효과 실행 순서(일반)에 승격** — 매번 재발견되지 않도록.
- 갱신 후 유저에게 "GAMEPLAY 승격 항목: ..." 보고

---

## 해석 선언 (보강 모드, 필수)

모호함을 *인지했든 안 했든*, **대미지 크기·실행순서·스케일링·모드전환에 관여하는 효과**는 각각 한 줄로 해석을 명시한다. AI가 확신한 해석도 표면화해 유저가 검토에서 오독을 잡게 하는 forcing function(모호성 인지에 의존하지 않는 게 핵심). 사소한 buff는 제외.

| 효과 | 해석 | 근거(텍스트/시나리오 라인) | 대안 해석이었다면 |
|---|---|---|---|
| <name> | X로 해석 | "..." | Y였다면 <결과 변화> |

시나리오 "## 해석 선언" 절에 기록. 초안 모드는 생략(파싱 전이라 stat 미확정).

---

## Step 7 — 체크리스트 생성

시나리오 끝에 단계 4(`IMPL.md`) Phase D·이후 버그 수정이 직접 사용할 체크리스트 절.
(절 제목은 `## impl/bug-fix용 검증 체크리스트`로 굳어져 있다 — 기존 시나리오와 맞추기 위해 그대로 쓴다.)

초안 모드: 자연어 거시 항목만 (예: "풀버스트 진입 시 모드 전환 적용 확인").
보강 모드: stat 키·발동 횟수·사이클 간격을 정밀하게.

- 풀버스트 진입 시 활성화되어야 하는 버프 목록
- 한 사이클 동안 기대 발동 횟수
- 발동되면 안 되는 효과 (네거티브)
- 사이클 간격 기대 (기본 12.5s ±)
- 상호작용 검증 항목 (Step 5 작성 시)

---

## Step 8 — 저장

`context/scenarios/<캐릭터명>.md`. 폴더 없으면 생성.

**파일명 정규화**: 콜론 `:` → `_` 치환 (Windows 파일명 금지). 예: `라피 : 레드 후드` → `라피 _ 레드 후드.md`. 문서 본문·표·검증 스쿼드 안의 캐릭터 키는 원본 그대로.

보강 모드 시 기존 파일 덮어쓰기. 초안 모드의 모호 점 답·유저 확인 사항은 보강 본에도 보존.

## 완료 후 — 유저 보고

본문 메시지에 다음 항목을 명시:
1. 시나리오 파일 위치 (마크다운 링크)
2. **검증 스쿼드 목록**: 각 스쿼드를 `["...", "...", ...]` 그대로 복사 가능한 파이썬 리스트 형태로 나열. 변형이면 조건 한 줄씩.
3. 아직 답 안 받은 모호 점 질문 (있으면)
4. GAMEPLAY 승격된 항목 (있으면)
5. **해석 선언 요약** (보강 모드): 대안 해석 시 결과가 크게 달라지는 효과 위주로 유저에게 노출
6. 다음 단계 제안 — 초안 모드 종료 → 단계 2(파싱) / 보강 모드 종료 → 단계 4(구현).
   **유저 승인 전 자동 진행 금지** (`SKILL.md` 단계 게이트).

```markdown

## 기본 정보
- 버스트 단계: B?
- 본인 쿨다운: ??s
- 무기 유형: ??
- 작성 사이클 수: 1 or 2

## 검증 스쿼드
- **표준**: `[..., TARGET, ...]` — 기본 사이클 동작 검증
- **변형 1 (조건: ...)**: `[..., TARGET, ...]` — <어느 효과 검증용>

## 사이클 타임라인

| t (예상) | 이벤트 | 발동 효과 | 대상/지속/스택 | 비고 |
|---|---|---|---|---|

(단일 효과 캐릭터면 생략)

## 유저 확인 사항
- Q: ...
  A: ...

## 해석 선언
(보강 모드 필수 — 대미지 크기·실행순서·스케일링·모드전환 효과)

| 효과 | 해석 | 근거 | 대안이었다면 |
|---|---|---|---|

## impl/bug-fix용 검증 체크리스트
- [ ] 풀버스트 진입 시 활성 버프: ...
- [ ] 사이클당 발동 횟수: ...
- [ ] 발동 금지: ...
- [ ] 사이클 간격 기대: ...
- [ ] 상호작용: <효과 X 발동 시 효과 Y 활성 확인> ...
```
