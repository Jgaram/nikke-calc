# bug-fix

calculator 버그 수정 절차.

$ARGUMENTS: 버그 대상 캐릭터와 증상 설명.

**인자가 없거나 캐릭터명만 있으면 작업을 시작하지 않고** 아래 형식으로 구체적인 정보를 요청한다:

1. 어떤 조건(스쿼드 구성, 운용 방식)에서 발생하는가?
2. 기대되는 동작은 무엇인가? (예: 예상 사이클, 예상 버프 발동 여부)
3. 실제로 어떻게 동작하는가?

**충분한 예시:**
`/bug-fix 라피 : 레드 후드 — 팀에 1버스트 없을 때 본인이 1버스트가 되는 조건에서, 버스트 쿨 20초 감소 효과가 발동하지 않음. 12.52초 간격 사이클이 나와야 정상인데 32초대로 나옴.`

**불충분한 예시 (이 경우 작업 진행 안 함):**
`/bug-fix 신데렐라 딜 수치 이상`

---

## 시작 전 준비

`context/CALCULATOR.md`를 읽는다 (모듈 구조·데이터 흐름 파악).

---

## 스쿼드 구성

`parsed_nikke.json`에서 대상 캐릭터의 버스트 단계와 쿨타임을 확인하고, 아래 템플릿에서 자동 선택한다:

```
B3 대상:         ["리틀 머메이드", "크라운", TARGET, "test_B3"]
B1 (쿨 20s):    [TARGET, "크라운", "신데렐라", "test_B3"]
B1 (쿨 40s):    [TARGET, "리틀 머메이드", "크라운", "신데렐라", "test_B3"]
B2 (쿨 20s):    ["리틀 머메이드", TARGET, "신데렐라", "test_B3"]
B2 (쿨 40s):    ["리틀 머메이드", TARGET, "크라운", "신데렐라", "test_B3"]
```

---

## 재현 및 수정

1. `context/test.py`를 위 스쿼드 구성으로 수정하고 실행 (`python -m context.test`).
2. 버스트 사이클 간격(셀 2 출력)이 **12.5초에서 5초 이상 벗어나면** — 모든 작업을 중단하고 유저에게 스쿼드 구성을 묻는다. 유저 응답 전까지 버그 수정 작업을 진행하지 않는다.
3. 버프 스냅샷·히트 이벤트로 버그를 재현한다.
4. 원인을 파악하고 수정한다.
5. 수정 후 test.py 재실행으로 결과를 확인한다.

---

## 회귀 테스트

calculator 코드를 수정했으면 반드시 실행한다 (`python -m context.regression_test`).

- PASS: 완료
- FAIL: **재시도 없이 중단**. 실제 딜 수치를 유저에게 보고하고 의도한 변경인지 확인 후 지시를 기다린다.

회귀 테스트 운영 상세는 `context/IMPL-STATUS.md` `### 운영` 섹션 참고.
