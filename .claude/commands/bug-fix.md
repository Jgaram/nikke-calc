# bug-fix

calculator 버그 수정.

$ARGUMENTS: 대상 캐릭터 + 증상.

인자 없거나 캐릭터명만 있으면 작업 중단, 아래 정보 요청:
1. 발생 조건 (스쿼드 구성, 운용 방식)
2. 기대 동작 (예상 사이클, 버프 발동 여부)
3. 실제 동작

**충분:** `/bug-fix 라피 : 레드 후드 — 팀에 1버스트 없을 때 본인이 1버스트가 되는 조건에서, 버스트 쿨 20초 감소 효과가 발동하지 않음. 12.52초 간격 사이클이 나와야 정상인데 32초대로 나옴.`

**불충분 (진행 안 함):** `/bug-fix 신데렐라 딜 수치 이상`

---

## 시작 전

1. `context/CALCULATOR.md` 읽는다.
2. `context/GAMEPLAY.md` §스쿼드 구성 읽는다 (표준 테스트 스쿼드·더미 캐릭터 주의사항).
3. `context/scenarios/<이름>.md` 있으면 읽고 증상과 시나리오 항목을 매칭한다. 없으면 증상 관련 효과 1~2개만 다루는 작은 시나리오 절(검증 스쿼드 + 타임라인 + 체크리스트)을 즉석 작성해 같은 경로에 저장 후 진행. 즉석 작성분도 누적.

---

## 스쿼드 구성

시나리오 문서 "## 검증 스쿼드" 절이 있으면 거기 목록 사용. 없거나 즉석 시나리오라면 GAMEPLAY.md §표준 테스트 스쿼드에서 대상의 버스트 단계·쿨다운에 맞는 템플릿 선택. 증상이 특정 조건(예: 다른 B1 아군 부재) 의존이면 그 조건에 맞춘 변형으로 재현.

---

## 재현 및 수정

1. `context/test.py` 스쿼드 수정 후 실행 (`python -m context.test`).
2. 버스트 사이클 간격이 **12.5초에서 5초 이상 벗어나면** — 중단. 유저에게 스쿼드 구성 확인. 응답 전까지 작업 금지.
3. 버프 스냅샷·히트 이벤트와 **시나리오 체크리스트 항목**을 1:1 비교해 버그 재현. 시나리오상 X가 N회 발동해야 하는데 실제는 M회 — 식으로 차이 특정.
4. 원인 파악·수정.
5. test.py 재실행 확인 — 시나리오 체크리스트 전 항목 PASS.

## 회귀 테스트

calculator 코드 수정 시 필수 (`python -m context.regression_test`).

- PASS: 완료
- FAIL: **재시도 없이 중단**. 실제 딜 수치 보고 후 지시 대기.

상세: `context/IMPL-STATUS.md` `### 운영` 섹션.
