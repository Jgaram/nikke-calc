# report

딜량 보고서 생성 — 조합·육성·버스트 운용을 바꿔가며 돌린 결과를 HTML 한 장으로 비교한다.

$ARGUMENTS: 비교할 조합·조건을 자연어로. 없으면 유저에게 묻는다.
예: `/report 돌니스 마스트 앵커 흑련 리버 vs 세이렌 나유타 수렐루 프바 벨벳`

---

## 시작 전

1. `context/REPORT.md` 읽는다 (스펙 형식·필드·시드 정책의 정본).
2. `context/ALIASES.md` 읽는다 (유저 입력은 거의 항상 별칭이다).

---

## Step 1 — 케이스 확정

유저 입력을 **케이스 목록**으로 옮긴다. 케이스 1건 = 스쿼드 + 육성 + 버스트 운용 + 랩쳐.

- **별칭 → 정식 명칭 변환은 여기서 끝낸다.** `ALIASES.md` 표에 없는 축약어는
  추측하지 말고 유저에게 확인한다. 스펙 JSON에는 정식 명칭만 들어간다.
- 스쿼드 배열 순서 = 버스트 우선순위. 유저가 순서를 지정했으면 그대로 두고,
  안 했으면 유저가 부른 순서를 유지한다.
- 언급되지 않은 육성은 **기본값 그대로 둔다.** 임의로 스킬 레벨·장비 옵션을 지어내지 않는다.
- 비교축이 무엇인지 명시적으로 정한다 — 조합 비교인지, 같은 조합의 육성 비교인지,
  같은 조합의 버스트 운용 비교인지. **육성/운용 비교면 나머지 변수는 전부 고정**한다.
- **랩쳐 코드를 유저가 말하지 않았으면 묻는다.** 코드가 없으면 전원 속성 특효가
  꺼진 채로 계산돼 총딜이 크게 낮아지고, 조합 간 우열도 뒤집힐 수 있다.
  코어 크기·파츠 유무도 같이 확인한다 (기본은 코어 없음·파츠 없음).

확정한 케이스 표(이름·스쿼드·무엇이 다른지)를 유저에게 보이고, 애매한 게 있으면
**여기서 묻는다.** 시뮬은 케이스당 수십 초라 잘못 세운 채로 돌리면 그만큼 낭비다.

## Step 2 — 스펙 작성

`reports/specs/<영문-슬러그>.json`에 쓴다. 형식·필드는 `context/REPORT.md`.

자주 쓰는 패턴:

- **버스트 운용 지정** — `config.burst_sequence_cycle`에 사이클 패턴을 넣는다.
  "홀수 사이클엔 A가 2버" 같은 요구는 2개짜리 패턴으로 표현된다.
- **육성 비교** — 같은 `squad`를 케이스 2개로 복제하고 한쪽만
  `chars: { "이름": { "skill_levels": {...} } }`처럼 바꾼다. 이름에 차이를 적는다
  (`"스킬 10"` / `"스킬 7"`).
- **버스트 미사용** — `config.no_burst_char` (1명만 가능).
- **조건 축(탭)** — 같은 케이스를 조건만 바꿔 두 벌 돌릴 때는 `variants`.
  코어 유무·랩쳐 코드·전투 시간 같은 축이 여기 온다. 시뮬 횟수가 배로 늘어나므로
  축을 3개 이상 두지 않는다.

## Step 3 — 실행

```bash
python -m context.report reports/specs/<이름>.json --jobs 8
```

- 케이스 3개 × 10회면 2~4분. 오래 걸리므로 **백그라운드로 돌리고 기다린다.**
- 실패 시 그대로 보고한다. 이름 오류는 즉시 멈추고 스펙을 고친다.
- 표시 형식만 고칠 때는 `--from-cache`로 시뮬 없이 다시 렌더한다.

## Step 4 — 보고

1. 생성된 HTML 경로를 알려준다 (`reports/out/<이름>.html`).
2. 케이스별 **평균 총딜 ± 표준편차(억 단위)** 를 대화에도 짧게 적는다.
3. 눈에 띄는 것만 한두 줄로 — 예상과 다른 순위, CV가 유난히 큰 케이스,
   특정 캐릭터가 기여도를 독식하는 경우.
4. 수치를 **해석**해 달라는 요청이 아니면 분석을 길게 쓰지 않는다. 보고서가 본체다.

---

## 하지 않는 것

- 유저가 말하지 않은 케이스를 **덧붙이지 않는다** (비교군을 임의로 늘리지 않는다).
- 이미지가 없는 캐릭터가 있어도 **재다운로드하지 않는다.** 파일 유무만 보고한다
  (`context/UI.md §이미지 관련 금지 사항`).
- 계산기 코드는 건드리지 않는다. 결과가 이상하면 버그로 분리해 유저에게 보고한다.
