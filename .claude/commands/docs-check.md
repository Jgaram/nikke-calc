# check-docs

코드와 context/*.md 문서 간 불일치를 찾아서 목록으로 보고한다.

## 범위 인수 매핑

$ARGUMENTS 값을 아래 규칙으로 해석한다:

| 입력 | 대상 범위 |
|------|-----------|
| `ui`, `화면`, `앱` | `app.py`, `ui/` 폴더 ↔ `context/UI.md` |
| `calc`, `calculator`, `계산기`, `damage`, `buff` | `calculator/` 폴더 ↔ `context/CALCULATOR.md`, `context/IMPL-STATUS.md` |
| `scraper`, `scrape`, `스크래퍼`, `파싱`, `parsing` | `scraper/` 폴더 ↔ `context/SCRAPER.md`, `context/PARSING.md` |
| `data`, `데이터` | `data/` 폴더 ↔ `context/DATA_VERIFY.md` |
| `all`, `전체`, `` (인수 없음) | 모든 범위 |

인수가 위 표에 없으면 유사한 항목으로 추론해서 처리한다.

## 작업 절차

1. 범위에 해당하는 **코드 파일**을 읽는다.
2. 범위에 해당하는 **context/*.md 문서**를 읽는다.
3. 아래 항목을 교차 검증한다:
   - 함수·클래스·메서드 이름 (문서에 언급된 것이 코드에 실제로 존재하는가)
   - 파라미터·반환값·필드 이름
   - 파일 경로 (문서에 적힌 경로가 실제로 존재하는가)
   - 동작 설명 (문서 설명과 코드 구현이 일치하는가)
   - 삭제·이름 변경된 항목이 문서에 구식으로 남아 있는가

## 출력 형식

불일치 항목마다 아래 형식으로 출력한다:

```
[파일:라인] vs [문서 파일 섹션]
- 문서: "..."
- 코드: "..."
- 판정: 구식 문서 / 미구현 / 이름 불일치 / 기타
```

불일치가 없으면 "불일치 없음" 한 줄로 끝낸다.
