# char-impl

신규 캐릭터 계산기 구현·검증 (Phase C + D).

`/char-parse` 완료 + 유저 승인 후 실행.

$ARGUMENTS: 캐릭터 이름 (예: `/char-impl 신데렐라`)

---

## 시작 전

1. `context/CALCULATOR.md` 읽는다.
2. `context/IMPL-STATUS.md` Step 1-6 체크리스트 읽는다.
3. `context/GAMEPLAY.md` §스쿼드 구성 읽는다 (Phase D 스쿼드 사용 규칙).
4. `context/scenarios/<이름>.md` 읽는다. **없으면 즉시 멈추고 `/char-scenario <이름>` 초안 모드 먼저 요구.** Phase D 검증이 시나리오 체크리스트 기반이라 시나리오 부재 시 진행 의미 없음. **추가로 보강 모드 완료 상태 확인**: 시나리오 헤더에 "모드: 보강" 표기되어 있고, 효과 요약 표가 효과 단위(stat 키 포함)이며 체크리스트가 stat 단위로 정밀화돼 있고 `## 해석 선언` 절이 채워져 있어야 함. 초안 상태(스킬 단위 자연어)거나 해석 선언 절이 비어 있으면 멈추고 `/char-scenario <이름>` 보강 모드 먼저 요구.

---

## Phase C — 계산기 코드 수정

`/char-parse` Phase B 확인 항목 대상으로 IMPL-STATUS.md Step 1-6 필요 항목만 수행.

기존 캐릭터 영향 확인:
- `_BUFFS_ZERO` 초기값 0/False이면 기존 캐릭터는 해당 key를 0으로 받음 → 안전.
- 타임라인 로직 변경은 회귀 테스트로 검증.

---

## Phase D — 테스트

### 스쿼드 구성

**시나리오 문서 "## 검증 스쿼드" 절의 목록 그대로 사용.** 여러 스쿼드면 각각 시뮬·체크리스트 검증. 새 스쿼드 임의 생성 금지 — 필요 시 `/char-scenario`로 돌아가 시나리오부터 갱신.

### test.py 실행

`context/test.py` 스쿼드 수정 후 실행 (`python -m context.test`).

버스트 사이클 간격이 **12.5초에서 5초 이상 벗어나면** — 중단. 시나리오 스쿼드인데 사이클이 깨졌다면 시나리오·구현 둘 중 하나에 문제 있음. 유저 보고 후 응답 대기.

### 체크리스트

**시나리오 체크리스트 1:1 비교**: `context/scenarios/<이름>.md`의 "impl/bug-fix용 검증 체크리스트" 각 항목을 `r.log.buff_summary()`·`r.log.burst_log`·히트 분포와 1:1로 비교. 항목별 PASS/FAIL 명시.

추가 일반 점검:
- [ ] **해석 선언 각 항목이 실제 구현과 일치** — 특히 대안 해석 시 결과가 달라지는 효과(실행순서·스케일링·모드전환). 불일치면 어느 해석이 맞는지 유저 확인
- [ ] 모든 스킬 버프가 버프 스냅샷에 나타나는가
- [ ] 타이밍 트리거(hit_count, pellet_hit 등)가 시나리오 기대값만큼 발동하는가
- [ ] 히트 태그 분포가 시나리오와 일치하는가 (SG 펠릿 수, 버스트 중 변화 등)
- [ ] 기존 스쿼드 수치 변화 없는가

**불일치 발견 시 즉시 유저 보고 후 작업 중단.** 시나리오와 실제 동작 중 어느 쪽이 옳은지 유저 판단을 받는다 — 시나리오를 갱신할 수도, 구현을 고칠 수도 있다.

### 회귀 테스트

타임라인 로직 수정 시 필수. 실행·판정·FAIL 처리: `context/IMPL-STATUS.md` `### 운영` 섹션.
