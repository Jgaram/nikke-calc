# 재화 소모량

육성 한 칸을 올리는 데 **뭐가 얼마나 드는가**만 다룬다. 효율(= 소모량 대비 딜량 Δ)은
`report-growth`가 낸다.

## 정본

| 대상 | 정본 | 비고 |
|---|---|---|
| 모든 표·확률·가중치 | `tables.json` | 손으로 관리하는 유일한 파일 |
| 소장품 기대 소모량 | `kit.py` | `tables.json`을 읽어 계산 |
| 조회 API | `__init__.py` | 바깥에서는 여기만 부른다 |
| 구운 결과 | `../data/cost_expected.json` | **생성물.** `python -m cost.build`로만 갱신 |
| 회귀 | `test_cost.py` | `python -m cost.test_cost` |

원 출처는 상위 폴더의 `종합.xlsx`와 `module/`이다. 두 곳은 저장소 밖이라 import할 수
없어 값을 옮겨 적었고, 어느 시트에서 왔는지는 `tables.json`의 `_주석` 키에 적었다.

## 소장품 관리키트

**메커니즘.** 관리 1회 = 키트 10개. 획득 경험치는 초 200 / 중 500 / 상 1000. 매 회
**대성공** 확률이 있고 뜨면 그 자리에서 목표 레벨에 도달한다. 안 떠도 경험치는 쌓이며
목표 경험치를 다 채우면 확정 도달한다. 대성공 확률은 (직전 회차를 마친 뒤의 레벨,
키트 등급)으로 정해진다.

**목표는 5·10·15만.** 대성공이 구간 끝으로 보내주므로 중간 레벨을 목표로 잡을 이유가
없다. 그리고 대성공이 보내주는 곳은 **다음 구간 끝**이지 최종 목표가 아니다 — 0→15는
0→5·5→10·10→15를 따로 돌려 더한다.

**시작은 0~14 아무 값이나 된다.** 1→5, 8→10처럼 구간 중간에서 출발하는 것도 그대로
나온다 (목표까지 남은 경험치가 `(목표 − 시작) × 레벨당 경험치`로 줄어들 뿐이다).

**등급마다 배합이 다르다.**

- **R은 초급키트만.** R은 전 레벨에서 상급 대성공 확률이 1.0이라 한 회(키트 10개)에 구간이
  끝나버려 통째로 낭비고, 중급도 과하다. 0→15가 초급만 170개인데 상급만 30개 = 424점이다.
- **SR은 셋을 수급 비율대로 섞는다.** 중급·상급 키트는 다른 쓸 곳이 없어 수급되는 대로
  소비하게 되므로, 실제로 쓸 수 있는 비율이 곧 수급 비율이다. 최적 배분은 찾지 않는다.

보고도 이 기준으로 한다 — SR은 세 키트를 다 적고, R은 초급키트 한 줄만 적는다.

**순서는 고르게 편다** (`kit.spread`). 대성공이 뜨면 주기 도중에 끝나므로, 한 등급을 앞에
몰아두면 그 등급이 실제 소모에서 과대 대표되고 점수 환산과 어긋난다.

## 점수

키트 세 등급은 서로 대체 가능해서 숫자 셋으로는 축끼리 순위를 못 매긴다. 그래서 점수
하나로 접었다가, 보고할 때 표준 배합 비율로 되돌린다.

```
점수 = Σ 키트개수 × 가중치        (초급키트 1개 = 1점)
```

가중치는 **희소가치**(30일 수급량의 역비)를 쓴다. 성능 기준이 아니다 — 상급키트가 좋다는
사실은 이미 대성공 확률로 기대 소모량에 들어가 있어서, 가중치에 성능을 또 넣으면 같은
이점을 두 번 세게 된다.

가중치와 표준 배합이 같은 수급량에서 나오므로 한 주기는 세 등급이 점수를 정확히 1/3씩
나눠 갖고, 점수는 곧 **며칠치 수급**으로 읽힌다 (`daily_points()`, 기본 기준 45.4점/일).

## 키트 수급 (30일)

`tables.json`에는 **원시값만** 있고 합계·희소가치·표준 배합은 전부 코드가 거기서
계산한다. 수급처를 더하거나 고치면 셋이 같이 따라 움직인다.

**상자 하나는 셋 중 하나만 준다.** 확률이 각각 정확히 1.0으로 합쳐진다.

| | 내용 | 기대 개수 (초 / 중 / 상) |
|---|---|---|
| 상자1 | 80% 초급 3개 · 20% 중급 1개 | 2.4 / 0.2 / 0 |
| 상자2 | 70% 초급 5개 · 20% 중급 2개 · 10% 상급 2개 | 3.5 / 0.4 / 0.2 |

| 수급처 | 원시 입력 | 초급 | 중급 | 상급 |
|---|---|---:|---:|---:|
| 파견 | 항목표 × 4슬롯 × 30일 | 246.48 | 40.32 | 13.44 |
| 솔로레이드 | 상자1 12 + 상자2 51 | 207.30 | 22.80 | 10.20 |
| 뮤지엄 | 6개월에 3회 × (170/60/30) | 85.00 | 30.00 | 15.00 |
| 고철상점 | 상자2 월 10개 | 35.00 | 4.00 | 2.00 |
| **합계** | | **573.78** | **97.12** | **40.64** |

→ 희소가치 1 : 5.91 : 14.12, SR 배합 초 39 : 중 6 : 상 3 (48회 주기), 57.4점/일.

파견 항목표의 확률 합은 0.80이고 남는 0.20은 마일리지(소장품 조각)라 키트를 주지 않는다.
`kit_supply_by_source()`가 이 합이 1.0인지 검사한다.

### 종합.xlsx의 합계를 쓰지 않는 이유

그 시트는 상자 내용물을 **연쇄로** 곱한다 — 중급 = 초급수량 × 계수, 상급 = 중급수량 ×
계수. 파견 항목표와 솔로레이드 블록 양쪽이 그렇게 되어 있다. 하지만

- 정의 행 `Y14:AB15`의 수식이 `=0.8*3`, `=0.2*1` / `=0.7*5`, `=0.2*2`, `=0.1*2`이고,
- 바로 옆 가치 셀 `AC14`가 `=Z14*1 + AA14*3.5 + AB14*9.5` = 3.1로 셋을 **직접 개수**로 쓰며,
- 상자별 확률이 각각 정확히 1.0으로 합쳐진다.

셋 다 직접 개수 쪽을 가리킨다. 그래서 합계 셀을 버리고 원시값에서 다시 세웠다. 시트의
파견 표에는 그와 별개로 상자2 행에 상자1의 초급값 2.4를 끌어다 쓴 복사 실수도 있다.

리롤은 계산하지 않는다 — 쥬얼을 태우는 기대값 체인이 필요하고, 이 폴더가 안 하기로 한
종류의 계산이다.

## 일부러 빼기로 한 것 (`tables.json`의 `_안다룸`)

자료가 있고 없고와 무관하게 **안 넣기로 결정한 것들**이다. 다시 꺼내기 전에 사유를 본다.

- **크레딧.** 장비 강화에서만 쓰이고 장비 경험치에 비례한다. 따로 세도 순위가 안 바뀐다.
- **소장품 아이템 자체 · 장비 획득 자체.** 가치를 매기기 어렵다. 관리키트와 장비 경험치만
  센다. 그래서 `collection_to()`는 미장착(`"없음"`)에 None을 준다 — 0이 아니라 "모른다"다.
- **콘솔.** 단기간에 올릴 수 있는 축이 아니다. 오래 하면 오르는 것이라 비용으로 잡을 게 없다.
- **애장품.** 비용을 따지기 애매하다. 종합.xlsx에 두 조각(0→1=50, 1→2=110)만 있는 게
  맞고, 더 찾을 것도 없다.
- **호감도.** 비용을 고려하지 않는다.
- **파견 리롤.** 쥬얼을 태우는 기대값 체인이 필요하다. 수급은 리롤 없음 기준으로만 센다.
- **모듈 DP.** `..\module\`의 결과값만 옮겨 적는다. 조합이 늘면 그쪽에서 돌려 값을 추가한다.

## 아직 못 넣은 것 (`tables.json`의 `_미수집`)

**큐브 하나뿐이다.** 시뮬레이터에 `cube.level` 축은 있는데 강화 재화 자료가 없다. 효과값만
종합.xlsx 시공증 시트에 있다. 조회하면 값이 없으므로 `report-growth`는 비용 없이 Δ만 낸다.

## 채워진 축

| 축 | 재화 | 확률 시행 |
|---|---|---|
| 스킬 1·2·버스트 레벨 | 스킬 메뉴얼 / 버스트 메뉴얼 | 아니오 |
| 장비 강화 (T9·오버로드) | 장비 경험치 | 아니오 |
| 돌파 0~3 · 코어강화 0~7 | 뽑기 | 아니오 |
| 소장품 R·SR | 관리키트 초·중·상 | **예** |
| 오버로드 옵션 | 커스텀 모듈 | **예** |

**돌파·코어강화는 한 칸을 1뽑기로 통일해서 센다.** 둘 다 캐릭터 한 장을 먹으므로 같은
재화다. 캐릭터마다 뽑기 확률이 다르지만 그 차이는 다루지 않는다 — 축끼리 순위를 매기는
데는 칸 수로 충분하다. 코어강화는 돌파 3 이후 해금이라 그 순서를 코드가 강제한다.

스킬은 **노랑칩만** 센다. 파랑·보라는 병목이 아니라 가중치 `0 / 0 / 1`로 껐을 뿐, 레벨별
장수는 `tables.json`에 그대로 남아 있고 `skill_manual(...)["breakdown"]`으로 볼 수 있다
(7→10이면 파랑 714 / 보라 505 / 노랑 315). 병목이 바뀌면 가중치만 고치면 된다.

스킬과 버스트는 칩 장수가 같고 먹는 칩 종류만 다르다. 장비 강화는 무엇을 갈아 넣든
경험치가 같아서 재화가 하나뿐이다.
