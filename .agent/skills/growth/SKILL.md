# growth

육성 효율 보고서 생성 — 덱을 고정하고 한 캐릭터의 육성 변수를 한 축씩 움직여
**덱 전체 딜 Δ**와 **그 캐릭터 자신의 딜 Δ**를 각각 낸다.

**인자**: 대상 캐릭터 · 덱 · 보고 싶은 변수를 자연어로. 없으면 유저에게 묻는다.
예: `/growth 돌니스 브리드 수화 디젤 프바 조합에서 브리드 스킬레벨이랑 오버로드 효율`

조합 A와 B 중 뭐가 센지를 묻는 요청이면 이 스킬이 아니라 `report`다.

---

## 시작 전

1. `.agent/skills/growth/GROWTH.md` 읽는다 (스펙 형식·페어드 델타·화면 구성의 정본).
2. `context/ALIASES.md` 읽는다 (유저 입력은 거의 항상 별칭이다).
3. 육성 필드·시뮬 설정·랩쳐 키가 헷갈리면 `.agent/skills/report/REPORT.md`의 해당 절만.

## Step 1 — 조사 대상 확정

유저 입력에서 넷을 끌어낸다. **하나라도 비면 묻는다.**

| 항목 | 확인할 것 |
|---|---|
| 대상 캐릭터 | 정식 명칭. `ALIASES.md`에 없는 축약어는 추측하지 않는다 |
| 덱 | 1~3개. 배열 순서 = 버스트 우선순위. 대상은 자기 단계에서 맨 앞 |
| 랩쳐 | **코드를 반드시 묻는다.** 비우면 속성 특효가 꺼져 Δ 순위까지 흔들린다. 코어·파츠도 |
| 모드 | 스킬 조사인가 옵션 조사인가 — 아래 |

**모드는 둘 중 하나로 정한다.** "육성 효율"이라는 말만 왔으면 어느 쪽인지 묻는다.
스킬과 옵션을 한 보고서에 섞지 않는다 (`GROWTH.md §모드`).

- 스킬 얘기(스킬 레벨·만렙·강화) → `mode: "skill"`. 장비 옵션은 기본 스펙 고정.
- 옵션 얘기(오버로드·공증·크확·줄) → `mode: "option"`. 스킬 10/10/10 고정.
- 둘 다 필요하면 **보고서를 두 개** 만든다.

`mode`가 기준 육성과 축을 다 만들므로 보통 더 물을 게 없다. 다만 **우월코드 축은 기본으로
들어가지 않는다** — 유저가 우코를 물었을 때만 `include_element_bonus: true`를 켠다.
축을 유저가 따로 지정했으면 그것만 `axes`에 덧붙인다. **말하지 않은 축을 덧붙이지 않는다.**

확정한 표(대상 · 덱 · 랩쳐 · 모드 · 축 목록)를 유저에게 보이고 여기서 확인받는다.

## Step 2 — 스펙 작성

`reports/specs/<영문-슬러그>.json`에 쓴다. 형식은 `GROWTH.md`.
모드를 쓰면 대개 `title`·`subject`·`mode`·`enemy`·`decks`만 적으면 끝난다.

축을 직접 적어야 할 때만:

- 축 하나에 변수 하나. 두 개를 같이 보고 싶다는 요청은 `combos`로 옮긴다.
- 단계 라벨은 유저가 읽을 말로. 보고서에 그대로 나온다.
- 기준 단계에는 `over`를 적지 않는다.

## Step 3 — 횟수 확인

```bash
python .agent/skills/growth/growth.py reports/specs/<이름>.json --dry-run
```

케이스 수 × 회차를 유저에게 알린다. **200회를 넘으면 축이나 단계를 줄일지 먼저 묻는다**
(8병렬로 시뮬 100회당 대략 6~10분).

## Step 4 — 실행

```bash
python .agent/skills/growth/growth.py reports/specs/<이름>.json --jobs 8
```

- 오래 걸린다. **백그라운드로 돌리고 기다린다.**
- 표시 형식만 고칠 때는 `--from-cache`로 시뮬 없이 다시 렌더한다.
- 실패 시 그대로 보고한다. 이름 오류는 즉시 멈추고 스펙을 고친다.

## Step 5 — 보고

1. 생성된 HTML 경로를 알려준다 (`reports/out/<이름>.html`).
2. **기준 덱 총딜과 대상 본인 딜**을 억 단위로 적는다. Δ만 적으면 기준을 알 수 없다.
3. 효율 랭킹 **상위 3~4줄**을 덱 Δ%·본인 Δ% 둘 다 붙여 대화에도 옮긴다.
4. `판정 불가`가 난 항목은 **그렇다고 말한다.** 회차를 늘리면 갈릴 수 있다고 덧붙인다.
5. 덱 딜과 본인 딜이 크게 어긋난 항목이 있으면 한 줄로 짚는다 — 이 보고서의 핵심이다.
6. 수치를 **해석**해 달라는 요청이 아니면 분석을 길게 쓰지 않는다. 보고서가 본체다.

## 결과를 보고할 때

보고서 상단 **기본 스펙 이탈 배너**의 내용을 유저 답변에도 옮긴다. `baseline`이 곧
이탈이므로 이 보고서는 거의 언제나 배너가 붙는다 — 기준 육성을 빼고 Δ만 옮기면
유저는 만렙 기준 수치로 읽는다.

## 하지 않는 것

- 유저가 말하지 않은 축·덱을 **덧붙이지 않는다.**
- 재화당 효율로 환산하지 않는다. 비용표가 저장소에 없다.
- 이미지가 없는 캐릭터가 있어도 재다운로드하지 않는다 (`REPORT.md §이미지`).
- 계산기 코드는 건드리지 않는다. 결과가 이상하면 버그로 분리해 유저에게 보고한다.
