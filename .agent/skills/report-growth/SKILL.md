# report-growth

한 캐릭터의 육성 변수를 기준점에서 한 축씩 움직여 **덱 전체 딜 Δ**와
**대상 캐릭터 딜 Δ**를 각각 측정한다.

## 시작 전

1. `references/format.md`를 읽는다.
2. `context/ALIASES.md`에서 정식 명칭을 확인한다.
3. 육성·시뮬·랩쳐 필드가 필요하면 `../report-squad/references/format.md`의 관련 절만 읽는다.

다음을 모두 확정한다.

| 항목 | 기준 |
|---|---|
| 대상 | 정식 캐릭터명 |
| 덱 | 1~3개, 배열 순서가 버스트 우선순위 |
| 랩쳐 | 코드 필수, 코어·파츠 확인 |
| 모드 | 스킬 또는 옵션 |

- 스킬 모드는 메뉴얼 비용과 투자 순서를 함께 계산한다.
- 옵션 모드는 스킬 10/10/10을 고정한다.
- 둘 다 요청하면 보고서를 두 개 만든다.
- 우월코드는 요청했을 때만 축에 넣는다.
- 요청하지 않은 축과 덱은 추가하지 않는다.

확정한 대상·덱·랩쳐·모드·축을 사용자에게 보여준 뒤 실행한다.

## 실행

스펙은 `.report-work/<영문-슬러그>/spec.json`에 둔다.

```bash
python .agent/skills/report-growth/scripts/growth.py \
  .report-work/<슬러그>/spec.json --dry-run
python .agent/skills/report-growth/scripts/growth.py \
  .report-work/<슬러그>/spec.json --jobs 8
```

200회를 넘으면 축이나 단계를 줄일지 먼저 묻는다. 표시만 고치면 `--from-cache`를 사용한다.
결과는 `reports/<슬러그>.html`, 캐시는 `.report-work/<슬러그>/result.data.json`에 생긴다.

## 결과 보고

1. HTML 경로와 기준 덱 총딜·대상 딜을 적는다.
2. 델타가 큰 항목 3~4개를 덱 Δ%·대상 Δ%와 함께 적는다.
3. 스킬 모드면 100장당 효율 상위 3~4개와 만렙까지 총 장수를 적는다.
4. 버스트 메뉴얼은 수급량 차이를 함께 말한다.
5. `판정 불가`를 숨기지 않고 회차를 늘리면 갈릴 수 있다고 적는다.
6. 기본 스펙 이탈 내용을 답변에도 옮긴다.

## 하지 않는 것

- 스킬과 옵션을 한 보고서에 섞지 않는다.
- 비용표가 없는 재화를 임의로 효율 환산하지 않는다.
- 이미지를 재다운로드하거나 계산기 코드를 고치지 않는다.
