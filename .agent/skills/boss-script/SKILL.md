# boss-script

**게임 테이블에는 보스가 스킬을 언제 어떤 순서로 쓰는지가 없다**(AI 행동 트리 에셋). 그래서 순서는
사람이 플레이 영상과 커뮤니티 정리 글에서 읽어 스크립트로 적는다. 이 skill은 그 작업의 절차다.

산출물은 `data/boss_scripts/<프리셋 이름> <보스 한국어 이름>.json` 하나.
포맷의 정본은 `calculator/boss_pattern.py` 모듈 docstring, 프리셋 참조(`preset`·`skill`·`part`)는
`runner/boss.py` docstring이다. **작업 전에 둘 다 읽는다.**

## 0. 준비

| 확인 | 어디 |
|---|---|
| 그 보스가 프리셋에 있는가 | `data/boss_presets.json` — 없으면 먼저 프리셋부터(§6) |
| 진행 기록·유저 결정 | 레포 루트 `보스패턴_설계.txt`(gitignore). **계획·문답은 여기에만 적는다** |
| 엔진이 표현할 수 있는 것 | `calculator/boss_pattern.py` docstring의 kind 표 |

### 모드 — 좌표를 켜는가

보스 모드는 간단 모드(패턴 없음 — 프리셋 스탯만)와 패턴 모드 둘이고, **이 skill이 만드는 스크립트는 늘 패턴
모드다.** 정할 것은 패턴 모드 안의 좌표 스위치 하나다(정본: `calculator/boss_pattern.py` docstring §모드).

관통·발사체 폭발·「파츠 포함」 전체기가 본체와 파츠를 함께 맞히면 파츠마다 대미지가 더 들어간다. 파츠에
**무엇이 닿는가**를 정하는 방식이 좌표 스위치에 따라 갈린다.

| 좌표 | 파츠에 무엇이 닿는가 | 영상에서 읽는 것 |
|---|---|---|
| off (`coord` 없음) | 파츠(1~5)·저지원(1~4)마다 위치 단계 `reach`를 정해 적는다. 무엇을 겨누는가는 조준 순서(아래)가 정한다 | 관통·폭발·전체기가 그 표적에 닿는가 (§2) |
| on (좌표 모드, `coord` 블록) | 표적·코어의 **화면 좌표**를 적고, 엔진이 에임·탄착군·관통·폭발 원으로 푼다 | 자동 에임 위치(기준점)·표적 모양·코어 위치·화면 환산 비율·RL 폭발 크기 ([FRAME-READING.md](FRAME-READING.md) §6) |

**무엇을 겨누는가는 좌표와 상관없이 엔진의 조준 순서가 정한다** — 카메라 니케(레이어 2)는 산 저지원 → 쫄몹 → 벌칙
파츠 → 본체, 나머지는 쫄몹 → 본체(정본: `calculator/boss_pattern.py` §조준). 스크립트에 조준 비율을 적는 칸은 없다
(`share`는 2026-09-19에 없앴고 적으면 거절한다). 그래서 **못 깨면 벌칙이 오는 파츠는 실패 분기를 그 parts 패턴에 직접
달아야** 엔진이 벌칙 파츠로 알아보고 겨눈다(§3).

**좌표를 켤지는 유저가 정한다 — 자료 수집(§1)에 들어가기 전에 반드시 묻는다.** 영상에서 읽을 것이 처음부터
갈리므로(위 표) 나중에 묻으면 판독을 다시 해야 한다. 기본값을 골라 두고 진행하지 않는다.

- 물을 때 위 표의 차이와 현재 상태를 함께 보여 준다 — 좌표 모드로 만든 실제 보스는 S40 하나다(2026-09-19,
  `docs/bosses/사치스러운 거미.md`가 판독·보정의 예시다). 좌표를 끄면 영상에서 조준·닿음만 읽으면 되고, 켜면 표적
  위치·크기·환산 비율·자동 에임 위치까지 재야 한다.
- 코어가 없는 보스의 **자동 에임 위치**는 유저에게 묻는다(S40은 흉부 — 유저 확인). 영상의 폭발 한 번 같은 약한
  근거로 정하지 않는다 — 파츠가 오토 탄에 깨지느냐가 여기서 갈린다.
- 기존 스크립트를 고치는 작업이면 그 스크립트의 지금 스위치(`coord` 유무)를 알려 주고, 그대로 갈지 묻는다.
- 답은 `보스패턴_설계.txt`와 보스 문서(§7)에 적는다.
- **좌표 on으로 시작했는데** 영상에서 표적 위치·크기를 안정적으로 잴 수 없으면(보스가 크게 움직이거나 카메라가
  자주 확대되면) **혼자 off로 바꾸지 않는다.** 무엇을 못 쟀는지 보고하고 다시 묻는다.

## 1. 자료 수집

시각을 주는 자료는 **플레이 영상**이고, 순서·분기를 주는 자료는 **커뮤니티 정리 글**이다. 둘을 대조한다.

- **아카라이브 승리의 여신 니케 채널** — `arca.live/b/nikketgv?target=title&keyword=<보스 이름>`.
  WebFetch는 403이다. **내장 브라우저(`mcp__Claude_Browser__*`)로 열고** 본문·댓글은 페이지 안에서
  `fetch`로 받아 파싱하면 한 번에 여러 글을 훑을 수 있다. 「정보/공략」 글과, 운영법·기믹 처리법 글의
  **댓글**이 특히 값지다(기믹 전환 타이밍·실패 시 거동이 댓글에 있다).
- **패턴 영상** — 「패턴」·「미리보기」·「공략」으로 검색한다. **스킬 설명창과 자막을 달아 둔 영상**이
  제일 좋다. 인게임 스킬 설명창은 프리셋의 어느 스킬인지 이어 주는 열쇠다.
- 영상 설명·타임스탬프는 watch 페이지의 `ytInitialPlayerResponse` → `videoDetails.shortDescription`
  에서 뽑는다(curl + 정규식).

읽을 때 갈라 적을 것:

  보스 AI 상수    구간 길이·다음 패턴까지의 지연·저지 제한시간·그로기 길이 — 스크립트의 뼈대
  플레이 시간     저지를 몇 초에 깼나·쫄몹을 몇 초에 정리했나 — 스쿼드에 따라 변하는 값
  분기           저지 성공/실패, 파츠 파괴/유기, 쫄몹 정리/실패에 각각 무엇이 오는가

## 2. 영상 프레임 판독

절차와 붙여 쓸 코드는 [FRAME-READING.md](FRAME-READING.md)에 있다. 요지만:

- 내장 브라우저로 영상을 열고 **화질을 hd1080으로 고정**한 뒤, 비디오를 캔버스에 합성해
  (전체 화면 + 인게임 타이머 + 스킬 설명창 + 자막)을 **한 장**으로 만든다.
- `seek → draw → screenshot`을 `browser_batch`로 묶어 3초 간격으로 훑고, 구간 경계만 1초 이하로 좁힌다.
- **인게임 타이머는 카운트다운이다.** `t = 전투시간 − 남은시간`으로 바꿔 적는다.
- 저지 UI의 남은 시간 표시를 두 프레임 읽으면 **제한시간**이 나온다(시계는 내림이라 ±1초).
- **성공 시각은 저지 카운트다운이 멈춘 값으로 읽는다**(제한시간 − 멈춘 값). 초 단위로 내림하는 인게임 시계보다
  정확하다 — S40에서 인게임 시계로 읽은 M자 4.5 · 암전 9초가 카운트다운으로는 3.5 · 5.8초였다.
- 영상이 여러 판을 이어 붙였거나, 분기 설명용 다른 판을 작은 화면으로 끼워 넣었을 수 있다. 타이머가 거꾸로 가거나
  둘이 보이면 다른 판이니 분기 자료로만 쓴다.
- **파츠·저지원의 위치 단계(`reach`) 근거도 영상에서 본다.** 관통 사격·RL 폭발·「파츠 포함」 전체기가 본체를 맞힐 때
  그 파츠·저지원 위에도 대미지 숫자가 따로 뜨는가. 관통 범위·폭발 범위 버프가 켜진 구간과 꺼진 구간을 나눠 본다
  (예: 레드 후드 `관통 범위 100% 확장` 10초) — 버프가 있을 때만 뜨면 단계 2 또는 4다.
- **좌표 모드면 표적의 화면 좌표를 잰다** — 환산 비율·기준점·모양·폭발 크기. 절차는 FRAME-READING.md §6이다.

## 3. 스크립트 작성

- 한 줄짜리 패턴마다 `note`에 **인게임 시각(카운트다운)과 근거**를 적는다. 스크립트가 곧 자료의 요약이다.
- 공격은 프리셋 스킬을 `skill`로 참조하고, 발수·간격만 `spec`으로 덮는다. 파츠는 `part`로 참조한다.
- **성공·실패를 둘 다 적는다.** 저지는 `interrupt` + `until: {time: 제한, targets_cleared: true}`로 두고
  `after`의 `outcome`으로 갈라, 두 분기가 다시 만나는 자리(대개 그로기)에서 `after`에 둘을 나란히 적는다.
- 「플레이 시간」은 표적 체력·쫄몹 체력으로 표현한다. 시간으로 못 박으면 스쿼드가 세져도 안 당겨진다.
- 타수 기믹 쫄몹(한 발에 1)은 `hit_hp`·`hit_hp_after`로 적는다.
- **파츠(`parts` 표적)마다 위치 단계 `reach`를 정한다.** 누적이다 — 높은 단계에 닿는 수단은 낮은 단계에도 닿는다.

  | reach | 이 파츠에 닿는 발 |
  |---|---|
  | 1 | 모두 — 관통 · 발사체 폭발 · 「파츠 포함」 전체기 |
  | 2 | 관통은 관통 범위 ▲ 합 100% 이상일 때만 · 폭발 · 전체기 |
  | 3 | 발사체 폭발 · 전체기 (관통은 안 닿는다) |
  | 4 | 폭발은 폭발 범위 ▲ 합 100% 이상일 때만 · 전체기 |
  | 5 | 「파츠 포함」 전체기만 |

  정본은 `calculator/boss_pattern.py` docstring §파츠 다중 타격이다. 근거(영상 시각·글)를 note에 남긴다.
  **근거가 없으면 적지 않고 ⬜로 둔다** — 안 적은 파츠는 다중 타격 추가 딜이 없어 딜이 낮게 나오는 쪽으로 틀린다.
  **저지원(`interrupt` 표적)에는 1~4만 적는다** — 「파츠 포함」 전체기는 저지원에 안 닿는다. 저지원에 닿은 딜은
  총딜 밖이다(`--view boss`의 **[저지원에 들어간 딜]**).
- **좌표 모드**: 스크립트 최상위에 `"coord": {"auto_aim": [x, y], "explosion_scale": …}`를 두고, 표적은
  `reach` 대신 원 `{x, y, r}` 또는 직사각형 `{x, y, w, h, rotation}`으로 적는다(`z`가 크면 앞). 코어는
  `core` 패턴의 `x`·`y`다. **표적 이름은 스크립트 전체에서 하나여야 한다** — 에임 컨트롤(`--aim "니케:표적"`)이
  이름으로 겨눈다(같은 파츠가 여러 번 나오면 `part`에 `name`을 덧붙여 알집1·알집2처럼 가른다). 잰 근거(영상 시각·
  환산 비율)를 note에 남기고, 못 잰 값은 ⬜로 둔다. 포맷의 정본은 `calculator/boss_pattern.py` docstring §좌표 모드다.
- **저지원이 세트로 차례로 나오면**(앞 세트를 깨야 다음 세트) 한 패턴에 몰아 적지 않는다 — 앞으로 나올 저지원이
  처음부터 떠 있어 오토 탄·폭발을 미리 먹는다. 제한시간은 `idle` 타이머 하나(`until: {time: 제한, after: [{node:
  마지막 세트}]}`)가 재고, 세트마다 `interrupt`를 잇는다(`after` 앞 세트 `cleared` + 출현 지연 `delay` · `until:
  {targets_cleared: true, after: [{node: 타이머}]}`). 실패 분기는 타이머의 `expired`, 성공 합류는 마지막 세트의
  `cleared`를 본다. 예: S40 M자 저지.
- **기본 운용(레이어 2)은 벌칙 파츠만 겨눈다** — 벌칙 없는 파츠는 자동 에임에서 떨어져 있으면(좌표 모드) 또는 reach로
  닿지 않으면(좌표 off) 안 깨진다. 그런 파츠를 깨는 운용이 있으면(`--aim`, 좌표 모드) 보스 문서에 적는다.
- **수치가 없으면 note에 `⬜`를 달고 적는다.** 조용히 그럴듯한 값을 넣지 않는다.
- 모델이 아예 없는 것(요격·시야 가림·부파 점수 등)은 넣지 말고 `note`에만 남긴다.

## 4. 보정

저지원 체력·쫄몹 체력/타수는 인게임 표에 없다. **영상이 보여 준 성공 시각을 기준 스쿼드가 재현하도록**
역산한다.

1. 스크래치패드에 반복 실행 스크립트를 둔다(`runner.boss.build_enemy` + `runner.spec.build_squad` +
   `calculator.timeline.simulate`, `rng_mode: expected`). 후보 수치를 인자로 받아 구간 길이를 찍게 한다.
2. 기준 스쿼드 하나를 정해 두고(스크립트 note에 적는다) 2~3회 반복해 맞춘다.
3. 맞춘 뒤 **약한 스쿼드로 한 번 더 돌려 실패 분기가 실제로 열리는지** 본다. 안 열리면 분기를 잘못 적은 것이다.
4. **좌표 모드는 좌표 off에서 맞춘 수치를 옮기지 않는다.** 저지원은 레이어 2(카메라 니케가 겨누고, 풀버스트 동안 전원이
   따라온다)의 탄 분포로 깨져, 겨눈 발이 통째로 들어가는 좌표 off와 배분이 다르다. 좌표 모드로 따로 맞춘다.
5. **클리어 시각은 체력의 계단 함수일 수 있다** — 풀버스트가 저지 도중에 끝나느냐로 갈린다(S40 암전: 한 개 220만
   4.9초 ↔ 230만 6.6초). 이분법은 그 턱에 걸리니 격자로 훑어 평평한 자리를 고르고, 앞 저지를 바꾸면 뒤 저지의 위상이
   통째로 밀리므로 **순서대로** 다시 맞춘다.

## 5. 검증

```bash
python -m runner.sim "<스쿼드>" --boss "data/boss_scripts/<파일>.json" --view boss --expected
python -m runner.boss        # 프리셋 참조 검산
python -m runner.doclint
```

- 패턴이 **의도한 시각에 열리고 닫히는지** 로그로 확인한다. 안 열린 패턴은 조용히 무시되지 않고
  `validate`가 거절하지만, 「조건을 못 만나 영영 안 열리는」 분기는 로그로만 드러난다.
- 좌표 모드면 `--view boss`의 **[에임]**(누가 무엇을 몇 초 겨눴나)·**[파츠에 떨어진 탄]**·**[저지원에 들어간 딜]**로
  에임이 의도대로 갔는지 본다.
- 엔진(`calculator/`)을 고쳤으면 `python -m calculator.boss_pattern`과 `python -m runner.snapshot`
  (33개 스쿼드 무변동)을 함께 돌린다. **패턴을 안 주면 결과가 한 자리도 달라지면 안 된다.**
- 기본 스펙에서 벗어난 설정으로 돌렸으면 이탈 목록을 결과와 함께 보고한다.

## 6. 프리셋이 없을 때

보스 스탯·스킬 계수는 게임 테이블에서 온다. 진입 방법은 `docs/REFERENCES.md`(enikk GraphQL ·
GitHub 게임 테이블 덤프), 옮기는 규칙과 출처 기록은 `docs/DATA_VERIFY.md` §레이드 보스 스탯이 정본이다.
**프리셋에는 스탯·스킬·파츠만 넣고 순서는 넣지 않는다**(유저 결정 2026-09-15).

## 7. 마무리

- **`docs/bosses/<보스 이름>.md`를 쓴다** — 좌표 on/off(유저가 고른 쪽) · 자료 출처 · 흐름과 분기 · ⬜ 어림값(보정 기준 스쿼드까지) ·
  ⬜ 미확인(근거 없이 비워 둔 파츠 위치 단계 포함). 좌표 모드면 좌표를 잰 프레임·환산 비율·`explosion_scale`
  근거도 적는다. **수치·구간의 정본은 스크립트이므로 옮겨 적지 않는다.** 보스별 미검증은 `DATA_VERIFY.md`가
  아니라 여기다(유저 결정 2026-09-17) — 그쪽은 엔진 규칙과 게임 표 읽기의 검증만 맡는다.
- 진행·다음 할 일은 `보스패턴_설계.txt`에 남긴다. 다음 세션이 같은 자료를 다시 캐지 않게.
- 엔진을 고쳤으면 `docs/CALCULATOR.md`의 해당 절도 고친다. `docs/*.md`는 **변경안을 만들어 유저 승인을 받고**
  반영한다.
