# 루주 동작 시나리오

> 모드: 보강 (parsed_skills 반영)
> **역순 작성** — 등록·검증이 끝난 캐릭터의 시나리오를 뒤늦게 채운 문서다.
> 초안(파싱 전) 단계 없음. 수치·발동 시각은 전부 실측이다.

## 기본 정보
- 버스트 단계: B1
- 본인 쿨다운: 20s (더 게임 마스터) → **자체 쿨감으로 실효 13s**
- 무기 유형: SR (6발, 재장전 2.33s, 차지 1.0s, 계수 71.07%, 코어 200%)
- 속성 코드: 전격 · 클래스: 지원형 · 기업: 테트라
- 애장품: **없음**
- 작성 사이클 수: 1 (매 사이클 버스트) — 단, **코인 단계는 5사이클에 걸쳐 오른다**

## 핵심 전제 — 후열 배치가 킷의 전제조건이다

스킬2 첫 블록이 `■ 전투 시작 시 **후열에 배치됐을 때**`로 시작한다. `back_row`는
**스쿼드 인덱스 1 또는 3**으로 판정된다(`docs/IMPL-STATUS.md`).

여기서 실패하면 `소드 코인`이 안 붙고 → `실드 코인`(`self_state:소드 코인`) → `더블 소드 코인`
(`self_state:실드 코인`)까지 **3단 체인이 통째로 죽는다.** 버스트의 조건부 3블록
(`더 게임 마스터 2·3·4`)도 전부 같이 꺼져 **버스트가 첫 블록 하나짜리가 된다.**

실측 (180s, `--expected`, `["크라운", "루주", "test_B3", "스노우 화이트 : 헤비암즈"]` 골격):

| 루주 위치 | 스쿼드 총딜 | 전열 대비 | 소드 코인 수령자 |
|---|---|---|---|
| index 0 (전열) | 1,438,483,746 | — | **없음 (체인 전멸)** |
| index 1 (후열) | 1,457,412,862 | +1.32% | 크라운 · test_B3 · 루주 |
| index 3 (후열) | **1,471,860,731** | **+2.32%** | 스노우 화이트 : 헤비암즈 · 루주 |

index 3이 더 높은 이유는 `allies_adjacent:2`가 **인접 슬롯**을 보기 때문이다 —
그 자리에서 옆에 오는 것이 스쿼드 최대 딜러(스노우 화이트 : 헤비암즈)다.
**루주는 어디에 두느냐가 아니라 누구 옆에 두느냐가 성능이다.**

**`카드 스로우`는 두 항목이다** (buff + instant `카드 스로우 2`). 원문 한 clause에 체력 버프와
쿨감이 함께 적혀 있어서 나온 형태다. `_activate()`는 effect dict의 identity로 버프를 식별하므로
항목이 둘이어도 서로 간섭하지 않는다.
2026-09-05 이전에는 **둘 다 이름이 `카드 스로우`**였다 — 이름 없는 효과 둘이 스킬 키 이름을
나눠 가진 형태라 `PARSING.md` Step 7의 중복 금지에 걸린다. 번호 없는 이름은 지속 효과(5초 buff)가
갖고 instant가 뒤 번호로 밀렸다. 참조하는 이름이 없어 동작은 그대로다.

**`self_state:` 판정이 성립하는 이유**: `allies_adjacent:2`는 *자신 포함* 최대 3명
(`docs/IMPL-STATUS.md`)이라 `소드 코인`·`실드 코인`이 루주 본인에게도 붙는다.
그래서 `_has_self_state`가 참이 되고 다음 단계가 열린다. 실측 수령자 목록이 그대로 보여준다 —
index 1이면 `[크라운, test_B3, 루주]`, index 3이면 `[스노우 화이트 : 헤비암즈, 루주]`.

정적 딜 기여는 `atk_dmg_pct`(소드 코인, ⑤)와 `atk_caster_based_pct`(더 게임 마스터, ②) 둘뿐이다.
나머지 코인 계열은 전부 **최대 체력·받는 대미지**라 보스 DPS에는 직접 기여하지 않는다.

## 검증 스쿼드
- **표준 (B1 · 쿨 20s, 후열 배치)**: `["크라운", "루주", "test_B3", "스노우 화이트 : 헤비암즈"]`
  - 표준 템플릿(`TARGET`이 index 0)을 **그대로 쓰면 안 된다** — `back_row`가 깨진다.
    크라운을 앞으로 빼 루주를 index 1에 앉힌 변형이다.
- **변형 1 (전열 네거티브)**: `["루주", "크라운", "test_B3", "스노우 화이트 : 헤비암즈"]`
  - `back_row` 미충족 → 코인 체인 3단 + 버스트 조건부 3블록 전멸 확인용.
    실측에서 여섯 효과 **전부 활성 0회**였다.
- **변형 2 (최대 딜러 인접)**: `["크라운", "test_B3", "스노우 화이트 : 헤비암즈", "루주"]`
  - `allies_adjacent:2`가 누구를 잡느냐로 총딜이 갈리는 것 확인용.

- **실전 조합 (하네스)** — 세 조합 **모두 루주를 후열(index 1 또는 3)에 둔다.**
  배치가 킷의 전제라는 것이 편성에 그대로 반영돼 있다:

  | 스쿼드 | 멤버 (루주 위치) | 적 · 비고 |
  |---|---|---|
  | `S36_아인루주` | 미란다 · 타키나 · 아인 · **루주(idx 3)** · 에이다 | 수냉 · 미란다 컨트롤 레이어 |
  | `S36_블랑` | 미란다 · 블랑 · 스노우 화이트 : 헤비암즈 · **루주(idx 3)** · 디젤 : 윈터 스위츠 | 수냉 · **`no_burst_char: 루주`** |
  | `커버_라플라스맥스웰` | 라플라스 : 얼티밋 히어로 · **루주(idx 1)** · 신데렐라 · 트리나 · 맥스웰 : 오디너리 미케닉 | 코드 없음 |

  남는 것은 `소드 코인`·`실드 코인`(풀차지 카운터)과 `카드 스로우`뿐이다.
  **루주는 버스트를 쓸 때와 안 쓸 때가 다른 캐릭터에 가깝다.**

실측 (180s, `--expected`, 표준): 스쿼드 총딜 **1,457,412,862** / 루주 103,768,274 (7.1%).

## 스킬 간 상호작용

- **코인 3단 체인 — `back_row` → 소드 → 실드 → 더블 소드**
  - 경로: `소드 코인`(battle_start + back_row) → `self_state:소드 코인` → `실드 코인`
    (30번째 풀차지) → `self_state:실드 코인` → `더블 소드 코인`(5번째 버스트).
  - `allies_adjacent:2`가 자신을 포함하므로 각 단계가 다음 단계의 `self_state`를 만족시킨다.
  - 위험: **첫 고리가 배치 의존**이라, 스쿼드 편성 실수 하나로 킷의 3/4가 사라진다.
    네거티브 스쿼드로 반드시 확인할 것.
- **코인 상태 → 버스트 블록 게이팅 (상태 3개 → 버스트 4블록)**
  - `더 게임 마스터 2·3·4`가 각각 소드/실드/더블 소드를 조건으로 갖는다.
    코인이 다 열려야 버스트가 4블록 전부 발동한다.
  - 시점: `burst_cast` 동일 프레임. `_condition_ok`가 그 시점 상태를 읽으므로
    **5번째 버스트에서 `더블 소드 코인` 성립과 `더 게임 마스터 4` 발동이 같은 프레임에 일어난다.**
    파싱 배열 순서(스킬2 → 스킬3)가 이를 보장한다 — 실측에서 셋 다 t=55.0이다.
- **`카드 스로우`(8발마다 쿨 −7s) → 본인 사이클 단축 → `burst_cast_count` 누적 가속**
  - 5번째 버스트 도달이 20s 쿨 기준 100초에서 실측 55초로 당겨진다.
- **`실드 코인`(30 풀차지)과 5번째 버스트의 경합**
  - 30번째 풀차지 t=42.733 < 5번째 버스트 t=55.0 → **12초 여유로 순서가 맞는다.**
  - 위험: 사격이 느려지거나(엄폐컨·장전컨) 사이클이 빨라지면 순서가 뒤집혀
    `더블 소드 코인`이 6번째 버스트로 밀린다. `burst_cast_count:5`가 `>= 5` 누적형이라
    영구히 놓치지는 않는다.

## 유저 확인 사항
- 초안 단계 없음. 아래는 파싱·코드·실측에서 확인한 사실.
- Q: `allies_adjacent:2`에 루주 자신이 포함되나?
  A: **포함된다** (자신 포함 최대 N+1명). 실측 수령자에 루주가 들어 있고,
  그래서 `self_state:소드 코인`이 성립한다.
- Q: `back_row`는 어떻게 판정하나?
  A: **스쿼드 인덱스 1 또는 3**. 표준 B1 템플릿(index 0)을 그대로 쓰면 안 된다.
- Q: `full_charge_fire_count:30`은 "30번째 한 번"인가?
  A: **30발마다 반복**(`count % 30 == 0`) — 실측 4회. 다만 `실드 코인`이 영구 버프라
  첫 회만 의미 있다.
- Q: `카드 스로우`가 두 항목이다. 문제인가?
  A: 항목이 둘인 것은 맞다 — `_activate()`는 effect dict의 identity로 식별하므로 스택이 섞이지
  않는다. 다만 **이름까지 같았던 것**은 규칙 위반이라 2026-09-05에 instant를 `카드 스로우 2`로
  밀었다 (`PARSING-CHARS.md` 루주 행).
