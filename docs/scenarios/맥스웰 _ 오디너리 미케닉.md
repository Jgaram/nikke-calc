## 스킬 간 상호작용

- **핵심 순환: `순차적 리미트 해제` → `출력 전환 시퀀스` 증폭**
  - 경로: `hp_caster_based_pct` 1.0 × 30중첩 → **`all_allies`(시전자 포함)** 최대 체력 상승
    → `effective_max_hp(맥스웰)` 상승 → `atk_from_hp_pct` = `effective_max_hp × 1.0%` → 아군 `atk_flat`
  - **실시간 재계산이다** — `get_buffs()` 후처리에서 매번 `effective_max_hp(caster)`를 다시 읽는다.
    실측으로 스택 상승에 맞춰 36,902 → 44,012로 연속 증가 확인.
  - `all_allies`가 시전자를 포함하지 않으면 순환이 끊긴다 (GAMEPLAY §target — 포함 확정).

- **`과전류 2`(게이지) → `메티스 버스트 버스터 3~7` 게이팅** *(동일 timing, 실행 순서 의존)*
  - 같은 `burst_cast` 프레임에 **게이지 +1 → `gauge_eq` 판정 → 차지 시간 결정**.
  - `gauge_eq`는 **래치**다([buff_manager.py:1169](calculator/buff_manager.py#L1169), `_RUNTIME_COND_PREFIXES` 미포함).
    모드가 살아 있는 동안 재판정되지 않으므로 tier가 중간에 꺼지지 않는다 — **의도된 동작**.
  - `self_stack_above:과전류:N`으로 풀었다면 5단계에서 **5개 조건이 전부 참**이 된다.
    `_fixed_charge_time`이 그중 하나를 고르는 규칙(현재는 최신값)에 결과가 통째로 의존하게 되어,
    parsed_skills 배열 순서를 바꾸는 것만으로 차지 시간이 달라지는 취약한 구조가 된다.
    `gauge_eq`는 애초에 **정확히 하나만** 참으로 만들어 이 의존을 없앤다.

- **`과전류`(ATK)는 단계와 무관** — `atk_pct` +30% 고정(Q7). 단계의 효용은 **차지 시간 단축뿐**이고,
  그 단축은 모드 진입~발사 사이 딜 공백을 줄이는 형태로만 기여한다.

- **모드 → `메티스 버스트 버스터 2`(관통)** — `duration_bullets: 1`로 모드와 수명을 맞춘다.
  트리거가 `burst_cast`(bullet-bound 아님)라 부여한 발이 즉시 차감되지 않는다.
  스노우 화이트 `세븐스 드워프 : I 2`와 동일 패턴. 라플라스 : 얼티밋 히어로처럼
  `full_charge_hit`로 부여했다면 1발 일찍 꺼졌을 것.

- **모드 중에도 `full_charge_hit`가 발동** — 메티스 1발이 `순차적 리미트 해제` +1중첩과
  `출력 전환 시퀀스 2`를 추가 발동시킨다. 실측 100회 중 14회가 메티스분.
  (일반 규칙 → GAMEPLAY §무기 메카닉 승격 완료)

- **버프 지속 vs 사이클 주기(12.533초)**
  - `출력 전환 시퀀스` **15초** > 주기 → **끊김 없이 상시 유지**
  - `메티스 버스트 버스터 8` **10초** → 사이클당 약 2.5초 공백
  - `순차적 리미트 해제 2` **5초** → 풀버스트 전반부만

## 구현 이력 (`/char-impl` 완료)

이 캐릭터를 붙이면서 계산기 2곳을 고쳤다. **둘 다 파싱이 아니라 계산기 쪽 한계**였다
(파싱은 처음부터 정확히 하나의 tier만 활성화하고 있었다). 회귀 스냅샷 20/20 유지.

### 1. `charge_time_fixed`가 base보다 **짧게** 고정하지 못했다

[`_fixed_charge_time`](calculator/timeline.py#L613) — 기존에는 `max_val = charge_time_base`로
시작해 최대값을 취했다. 무기 변경 시 `charge_time_base`가 3.0으로 교체되므로
`max(3.0, 0.4) = 3.0`, 즉 **단축이 구조적으로 불가능**했다.

수정: **base를 후보에서 제외**하고, 복수 활성이면 **최신값**(`activated_at`, `uid` 순)을 고른다.
최대값이 아니라 최신값인 근거는 데이터 안에 있었다 — 스노우 화이트 : 헤비암즈의
`어나더 화이트 차지시간고정`(1.2초)이 **`event:state_end`로 한 번 더 재부여**되는데,
최대값 시맨틱이면 그 재부여 항목이 아무 일도 하지 않는다. 모드 종료 시 고정값을 되돌리려는
의도, 즉 원래 최신값 우선을 전제하고 쓰인 데이터다.

`fixed_value` 없이 stat만 붙은 버프(아니스 : 스타 `슈팅 스타2` = "차지 속도 버프 무시")는
후보가 없으므로 base를 그대로 쓴다 — 동작 불변.

### 2. 무기 변경 진입 시 이전 무기의 차지 진행분을 이어받았다

1번을 고치자 드러난 문제. [`_tick_weapon_change`](calculator/timeline.py#L561)는
진입 시 `_charge_phase == "charging"`이면 차지를 이어받았다. 차지 시간만 0.4초로 줄어드니
`_charge_start_t + 0.4`가 **이미 과거**가 되어 진입과 동시에 발사되고,
풀버스트 진입(버스트 사용 +0.15초) 전에 쏴 풀버스트 버프를 통째로 놓쳤다.

결과는 **과전류 5단계가 4단계보다 손해**라는 역설이었다 — 메티스 딜 4,089,964 → 2,694,702 (−34%).

수정: 모드 첫 진입 프레임에 **차지를 새로 시작**한다. 무기가 통째로 바뀌므로 진행분을 물려받을
근거가 없다. **인게임 확인 완료** → GAMEPLAY §무기 메카닉 승격.
기존 무기 변경 캐릭터(스노우 화이트 : 헤비암즈·신데렐라 : 크리스탈 웨이브)는 차지가 **늘어나는**
방향이라 이어받든 리셋하든 결과가 같아 3시드 비교에서 완전 동일.

### 딜 영향 (표준 스쿼드, seed=1)

| | 수정 전 | 수정 후 |
|---|---|---|
| 맥스웰 본인 | 110,601,990 | **124,506,948 (+12.6%)** |
| 스쿼드 비중 | 8.0% | **9.0%** |
| 스쿼드 총딜 | 1,383,536,651 | 1,385,400,811 (+0.13%) |

> 스쿼드 총딜 변화가 작은 것은 맥스웰이 서포터라 본인 딜 비중이 9%뿐이기 때문이다.
> 1번만 고쳤을 때는 본인 딜 +2.7%(5시드 평균)에 그쳤고, 2번까지 고쳐야 +12.6%가 된다 —
> **두 수정은 세트다.** 1번만 적용하면 5단계에서 오히려 딜이 떨어진다.

## 유저 확인 사항

- **Q1. 「메티스 버스트 버스터」 무기 유형** (텍스트 미기재) → **A: SR.**
  차지 시간·풀 차지 대미지·관통 특화·1발 장탄 문형이 스노우 화이트 `세븐스 드워프 : I`와 동일.
- **Q2. 모드 종료 조건** → **A: `duration_bullets: 1`.** `[N초 유지]`·`해제 조건` 없이
  `최대 장탄 수 : 1발`만 있는 문형 (PARSING §7-13). 빼면 영구 모드가 된다.
- **Q3. `burst_cast` 동일 timing 실행 순서** → **A: 과전류 단계가 먼저 오르고 그 단계로 차지 시간이 정해진다.**
  1회차 버스트부터 1단계로 센다. → 배열에서 게이지 충전이 무기 변경보다 앞.
  (일반 규칙 → GAMEPLAY §효과 실행 순서 승격 완료)
- **Q4. 단계별 차지 시간 표현** → **A: 게이지 + `gauge_eq:과전류:N`.**
  최초 답변은 `self_stack_eq` 신규 condition이었으나, Q7에서 ATK가 단계 무관으로 확정되면서
  ATK 버프와 카운터를 분리해야 했고, 카운터를 게이지로 두면 기구현 `gauge_eq`로 충분해졌다.
  **신규 condition 추가 0건.**
- **Q5. 모드의 풀차지가 `full_charge_hit`를 발동하는가** → **A: 발동한다.** 실측 100회 중 14회가 메티스분.
  (일반 규칙 → GAMEPLAY §무기 메카닉 승격 완료)
- **Q6. `버스트 게이지 충전 7.15%`** → **A: `burst_charge_pct` 🚫 보류 stat.** 파싱만, DPS 무영향.
- **Q7. `과전류` 수치** → **A: 5단계여도 총 +30% 고정.** 단계는 차지 시간 결정용 카운터일 뿐.
  → `max_stack: 1` 필수 ([buff_manager.py:2090](calculator/buff_manager.py#L2090)).

- **Q8. 무기 변경 진입 시 이전 무기의 차지 진행분** (`/char-impl` 중 제기) → **A: 이어지지 않는다. 인게임 확인됨.**
  모드 진입 프레임에 차지를 새로 시작한다. → 계산기 수정 (§구현 이력 2).
  (일반 규칙 → GAMEPLAY §무기 메카닉 승격 완료)

### GAMEPLAY 승격 완료 항목
- §효과 실행 순서 — 카운터 부여와 그 카운터를 읽는 무기 변경이 같은 timing이면 부여가 먼저 반영된다 + 배열 순서 제약
- §무기 메카닉 — 무기 변경 모드의 차지형 무기도 `full_charge_hit`를 발동한다
- §무기 메카닉 — 무기 변경 모드 **진입** 시 이전 무기의 차지 진행분은 이어지지 않는다 (같은 무기의 `charge_time_fixed` stat만 바뀌는 경우와 구분 — 그쪽은 진행분 유지)
