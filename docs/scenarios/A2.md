## 스킬 간 상호작용

- **B 모드의 수명은 지속시간이 아니라 자해 누적이 정한다**
  - 경로: `B 모드 3`(1초 간격 ×0.9601) → `sync_hp` → `bm._notify_hp_below`가 40% 하향 통과를 감지해 `hp_below:40` →
    `B 모드 해제`·`B 모드 해제 2`가 담체·차지 속도를 걷는다 → `B 모드 3`은 영구 주기 instant의 런타임 재판정(`self_state:B 모드`)으로 멈춘다
  - 실측: 3.2 → 26.217 = **23.017초**(23틱 + 프레임). 해제 뒤 체력 39.2%로 고정
  - **`hp_below:N`은 IMPL-STATUS에 「⚠️ `_timing_match`에 분기 있음. 체력 변화 시 notify 호출처 없음」으로 적혀 있지만 낡은 서술이다** —
    `hp_below_count:` 행이 이미 같은 함수(`bm._notify_hp_below`)를 적고 있고, 이 실측이 `hp_below:40` 자체의 첫 발동이다.
    A2가 첫 보유자라 그동안 드러날 일이 없었다 → 단계 4에서 ✅로 고쳤다
- **회복 → 재진입** — 회복이 없으면 2회차부터 진입 즉시 해제된다(`burst_cast` 경로). 마르차나를 넣으면 해제 자체가 없다
- **`출력 상승`(15초)은 B 모드와 독립이다** — 같은 시전에 걸리지만 표준 2회차 이후에는 `출력 상승`만 산다.
  A2 기여 1위(−18.79%)가 버스트 모드가 아니라 이쪽인 이유다
- **배열 순서** — 담체(`B 모드`) → `B 모드 2` → 자해 → 해제 2개. 원문은 자해(효과 1)가 먼저지만 자해의 활성 조건이 담체를
  읽으므로 담체를 앞에 둔다(`PARSING-CHARS.md` A2 행). 해제가 모드 항목 **뒤**라 2회차 이후 「켜고 곧바로 걷는다」가 성립한다

## 유저 확인 사항

- **Q1: `post_fire_delay`·`post_reload_delay` 실측.**
  **A(유저 확인 2026-09-24): CDN 유도값 그대로** — `post_fire_delay` 1.06 · `post_reload_delay` 0.
  `weapon_delays.json` `_exceptions`에 등록하지 않는다
- (자체 판단) **B 모드는 지속시간이 없다 — 해제 조건(체력 40% 이하)으로만 끝난다.** 원문 효과 셋 어디에도 유지 블록이 없고
  기능 설명이 해제 조건을 따로 적었다
- (자체 판단) **해제는 두 경로다 — 40%를 넘어 내려가는 순간과, 이미 40% 이하에서 진입하는 순간.** 원문 「체력이 40% 이하라면
  해제」는 상태 조건이라 진입 순간에도 참이다. 대안(1초 틱에서만 판정)이었다면 2회차 이후 매 진입마다 1초간 공격력·차지 속도가
  살고 자해가 한 번 더 들어간다 — 7회 × 1초라 본인 **≈+1% 이하**(추정 — 틱 판정 해제는 지금 문법으로 바로 적을 수 없어 재지 못했다)
- (자체 판단) **체력 감소는 곱연산**(`GAMEPLAY.md` §값 산정 — 그레이브 · 홍련 · 길로틴과 같은 규약). 정액(최대 체력의 3.99%)이었다면
  16틱에 40% 아래라 첫 B 모드가 ≈16초로 줄어든다
- (자체 판단) **표준 스쿼드의 「B 모드 전투당 1회」는 버그가 아니라 원문 그대로의 결과다** — 기본 경로에는 피격이 없어 체력이
  회복 없이는 안 돌아온다. 인게임에서 A2를 회복 아군과 쓰는 이유가 이것이고, 그래서 변형 1을 검증 스쿼드에 넣었다
