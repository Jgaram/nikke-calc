## 스킬 간 상호작용

- **`폐품` → `사제 탄창` → 두 갈래로 딜에 도달**
  - 경로 A: #5 `atk_pct` = 7.5 × N (N = 사제 탄창, 최대 30.0). `duration: -1` + `scaling_ref`라
    `_capture_scaling_stack`이 값을 고정하지 않고 게이지를 **실시간 추종**한다.
  - 경로 B: #8의 `max_ammo` = 1 × N. 「모든 탄환 발사 시 제거」라 **N이 곧 모드 지속 시간**이기도 하다.
  - 위험: 두 경로가 같은 카운터에 매달려 있어 폐품 수급이 막히면 **동시에** 최소값에 눌린다.

- **동일 timing 내 실행 순서 — 배열 순서가 곧 결과** (이 캐릭터의 최대 사각지대)
  - `#0 → #4 → #5 → #6 → #7`. 하나라도 뒤집히면:
    - **#7(폐품 소모)이 #6보다 앞** → #6의 `gauge_above:폐품:10`이 깨져 **사제 탄창이 영원히 0개**.
      #5도 0, #8 장탄도 0발이 되어 캐릭터가 통째로 죽는다. 원문 서술 순서는 제거가 먼저지만
      엔진에서는 소비를 마지막에 둔다 — 네온 `초화력`·아크레인저 블랙 `변신`과 같은 규약.
    - **#0(폐품 충전)이 #6보다 뒤** → t=0에 사제 탄창이 안 만들어진다. 그래서 스킬2 항목들이
      배열에서 스킬1보다 **앞**에 온다(`source` 순서가 아니라 실행 순서로 배열한다).
  - #5는 순서와 무관하다 — 조건 없이 등록되고 게이지를 실시간으로 읽기 때문이다.

- **#5에 게이지 조건을 붙이면 안 된다**
  - `gauge_above`·`gauge_below`는 `_RUNTIME_COND_PREFIXES` 소속이라 매 순간 재평가된다.
    `[지속]` 버프에 `gauge_above:폐품:10`을 달면 #7이 폐품을 비우는 순간 값이 꺼지고,
    `gauge_below:사제 탄창:4`를 달면 **탄창이 최대일 때 정확히 꺼진다**(가장 커야 할 때 0).
  - 아크레인저 블랙 `변신`에서 이미 밟은 함정이다(GAMEPLAY §영구 버프에 런타임 조건 금지).

- **#8의 최대 장탄은 장탄 버프를 받지 않는다**
  - 원문에 `(사용 무기 변경 시 최대 장탄 수 효과 갱신)` 괄호구가 **없다** → `max_ammo_buff_applies`
    미설정 → 하네스 기본 스펙의 오버로드 최대 장탄 129.64%가 이 모드에 **얹히지 않는다**.
    라플라스 : 얼티밋 히어로(얹힌다)와 반대 사례.
  - 반면 `1발 X 사제 탄창 개수`는 버프가 아니라 **표기값 자체**라 괄호구와 무관하게 곱해져야 한다.
    그래서 장탄 버프 층이 아닌 별도 필드(`max_ammo_scaling_ref`)로 적었다.
  - 읽는 시점은 다른 장탄과 같아야 한다 — **모드 진입과 재장전 완료뿐**. 매 tick 재면 장탄과
    종료 조건이 어긋나 «탄이 마르고도 끝나지 않는 모드»가 생긴다(GAMEPLAY §무기 메카닉).

- **#8은 `duration`과 `duration_bullets`를 함께 쓰는 첫 모드**
  - 원문 `제거 시점 : 유지 시간 종료 또는 모든 탄환 발사 시` 그대로다. 엔진은 두 경로가 다 있다 —
    발수는 `_tick_weapon_change`가, 지속시간은 버프 만료가 끝낸다.
  - `duration_bullets == max_ammo`가 "모든 탄환 발사 시" 형태를 뜻하므로 실효 장탄을 따라간다.
  - 모드 안 자동 재장전은 `duration`·`duration_bullets`가 있으면 애초에 돌지 않는다(정상).

- **버스트 사이클에서 모드는 거의 즉시 끝난다**
  - 장탄 1발 + 차지 0.4초 → 진입 후 0.4초 만에 종료하고 **풀로드 SMG**로 돌아온다.
    `atk_pct` +430.05는 그대로 10초 남으므로, **이 버스트는 사실상 모드가 아니라 자버프다.**
  - 모드 사격은 스킬 대미지가 아니라 **일반 공격**이다(`skill_damage` 미표기 — 기본값).
    기본 무기가 SMG라 「투사체 폭발 대미지 ▲」는 RL 모드에서도 **못 받는다**(GAMEPLAY §무기 메카닉,
    나유타와 같은 케이스). 현 스쿼드에 그 버프 제공자가 없어 지금은 무영향.

## 유저 확인 사항

- **Q0. 「인 투 더 헤븐」의 변경 무기 유형은?** (2026-09-09 유저 확인)
  **A: RL(로켓 런처).** 원문에 무기군 표기가 없어 `PARSING.md` 10-7로 즉시 질문했다.
  RL은 무기군 기본이 차지형이라 `charge` 필드는 붙이지 않는다. 펠릿도 기본 1.

- **Q1. 폐품 추가 수급원 3종이 계산기에서 어떻게 되나?** (자체 판단 — 선례 있음)
  **A (자체 판단, 선례: 아크레인저 블랙 Q1 · 사쿠라 : 블룸 인 서머 Q1)**: `IMPL-STATUS.md` 기준
  - #1 `event:projectile_destroy` — notify 호출처 없음 → **영구 무발동**
  - #3 `enemy_death` — notify 호출처 없음 + 고정 시간 보스 sim → **영구 무발동**
  - #2 `event:part_destroy` — 기본 무발동이나 `enemy["part_break_interval"]`로 주기 발생
  → 파싱은 세 트리거를 모두 정상 등록하고, **파괴 주기 OFF/ON 두 모드를 짝으로 비교**한다.
  무발동 2종은 아래 체크리스트 네거티브 항목.

- **Q2. #4 「폐품 획득 시」가 전투 시작 충전·상한 초과 충전에도 발동하나?** (2026-09-09 유저 확인)
  **A: 발동한다. 사제 탄창이 최대(4개)여서 폐품이 cap에 정체하는 구간에서도 획득이 일어나면 발동한다.**
  → 게이지가 실제로 늘었는지를 보지 않으므로 **충전 트리거 4종의 union**이 정확한 표현이다.
  파싱은 그대로 두면 되고, 표준 스쿼드에서는 t=0 1회뿐이지만 **파괴 주기 ON에서는 사제 탄창이
  4개에 닿은 뒤에도 `element_bonus_pct` +16.36이 파괴마다 계속 갱신**된다.

- **Q3. 사제 탄창이 이미 4개일 때 폐품 10은 어떻게 되나?** (자체 판단)
  **A (자체 판단)**: 원문 「사제 탄창 제작 수가 4개 미만이라면」이 **제작 자체를 막는** 문장이므로
  #6·#7이 둘 다 조건 불충족으로 건너뛰어 **폐품이 10에서 정체**하고 이후 획득분은 cap에 버려진다.
  → #7에도 같은 조건을 그대로 달아 두었다(조건이 #6과 어긋나면 폐품만 사라진다).

- **Q4. 버스트 모드 장탄이 0발이 되는 경우가 있나?** (자체 판단 — 발생하면 버그)
  **A (자체 판단)**: t=0에 사제 탄창 1개가 확정되므로 정상 동작에서는 없다.
  배열 순서나 #5 조건을 잘못 잡으면 발생하므로 **네거티브 체크 항목**으로 둔다.

- **Q5. 이 캐릭터에서 승격한 일반 규칙?** **없음.** #6/#7 순서 규약은 네온·아크레인저 블랙이
  이미 GAMEPLAY §효과 실행 순서에 올려 둔 규칙의 적용 사례이고, #5의 런타임 조건 금지도 마찬가지다.

## 모드 종료 후 장탄 복구 — E.H. 등록 중 발견해 고친 전역 버그 (2026-09-09)

**증상(고치기 전)**: #8이 전탄 발사로 끝난 뒤 SMG가 **풀로드로 돌아오지 않고**, 곧바로 재장전이 삽입됐다.

```
t=3.617  모드 1발 발사 (풀차지, dmg 2,815,781)
t=3.633  모드 종료 → 복귀 ammo = 1     ← 모드의 잔탄이 기본 무기로 새어 나온다
t=3.683  재장전 시작
t=3.950  재장전 완료 → ammo 276
```

`GAMEPLAY.md` §무기 메카닉은 「모드가 끝나면 원래 무기의 장탄은 **전부 복구**되며 **복귀 직후
재장전이 삽입되지 않는다**」(유저 확인 2026-08-08, 근거 캐릭터가 맥스웰 `피어스 샷`)라고 못박고 있다.

**원인**: `timeline._tick_weapon_change()`의 `duration_bullets` 소진 종료 경로가
`self.ammo = orig_ammo`로 되돌리는데, `orig_ammo`는 같은 함수 진입부에서
`self.ammo if not was_ready else None`로 잡힌다. **발사가 일어나는 tick에서는 `was_ready`가 거짓**이라
그때의 `self.ammo`(= 모드 장탄)가 잡히고, 그 값이 기본 무기의 잔탄으로 기록된다.
복구해야 할 값은 `self._full_ammo(bm, t)`(버프 반영 실효 최대 장탄)다.

**E.H. 고유 문제가 아니다** — 같은 경로를 타는 기존 캐릭터가 전부 같은 상태다:

| 캐릭터 | 모드 | 종료 후 복귀 잔탄 | 실효 최대 | 재장전 삽입 |
|---|---|---|---|---|
| E.H. | RL 1발 | 1 | 276 | 있음 |
| 츠바이 | SR 1발 | 1 | 21 | 있음 |
| 스노우 화이트 | SR 1발 | 1 | 138 | 있음 |
| 맥스웰 | SR 1발 | 14 → 7 → 10 (진입 전 잔탄) | 14 | 없음(우연히 근접) |

맥스웰조차 문서가 적은 「6/6 풀로드」가 아니라 **진입 전 잔탄**으로 돌아왔다.

**유저 확인 (2026-09-09)**: 「다른 문구 없으면 무기 변경 종료 시 (발사 횟수·지속시간 무관) **만탄**으로
복귀한다. 탄환 제거 N%가 붙은 라플라스 : 얼티밋 히어로·드레이크 : 그레이트 빌런만 재장전이 필요하다.」
→ `GAMEPLAY.md` §무기 메카닉에 승격했다.

**수정**: 종료 시 `orig_ammo`가 아니라 **실효 최대 장탄**을 채운다.
- 발수 소진 경로(`_tick_weapon_change`)는 `_buffed_ammo(bm, t)`로 채운다 — `_full_ammo`를 부르면
  `end_weapon_change`가 아직 아래에 있어 **모드 장탄**(1발)이 나온다.
- 지속시간 만료·토글 해제 경로(`tick`)는 종전에 `_wc_ammo_borrowed`(= 연사 모드)일 때만 채웠다 →
  **차지 모드가 이 경로에서 빠져 있었다.** 조건을 걷었다.
- 두 경로가 다 채우면 **두 번 채워져** 발수 소진 모드의 `event:state_end` 장탄 조작이 다음 tick에
  덮인다 — 실제로 라플라스가 재장전 9회 → **0회**가 되며 +6.3%로 튀었다. `_wc_ammo_restored`
  플래그로 정확히 한 번만 채운다.
- 모드 안에서 시작된 재장전(`_reload_in_weapon_change`)은 복구와 함께 취소한다.
