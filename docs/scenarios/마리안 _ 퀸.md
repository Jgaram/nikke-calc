## 스킬 간 상호작용

- **#2 다크 매터 창 → #3 약점 개방 → #6 대상 필터**: #6은 `enemies_with_buff:약점 개방`이라 약점 개방이 먼저 서야 한다. t=0 첫 창 명중부터 영구(1중첩 갱신)라 단일 보스에서는 #6이 열리는 시점(첫 버스트 3.2s)에 늘 서 있다.
  - 위험: 쫄몹 모드에서는 창이 닿지 않은 쫄몹이 #6 대상에서 빠진다 — #4(버스트 사용 시 적 전체)가 그 공백을 메우는 경로다.
- **#5 파고드는 소망(burst_cast) → #8/#9 분기(full_burst_start)**: 같은 사이클에서 burst_cast가 full_burst_start보다 약 0.38초 먼저라 **본인 버스트 사이클 = #9(코어 대미지 ▲), 동료 버스트 사이클 = #8(순차 공격 대미지 ▲)**이다. 배타라 동시에 켜지지 않는다(실측 #8 7회 + #9 8회 = 풀버스트 15회).
  - #8은 #2(순차 공격)에만, #9는 #6(확정 코어)·기본 공격 코어 히트에만 실린다 → 동료 사이클은 창 딜, 본인 사이클은 코어 명중 딜이 주력이다.
- **#7 주기 단축 → #2 빈도**: 4s → 2s(10초 창). `effect_interval`은 `target_effect` 이름 하나와만 맞춘다 — 의지를 벼린 창끝에서 `every:`를 도는 항목이 #2뿐이라 한 항목으로 충분하다(엠마 : 택티컬 업 `포메이션 LT 5~7`은 대상 항목이 셋이라 셋으로 쪼갰다).
- **#11 예열 2배 + #10 탄환 100%**: #6이 「발사 2회마다」라 발사 속도가 곧 #6 횟수다. 예열 가속이 #6 횟수를 직접 늘린다(코어 보스 사이클당 287~288회 ≈ 10초 × 약 57회/s ÷ 2).
- **동일 timing(burst_cast) 실행 순서**: #4 → #5 → #7 → #10 → #11 → #12 → #13 → #14(원문 블록 = 배열 순서). #14 버스트 대미지는 #4 약점 개방·#12 공격력·#13 공격 대미지를 받는다 — 원문도 버프 블록이 대미지 블록보다 앞이다(GAMEPLAY §효과 실행 순서 「원문 블록 순서 = 실행 순서」). #4는 단일 보스에서 이미 서 있는 상태의 갱신이라 순서가 딜을 바꾸지 않는다.
- **순환 강화 없음**: #6은 #3·#4를 다시 걸지 않는다(창 명중만 #3을 건다).

## 유저 확인 사항

- (자체 판단) **임전 상태 = 마커 buff `engaged_state`** — 부모 세션 공통 규약(홍련 : 신살 · 라푼젤 : 생츄어리 동시 등록). `persona_state` 선례(퀸(마코토)·유키코)와 같은 꼴, 같은 이름·트리거·지속. 두 상태 모두 원문에 `[해제 불가]`가 없어 `beneficial`
- (자체 판단) **`반복 주기 : 4초`는 하위 기능(#2)에만** — 상태(#1)는 유지 시간 표기가 없어 영구다. `battle_start` + `every:Ns`는 선례 엠마 : 택티컬 업 `환경 조성` · 일레그 : 붐 앤 쇼크 `빙의`
- (자체 판단) **#2 대상 「무작위 적들에게」 → `enemies_random`** — 선례 사쿠라 : 블룸 인 서머 `화양연화` · 율리아 `클라이맥스` 등 4명(parsecheck ✓)
- (자체 판단) **#3 「다크 매터 창 명중 시 대상에게」 → `hit_count:다크 매터 창:1` · `target`** — PARSING §4-1 `[스킬명] 명중 시`, 선례 이브 `임팩트 타입 엑소스파인 2` · 리틀 머메이드 `거품`
- (자체 판단) **#3·#4 같은 이름 `약점 개방`** — 같은 상태의 두 부여 경로(PARSING Step 7 §예외), `enemies_with_buff:약점 개방`이 읽는다. 값 {1}={2} 전 레벨 동일(doclint M ✓)
- (자체 판단) **#6 트리거는 clause 머리가 아니라 본문 「효과 1 : 일반 공격 2회 공격 시」** → `on_attack_count:2` + `self_state:임전 : 파고드는 소망`. 선례 아스카 : WILLE `섬멸 태세 추가 효과`(상태 창 안 발사 카운터). parsecheck `선례와 다름`(머리 문구 「버스트 스킬 사용 시」 ↔ `on_attack_count`)은 이 구조 때문이다
- (자체 판단) **#6 대상 「약점 개방 상태 적 전체에게」 → `enemies_with_buff:약점 개방`** — PARSING §5 `[버프명] 상태인 적 전체에게` 행, 문형 선례 아스카 : WILLE `섬멸`(「안티 AT 필드 상태인 대상에게」). parsecheck는 문구가 달라 `선례 없음`으로 띄운다
- (자체 판단) **#6 「코어 명중 대미지」 → `core_damage` + `core_hit`** — PARSING §6 `core_damage` 조항(「condition에 `core_hit`를 함께 적는다」) 그대로. **대안이면 딜이 크게 달라져 단계 3 잔여 질문 1번**이다
- (자체 판단) **#7 `effect_interval` −2.0 → `다크 매터 창`** — 선례 엠마 : 택티컬 업 `포메이션 LT 5`(「[X 반복 주기 N초 ▼]」)
- (자체 판단) **#8·#9 분기** — 선례 아스카 : WILLE `긴급 수복`(「풀 버스트 타임 시작 시 자신이 X 상태라면」 → `self_state:X`)
