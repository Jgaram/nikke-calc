# NIKKE 게임플레이 메커니즘 — 계산기 맥락 참고용

시뮬 결과가 "맞다"는 게 어떤 모습인지 판단 기준. 개별 스킬 구현 명세는 IMPL-STATUS.md.

---

## 전투 기본 설정

- **전투 시간**: 180초. `DEFAULT_CONFIG["duration"]`.
- **적**: 단일 보스 1명. 복수 적 환경은 시뮬 범위 밖.
- **스쿼드**: 기본 5인.

---

## 컨트롤

유저 조작으로 같은 스쿼드·같은 육성에서도 딜이 달라지는 요소가 있다.
**자동(꺼짐)이 기본**이고, 예외는 캐릭터별 기본 레이어에 등록된 니케뿐이다
(`data/char_defaults.json` — 앨리스·아인·밀크 : 블루밍 바니).

실제 조작은 **좌클릭 누르기**와 **shift 엄폐** 둘뿐이고, 둘 다 시작·끝을 가진 구간이다.
보고 있지 않은 나머지 4명은 언제나 자동으로 싸운다 — **자동이 디폴트다.**

- **톡톡이** — 차지형(SR/RL)에서 차지를 끝까지 하지 않고 짧게 눌렀다 떼기를 반복.
  발당 대미지는 낮아지고 발사 횟수가 늘어난다.
- **장전컨** — 엄폐로 재장전을 유리한 버프 구간에 밀어 넣는다. 엄폐 중에는 재장전을 하므로,
  재장전은 직접 거는 조작이 아니라 **엄폐로 유도되는 결과**다.
- **버스트 엄폐컨** — 본인 버스트 사이클의 풀버스트 동안 엄폐해 **한 발도 쏘지 않는다.**
  발수로 소모되는 버프를 일반 공격에 쓰지 않고 스킬 대미지 구간까지 아끼는 조작이다.
  장전컨과 원시타입은 같지만 목적이 반대다 — 재장전은 여기서 부산물이다.
- **홀드** — 풀차지 후에도 떼지 않고 들고 있다가 원하는 시점에 발사. 전투 내내 하는 운용이
  아니라 특이케이스라, 기본 전략이 아니라 시퀀스로만 지정한다.

메커니즘 수치·계산기 모델·설정 스키마·적용 대상은 **`context/CONTROL.md`가 정본**이다.

## 스쿼드 구성

### 버스트 쿨타임 현황

| 단계 | 일반적 쿨타임 | 비고 |
|------|-------------|------|
| B1 | 20초 | 간혹 40초·60초도 있음 |
| B2 | 20초 | 간혹 40초·60초도 있음 |
| B3 | 최소 40초 | 현 니케 풀에 20초짜리 없음 |

### 유효한 스쿼드의 조건

버스트 사이클 유지 = **각 단계(B1·B2·B3)에 한 사이클 안에 쿨이 도는 캐릭터 필요**.

- B3 쿨 최소 40초 → 항상 2명 필요 (번갈아 사용).
- B1·B2 20초 → 각 1명으로 충분.
- B1·B2 40초 → 2명 필요. B1 20초 1명 + B1 40초 1명 조합도 가능.

전형적 5인 구성: **B1×1 + B2×1 + B3×2 + 버스트 미사용×1**

### 버스트 쿨타임 감소

대부분 실전 스쿼드는 버스트 쿨타임 감소 캐릭터(주로 B1·B2) 포함.

- 실전 쿨 감소량: 아군 전체 기준 **약 6~8초**
- 사이클 주기: 쿨 감소 적용 시 약 **12~14초** (대표값 7.48초)
- 180초 기준: 풀버스트 14회 + 종료 직전 15번째 시작

**계산기 구현**: 두 개의 stat으로 나뉜다.

| stat | 성격 | 처리 |
|------|------|------|
| `burst_cooldown` | 지속형 buff. 거는 동안 쿨이 줄어든 상태 유지 | `BurstManager.tick()`의 `full_burst_start` 분기가 `burst_ready_at`을 당김 |
| `burst_cooldown_reduce` | 순간 차감. 발동 시 남은 쿨에서 한 번 깎음 | `_dispatch_instant()` |

쿨 감소량은 **왜 그 값인가보다 언제 몇 번 발동하는가**가 사이클을 좌우한다.
같은 7.48초라도 매 사이클 발동하면 주기가 고정되고, 3회만 발동하면 초반에만 짧다.

#### 감소 수치 (스킬 레벨 10 기준)

| 캐릭터 | 수치 | 대상 | 발동 |
|--------|------|------|------|
| 아니스 : 스타 | 7.48 | 전체 | 전투 시작 / 풀버스트 종료 (1버 아군 없을 때) |
| 라피 : 레드 후드 | 7.48 | 전체 | 풀버스트 시작 (전투 보조 상태) |
| 리틀 머메이드 | 7.48 | 전체 | 풀버스트 종료 |
| 솔린 : 프로스트 티켓 | 7.48 | 전체 | 풀버스트 시작 — **지속형**(`burst_cooldown`) |
| 목단 | 7.48 | 전체 | 풀버스트 시작 (열혈 상태) |
| D : 킬러 와이프 | 7.0 | 전체 | 풀차지 8회 |
| 루주 | 7.0 | 전체 | 풀차지 8회 |
| 아르카나 | 6.0 | 전체 | 풀버스트 종료 (운명의 수레바퀴 카드) |
| 리타 | 2.34 → 2.7 → 3.17 | 전체 | 풀버스트 시작 **1·2·3회차만** |
| 볼륨 | 2.34 → 2.7 → 3.17 | 전체 | 풀버스트 시작 **1·2·3회차만** |
| 헬름 : 아쿠아마린 | 1.82 → 2.2 → 2.6 | 전체 | 풀버스트 시작 **1·2·3회차만** |
| 라피 : 레드 후드 (스3) | 20.0 | 자신 | 버스트 시전 |
| 목단 (스1) | 20.0 | 자신 | 적 등장 — 지속형 |
| 레드 후드 | 40.0 | 자신 | 스쿼드 1버/2버 시전 시 각 1회 |
| 프리카 | **−21.0 (감소가 아니라 증가)** | 자신 | 떼창 |

> 프리카의 음수는 **파싱 오류가 아니라 의도된 값**이다. 자신의 버스트 쿨타임을 21초
> *늘린다*. 부호를 "고치지" 말 것.

`target: self`인 항목(라피 스3, 목단 스1, 레드 후드, 프리카)은 **아군 전체 사이클을 바꾸지 않는다.**
본인의 재사용 간격만 조절한다. 사이클 주기를 논할 때 이들을 전체 감소와 섞지 않는다.

#### 사이클 간격 패턴 (시드 42 실측)

| 구성 | 간격열 | 성격 |
|------|--------|------|
| 7.48 계열 보유 | `12.55` | 균일 — **표준** |
| D : 킬러 와이프 / 루주 (7.0) | `13.0` | 균일 |
| 볼륨 · 리타 | `17.65 → 14.95 → 12.25` 이후 `12.25` | 감쇠 후 정착 |
| 헬름 : 아쿠아마린 | `18.2 → 16.0 → 13.4` 이후 `13.4` | 감쇠 후 정착 |
| 아르카나 + 이사벨 | `7.25 ↔ 12.55` | 무한 교대 |
| 소다 : 트윙클링 바니 | `20.0` | 균일 — 버쿨감 없는 덱 |

**판정은 "12.5초에 가까운가"가 아니라 "그 구성의 프로필에 맞는 패턴인가"로 한다.**
아래 예외들은 전부 정상 동작이다.

#### 예외 케이스

**볼륨 · 리타 · 헬름 : 아쿠아마린 — 감쇠 후 정착**
`full_burst_start_count:1/2/3` 트리거라 **처음 세 사이클만** 쿨을 깎는다.
그래서 첫 간격이 가장 길고 점점 짧아지다가, 4번째부터 감소가 끊겨 고정값에 정착한다.
불규칙해 보이지만 회귀가 아니다. 볼륨과 리타는 수치가 같아 간격열도 소수점까지 일치한다.

**아르카나 + 이사벨 — 7.25초 교대**
아르카나·이사벨이 함께 버스트를 쓴 사이클 뒤에는 버스트가 약 5초 만에 끝나고
버쿨감이 한 번 더 적용된다. 그 결과 짧은 사이클과 표준 사이클이 무한 교대한다.
`7.25 ↔ 12.55`가 계속 반복되면 정상이다. (등록 스쿼드: `스쿼드5`)

**소다 : 트윙클링 바니 — 버쿨감을 아예 넣지 않는 덱**
소다는 `fullburst_duration`(풀버스트 지속시간)을 늘린다 — `burst_enter:3` 발동,
골든 칩 10·20스택 조건. **풀버스트 구간 자체가 길어지므로 쿨을 줄일 이유가 없다.**
그래서 이 덱은 버쿨감 캐릭터를 넣지 않고, 사이클도 20초로 길다.
사이클이 길다고 스쿼드가 깨진 게 아니다. 아주 특수한 경우다. (등록 스쿼드: `레이드_소다`)

**레드 후드 — `burst_stage: "A"`**
1·2·3단계 어디로든 쓸 수 있어 `burst_order`의 **세 단계 목록에 모두** 등록된다.
따라서 배치 위치가 사이클을 좌우한다 → §스쿼드 구성 §버스트 사용 순서와 배치.

### 버스트 사용 순서와 배치

**스쿼드 멤버 순서 = 버스트 사용 우선순위다.** 유저가 화면 왼쪽부터 누르는 것과 같다.
`BurstController`는 단계별 후보를 **스쿼드 입력 순서**로 세우고(`_rebuild_burst_order()`),
쿨이 도는 사람이 없으면 다음 순위로 넘어간다.

같은 단계에 여러 명이면 **앞사람이 계속 선점한다.** 뒤에 놓인 캐릭터는
앞사람 쿨이 안 돌 때만 쓰게 되고, 앞사람 쿨이 짧으면 **한 번도 버스트를 못 쓴다.**

> 관찰 대상 캐릭터는 반드시 **자기 단계 안에서 맨 앞**에 둔다.
> 뒤로 밀린 채 스냅샷을 찍으면 그 캐릭터의 버스트 스킬이 아예 검증되지 않는다.

예: `[미란다(B1), 에이드(B2), 헬름:아쿠아마린(B2), 에이다(B3), 스노우 화이트(B3)]`
→ 에이드(쿨 20초)가 B2를 독점해 헬름 : 아쿠아마린은 버스트를 한 번도 못 쓴다.
헬름 : 아쿠아마린을 관찰하려면 에이드보다 앞에 놓아야 한다.

#### `burst_stage: "A"` 캐릭터 (레드 후드)

레드 후드는 1·2·3단계 목록에 **모두** 등록된다. 그래서 배치가 특히 민감하다.

- **맨 앞에 두면** 첫 사이클에서 1·2·3단계를 혼자 다 쓴다. 이후 사이클도 흔들린다.
- 스쿼드 dict에 `burst_stage`를 주면 단계를 고정할 수 있지만, **라피 : 레드 후드와
  같이 쓸 때는 고정하면 안 된다.** 라피의 `no_burst1_ally` 조건은
  `burst_stages[n] == "1"`로 판정하는데, 레드 후드를 `"1"`로 고정하면 이 조건이 거짓이 되어
  **라피의 1버 전환이 막힌다.** 레드 후드는 `"A"`로 두고 배치 순서로만 조정한다.

라피 : 레드 후드는 팀에 고정 1버가 없으면 스킬1로 자신이 1버가 된다
(`burst_stage_override:1`). 레드 후드가 `"A"`라 1버로 세지 않으므로, 둘만 있는 팀에서는
라피가 1버를 맡는다. 이때 **라피를 레드 후드보다 앞에** 두는 편이 사이클이 안정적이다.

### 더미 캐릭터 "test_B3"

`parsed_nikke.json`에 **스킬 없는 3버스트 AR 캐릭터** `"test_B3"` 등록 (쿨 40초). 동일 패턴 `"test_B1"`, `"test_B2"`도 등록되어 있음.
스킬 없어 버프·딜 영향 없음. 버스트 사이클 완성 용도.

> **주의**: `"test_B3"` 중복 사용 시 `burst_cooldown` 소급 보정이 중복 계산되어 쿨타임 잘못 단축됨. B3 슬롯 2개 필요 시 한 자리에 `"스노우 화이트 : 헤비암즈"` 사용.

### 표준 테스트 스쿼드

**B1 기준으로는 `리틀 머메이드` (쿨 20초) 사용.**
`아니스 : 스타`는 B1이지만, 팀에 다른 B1이 있으면 B1 재진입이 발동해 사이클이 복잡해지므로 B1 슬롯 대용으로 쓰지 않음.

```python
# 대상이 B3, 쿨 40초
squad = [make_char(n) for n in ["리틀 머메이드", "크라운", TARGET, "test_B3"]]

# 대상이 B1, 쿨 20초
squad = [make_char(n) for n in [TARGET, "크라운", "test_B3", "스노우 화이트 : 헤비암즈"]]

# 대상이 B1, 쿨 40초 (보조 B1 필요 → 5슬롯 모두 사용)
squad = [make_char(n) for n in [TARGET, "리틀 머메이드", "크라운", "test_B3", "스노우 화이트 : 헤비암즈"]]

# 대상이 B2, 쿨 20초
squad = [make_char(n) for n in ["리틀 머메이드", TARGET, "test_B3", "스노우 화이트 : 헤비암즈"]]

# 대상이 B2, 쿨 40초 (보조 B2 필요 → 5슬롯 모두 사용)
squad = [make_char(n) for n in ["리틀 머메이드", TARGET, "크라운", "test_B3", "스노우 화이트 : 헤비암즈"]]
```

### 버스트를 쓰지 않는 캐릭터 지정

```python
result = simulate(squad, config={"no_burst_char": "캐릭터명"})
```

## 풀버스트 사이클

### 기본 구조

```
버스트 게이지 충전 → [B1 발동] → [B2 발동] → [B3 발동] → 풀버스트 상태 (~10초) → 종료 → 충전 재시작
```

- 버스트 게이지는 스쿼드 전체 공격으로 쌓임.
- B1→B2→B3 순서 연속 발동 필요.

#### 사이클 주기의 구성

계산기는 게이지 충전을 실제 누적이 아니라 **고정 시간**으로 모델링한다
(`burst_regen_time = 2.0초`). 첫 버스트만 이를 무시하고 `first_burst_time`에 발동한다.

표준 스쿼드(7.48 버쿨감 보유)의 실측 타임라인 — 사이클 12.55초의 내역:

```
13.250  full_burst 종료
15.533  stage:1 사용      (+2.283 = 게이지 충전 2.0 + 쿨 여유)
15.633  stage:2 사용      (+0.1  burst_switch_delay)
15.733  stage:3 사용      (+0.1  burst_switch_delay)
15.783  full_burst 시작   (+0.05)
25.783  full_burst 종료   (+10.0 풀버스트 지속)
28.317  다음 full_burst 시작 → 사이클 간격 12.55
```

즉 **10초(풀버스트) + 2초(게이지 충전) + 0.3초(단계 전환·진입) + 쿨 여유**.
버쿨감이 부족하면 "쿨 여유"가 늘어나 주기가 길어지고, 충분하면 게이지 충전이
병목이 되어 더는 짧아지지 않는다. 12.55초가 사실상 하한선인 이유다.

풀버스트 지속 10초는 `fullburst_duration` stat으로 연장될 수 있다
(예: 소다 : 트윙클링 바니). 연장되면 사이클 주기도 그만큼 길어진다.

캐릭터별 감소 수치·사이클 패턴·예외는 §스쿼드 구성 §버스트 쿨타임 감소.

### 풀버스트 상태의 전투적 의미

니케 버프·대미지 스킬 대부분이 풀버스트 구간 집중.
- `full_burst_start`, `burst_cast` 타이밍 강력 버프가 이 구간에 집중.
- 풀버스트 자체에서도 전 스쿼드원 딜 계수 +50% (DealForm ③).

### 버스트 단계 전환·진입 타이밍

유저가 B1→B2→B3 버튼 연속으로 누르는 행동 = 계산기에서 **단계 간 0.1초** 고정 모델링 (`burst_switch_delay = 0.1`).

```
idle → stage:1 사용 → switching(0.1초) → stage:2 사용 → switching(0.1초) → stage:3 사용 → full_burst
```

### 버스트 재진입 (Reenter)

일부 캐릭터는 버스트 발동 직후 **같은 단계를 다시 한 번 사용**.
- 재진입 딜레이: **0.5초** (`burst_reenter_delay = 0.5`).
- 계산기 상태: `stage:N → reenter:N(0.5초 대기) → 재진입 발동 → switching(0.1초) → 다음 단계`

현재 재진입 캐릭터: **아니스 : 스타** (B1, 쿨 20초)
- 스쿼드에 다른 B1 아군이 있으면 자신의 B1 발동 후 B1을 한 번 더 재진입.
- 버스트 사이클에 0.5초 딜레이 추가 + burst_cast 1회 더 발생.
- 테스트 스쿼드에서 B1 대용으로 쓰지 않는 이유.

## 트리거 발동 의미

PARSING.md §4 표는 텍스트→JSON 키 변환만 담당. 각 트리거가 *실제로 누구에게·언제* 발동하는지는 이 절에 누적 기록한다. `char-add` 시나리오 작성(단계 1·3) 중 일반 규칙(특정 캐릭터에 한하지 않는 동작)이 새로 확인되면 여기 한 줄 추가.

### timing

- **`burst_enter:N`**: 스쿼드의 누군가가 버스트 단계 N으로 진입 시 본인에게 트리거. 본인이 직접 N단계 발동했을 때만 트리거되는 게 아님. → B3 더미 발동 사이클에서도 B3 캐릭터의 `burst_enter:3` 효과가 본인에게 부여됨.
- **`full_burst_start`**: 스쿼드 풀버스트 진입 시 모든 캐릭터에게 트리거. 본인 burst_cast 여부와 무관. → 본인 미사용 사이클에서도 `full_burst_start` 조건 효과가 본인에게 부여됨 (`burst_enter:N`과 동일 패턴).
- **`battle_start`**: t=0 1회. passive 류와 결합 시 영구 유지.
- **`랩쳐 등장 시` / `랩쳐 사망 시`**: 단일 보스 sim에서 "등장"은 `battle_start` 1회로 처리, "사망"은 고정 시간 sim이라 보스가 죽지 않아 무발동.
- **`event:full_reload`**: 최대 장탄 재장전 완료 시 1회. 자연 ammo 0 도달 또는 수동/효과 트리거 리로드 후 풀로드 시점. 풀버스트 중에도 ammo 상황에 따라 발생 가능.
- **`burst_cast`**: 본인이 직접 자신의 버스트 스킬을 발동했을 때만 트리거. 다른 캐릭터(더미 포함)가 같은 단계 버스트를 발동한 사이클에서는 본인에게 트리거 안 됨. ↔ `burst_enter:N`/`full_burst_start`와 대비.
- **`event:cover_hit`(엄폐물 피격 시)**: buff_manager에 매칭 로직만 있고 notify 호출처가 없어 **보스 sim에서 영구 무발동**. 파싱은 정상 등록하되 시뮬 딜에는 기여하지 않는다 (`enemy_count_above:N`과 같은 클래스). → 해당 효과는 시나리오 체크리스트에 네거티브 항목("한 번도 발동하지 않아야 함")으로 둔다. (슈가 스킬1)
- **`event:[버프명]`**: named buff가 활성화될 때 **스쿼드 전체에 브로드캐스트**. 해당 buff를 활성화한 캐릭터 외 다른 캐릭터도 반응 가능. 각 캐릭터의 `self_state:` / `target: "self"` 등 조건·타겟은 반응하는 캐릭터 본인 기준으로 평가됨. → 프리카 앵콜이 민트의 `event:떼창`에 반응하는 구조.

### target

- **`all_allies`는 시전자 본인 포함**: `target: "all_allies"` 효과는 자신에게도 적용된다. (프리카 스킬3 퍼포먼스 확인)
- **`아군 공용 보호막`은 시전자 본인에게만 부여되며 일반 보호막과 별개 계열이다** (유저 확인). 텍스트에 대상 표기가 없어도 `all_allies`가 아니다. 단 보호막 판정 자체는 성립해 `during_shield`·`event:shield_applied`를 발생시킨다. → 블랑 `럭키 가드`. (보유: 폴리 `폴리스 라인`, 센티 `현장검토`, 라푼젤 : 퓨어 그레이스 `생츄어리` — 모두 미파싱)

### condition

- **`self_state:상태명`**: buff_manager에서 "활성 버프 중 이름이 [상태명]인 항목 존재" 판정. 별도 boolean 플래그 아님.
- **적(랩쳐) 수 조건 (`enemy_count_below:N` / `enemy_count_above:N`)**: 계산기는 단일 보스(적 1기) 기준. → `랩쳐 N기 이하`는 **항상 참**(1≤N), `랩쳐 N기 이상`(N≥2)은 **항상 거짓 → 영구 무발동**. 다수 적 AoE·적 수 게이팅 효과는 보스 sim 딜에 기여하지 않는다. (키 이름은 `char-add` 단계 2에서 확정)
- **`hit_count:N`(일반 공격 N회 명중)의 카운트 주체**: 본인 일반공격만 카운트(caster별). ↔ `part_hit_count`/`body_hit_count`는 스쿼드 전체 명중 브로드캐스트. 코어히트는 일반공격 판정이라 포함, 버스트/스킬 딜은 제외.
- **`대상이 타겟이라면` / `타겟 등장 시`**: 계산기는 단일 보스 sim이고 **보스는 언제나 타겟**이므로 이 조건은 **항상 참** → 무조건 발동으로 처리한다. `타겟 등장 시`는 `랩쳐 등장 시`와 같이 `battle_start` 1회. (로산나)
- **`우선적으로 [클래스] 적 N기에게`**: 단일 보스 sim에서는 **1기에게 1회 적중**. N기 표기라도 딜이 N배가 되지 않는다. (로산나 벤데타 `화력형 적 2기`)
- **`[효과명] 적용 대상 N ▲` / `공격 범위 N% ▲`**: 다른 효과의 타격 대상 수·사거리를 늘리는 버프. 단일 보스 sim에서는 대상이 이미 1기로 수렴해 있어 **항상 no-op** → 파싱은 정상 등록하되 계산기에서는 딜 기여 0, 시나리오 체크리스트에 네거티브 항목("히트 수가 변하지 않아야 함")으로 둔다. (레이 (가칭) 스킬1 — 아스카 : WILLE `섬멸 태세 추가 효과` 대상 +1 / 범위 +500%)
- **`[해제 불가]` 태그는 조건 유지와 무관하다**: 적의 버프 해제 스킬에 대한 면역을 뜻할 뿐, `~% 이상일 때 한하여` 같은 게이지·스택 조건이 붙은 `[지속] [해제 불가]` 버프는 **조건이 깨지면 정상적으로 해제된다** → 조건부 상시 재평가로 모델링한다. (치사토 `초감각` 임계 3단 — 게이지 70/55/25% 경계)
- **`self_hp_above:N`은 보스 sim에서도 상수가 아니다** (유저 확인, 2026-08-10). 아군 피격 모델이 없어 기본값은 100%지만, `max_hp_only_pct`·`hp_only_caster_based_pct`(**현재 체력 유지** 최대 체력 증가)가 걸리면 `hp_pct`가 떨어져 조건이 **꺼질 수 있다**. "어차피 항상 참"으로 상수화하지 말고 런타임 재평가 조건(`_RUNTIME_COND_PREFIXES`)으로 유지한다. (누아르 `럭키챰` 체력 70% 이상)

- **`hit_count:N` 카운터와 condition의 관계**: 카운터는 condition 충족 여부와 **무관하게 진행**된다. condition은 효과 발동만 게이팅하고 카운트는 계속 누적 → 조건 불충족 구간의 공격도 위상(phase)을 밀어낸다. (라플라스 : 얼티밋 히어로 `일반 공격 12회` + `self_state:일렉트릭 파워 풀 풀 차지`)

### 무기 메카닉

- **RL/SR 차지형 무기**: 기본 일반 공격이 풀차지 공격. 특별한 조건 명시 없으면 "일반 공격" 분류 트리거는 매 풀차지 hit에 발동.
- **차지 시간 stat 변경 (`charge_time_fixed`·`charge_speed_pct` 등)**: 차지 중에 stat이 변경되면 진행분(이미 모은 차지 시간)은 유지되고 새 차지 시간 기준으로 남은 시간만 추가 차징. 예: 0.7s 차징 상태에서 차지 시간이 1.2s→3.2s로 변경 → 남은 2.5s 더 차징.
- **`탄환 소모 N발` 표기**: 실제 장탄 소모량이 아니다. 장탄은 1발씩 정상 소모되고, "아군이 소비한 탄의 총합"류 집계에만 N발로 기여한다. (신데렐라 : 크리스탈 웨이브 저격 모드 — `풀 차지 공격 시 탄환 소모 40발`, 최대 장탄 15발과 모순되지 않는 이유)
- **무기 변경(`weapon_change`) 중 탄환 충전 미적용**: `ammo_charge_flat` 등 탄환 충전 계열 효과는 무기 변경 상태에서 적용되지 않는다.
- **`최대 장탄 수 : N발 (사용 무기 변경 시 최대 장탄 수 효과 갱신)` 괄호구**: 변경된 무기의 최대 장탄이 **최대 장탄 수 버프의 영향을 받는다**는 뜻. 이 문구가 없는 무기 변경은 표기된 장탄으로 고정. → 탄수 기반 종료(`duration_bullets`) 무기 변경에서는 장탄 버프가 **모드 지속 시간까지** 바꾸므로 단순 DPS 버프가 아니다. 현재 이 문구 보유: 신데렐라 : 크리스탈 웨이브, 라플라스 : 얼티밋 히어로.
- **무기 변경 모드의 차지형 무기도 `full_charge_hit`를 발동한다**: 변경된 무기에 `차지 시간`·`풀 차지 대미지`가 명시돼 있으면 그 무기의 풀차지 사격도 `풀 차지 공격 시` 트리거를 정상 발동시킨다. → 모드 밖 스킬(스택 충전·게이지 충전 등)이 모드 안에서도 계속 쌓인다. (맥스웰 : 오디너리 미케닉 — 메티스 버스트 버스터 1발이 스킬1 최대 체력 스택·스킬2 버스트 게이지를 사이클당 1회씩 추가 발동)
- **차지 표기가 없는 무기 변경 모드는 그동안 풀 차지가 아예 없다** (인게임 확인, 2026-07-29): 위 항목의 반대쪽이다. 차지형 캐릭터가 버스트로 MG 등 비차지 무기로 바뀌면 모드 지속 내내 `full_charge_hit`가 발동하지 않고, **풀 차지에 걸려 있던 팀 버프도 그 구간 동안 끊긴다.** 끊기는 게 정상이며 버그가 아니다. (벨벳 — 버스트 중 MG 모드 10초 동안 `사랑의 탄환`(아군 차지 대미지)이 사라지고, 그만큼 차지형 동료의 딜이 내려간다)
- **무기 변경 모드가 끝나면 원래 무기의 장탄은 전부 복구된다** (유저 확인, 2026-08-08): 모드 진입 전 잔탄이나 모드에서 소모한 탄수와 무관하게 **풀로드로 복귀**하며, 복귀 직후 재장전이 삽입되지 않는다. (맥스웰 `피어스 샷` — 장탄 1발 모드 종료 후 기본 SR 6/6)
- **최대 장탄 증가 버프가 만료되면 초과 잔탄은 잘린다** (유저 확인, 2026-08-10). `[N초 유지]`가 붙은
  `max_ammo_flat`·`max_ammo_pct`가 끝나는 순간 현재 잔탄이 원래 최대치를 넘고 있으면 원래 최대치로
  내려간다 — 남은 탄을 다 쏠 때까지 유지되지 않는다. **계산기는 아직 이 캡을 걸지 않는다**(잔탄은 발사로만
  줄고 만료 시 재평가가 없다) → 누아르 등록(단계 4)에서 구현한다. (누아르 `래빗 트윈즈 B` 최대 장탄 +5발 10초)
- **무기 변경 모드의 사격은 `weapon_hit:[name]` 이벤트를 쏘지 않는다** (코드 확인, 2026-08-13). 그 이벤트는 `_handle_damage_eff()`가 **named damage 효과**(발사체 등)를 명중시킬 때만 발생하고, `_tick_weapon_change()`의 발사 루프에는 호출처가 없다. → 모드의 **매 발마다** 따라붙는 효과는 `weapon_hit:`이 아니라 **`hit_count:1` + `self_state:[모드명]` 게이팅**으로 센다. 모드 사격도 일반 공격이라 `hit_count`는 정상 누적된다. (라플라스 `라플라스 버스터 4` — 매 발 방어력 무시 딜)
- **무기 변경 모드 진입 시 이전 무기의 차지 진행분은 이어지지 않는다** (인게임 확인): 모드 진입 프레임에 차지를 새로 시작한다. 위 `차지 시간 stat 변경`(진행분 유지)과는 **다른 규칙** — 그쪽은 같은 무기의 stat만 바뀐 경우고, 이쪽은 무기 자체가 교체된다. 이어받게 두면 변경 무기의 차지가 **짧을수록 손해**가 되는 역설이 생긴다: 진입 시점에 이미 `차지 시작 + 짧은 차지`가 지나 있어 즉시 발사되고, 풀버스트 진입(버스트 사용 +0.15초) 전에 쏴 버프를 통째로 놓친다. (맥스웰 : 오디너리 미케닉 — 과전류 5단계 0.4초가 4단계 1.5초보다 대미지가 34% 낮았다)

### 값 산정

- **`시전자 기준 [stat]` 계열은 시전자의 *버프 제외 기본 스탯*으로 환산된다** (유저 확인, 2026-08-10).
  `atk_caster_based_pct`는 `state["base_stats"][시전자]["atk"]`를 읽으므로 시전자에게 걸린 공격력 버프가
  값을 키우지 않는다 → **부여 시점 스냅샷이냐 매 프레임 재평가냐를 따질 필요가 없다.**
  (누아르 `럭키챰` — `[지속]`이라 t=0 1회 부여뿐이지만 이 성질 덕에 문제되지 않는다)
- **버프를 언제 읽는지가 대미지 종류마다 다르다** (유저 조사, 2026-08-11).
  - **순차 대미지(`sequential_damage`)는 풀버스트 *시작 전* 버프로 계산된다.** B3 버스트는 풀버스트보다
    0.05초 앞서 발동하므로, `burst_cast` 시점에 즉시 계산하는 현행 동작이 곧 이 규칙이다 —
    `bonus_damage`처럼 `_pending_burst_dmg`로 풀버스트까지 미루면 **안 된다**.
  - **지속 대미지(`dot_damage`)는 틱이 들어가는 순간의 버프로 계산된다.** 그래서 DoT의 **위상**이
    곧 딜이다 — 같은 틱 수라도 풀버스트 안에 몇 개가 들어가느냐가 달라진다.
  - → 다중 히트가 시간에 걸쳐 들어가는 효과를 **한 시점에 몰아 쏘면 조용히 틀린다.**
    사쿠라 : 블룸 인 서머 `화양연화 2`에서 램프 10틱(배율 합 55)을 버스트 시각에 몰았더니
    램프 전체가 풀버스트 밖으로 밀리고 대신 10중첩 틱이 3회 더 버프를 받았다 —
    상쇄되지 않고 순 손해 쪽으로 어긋났다. `ramp_interval`로 실제 타간 간격을 펼쳐 해결했다.
- **서로 다른 효과가 같은 stat을 걸면 합산된다** (유저 확인). 대상 범위·지속시간이 달라도 각각 별개 버프
  항목으로 병존하며 값이 더해진다 — 큰 값 하나만 적용되는 게 아니다.
  (누아르 `피날레` — 샷건 아군 10초분과 동일 스쿼드 30초분의 명중률·저지 부위가 겹치는 구간에서 합산)

### 버프 스택

- **스택 부여는 지속시간도 갱신한다** (일반 규칙, 유저 확인). 중첩형 버프에 스택이 추가되면 — 같은 효과가
  재발동하는 경로(`_activate()`)든 별도 항목이 올려주는 경로(`buff_stack_add`)든 — 남은 지속시간이
  **새로 부여된 것과 동일하게 갱신**된다. 원문 `[스택명 : ...] [N 중첩] [M초 유지]`가 "버프를 다시 붙이는"
  문장이기 때문이다. `[지속]`(`duration: -1`)은 만료가 없어 해당 없음.
  → **유한 지속시간 스택 버프는 스택이 계속 들어오는 한 만료되지 않는다.** 스택 공급이 끊긴 시점부터
  M초를 센다. 이걸 "각 스택이 따로 만료된다"로 모델링하면 최대 중첩 도달률이 크게 떨어진다
  (팬텀 `괴도의 단검` 5초·3중첩 — 미갱신 시 최대중첩 proc 42회→23회, 본인 딜 −12.3%).

### 효과 실행 순서 (동일 timing)

같은 timing에 복수 효과가 발동할 때의 순서 규칙 중 **여러 캐릭터에 공통**인 것을 누적한다(캐릭터 한정 순서는 각 시나리오에 둔다). `char-add` `SCENARIO.md` Step 6 최빈 사각지대(효과 실행 순서)에서 일반 규칙이 확인되면 여기 한 줄 추가 — 매번 재발견되지 않도록.

- **스택 부여와 `최대 중첩 시` 판정이 같은 timing이면 같은 프레임에 부여 → 판정 → 소비**까지 처리된다. 결과적으로 최대 중첩 상태의 버프는 한 발도 쓰이지 못하고 해제된다. (라플라스 : 얼티밋 히어로 예열 5중첩 → 즉시 무기 변경 — 5중첩째 차지 속도 +50%는 실효 없음)
- **원문 `■` 블록의 서술 순서가 곧 실행 순서다** (유저 확인). 같은 timing에 딜 블록과 디버프 부여 블록이 함께 있을 때, 딜이 **먼저** 적혀 있으면 그 딜은 뒤에 부여되는 디버프(`받는 대미지 ▲` 등)의 영향을 받지 않는다. → **파싱 시 배열 순서를 원문 블록 순서 그대로 유지**한다. (로산나 벤데타 — 아살토 딜 → 수냉 타겟 `받는 대미지 29% ▲`, 이번 버스트 딜에는 미적용)
- **카운터(스택·게이지) 부여와 그 카운터를 읽는 무기 변경이 같은 timing이면 부여가 먼저 반영된 뒤 무기 변경이 읽는다.** 따라서 첫 발동부터 카운터 1로 센다. → **파싱 시 배열 순서 제약**: 충전 항목을 무기 변경 항목보다 **앞**에 둔다. 뒤집히면 단계 램프가 한 칸씩 밀린다. (맥스웰 : 오디너리 미케닉 — 1회차 버스트에서 과전류 1단계 차지 시간이 적용됨)
- **주기 틱(`tick_interval`)에는 두 유형이 있다** (유저 조사, 2026-08-07). 회수는 양쪽 같고(2초 간격 10초 = **5회**, 1초 간격 10초 = **10회**) 다른 것은 **위상**이다.

  | 유형 | 첫 틱 | 10초·2초 간격의 틱 시각 | 캐릭터 |
  |---|---|---|---|
  | **type 1** | 스킬 발동과 **동시** | 0·2·4·6·8 | 미하라 : 본딩 체인 · 에이다 · 아크레인저 블랙 |
  | **type 2** | 발동 후 **+interval** | 2·4·6·8·10 (**만료 프레임 틱 포함**) | 디젤 : 윈터 스위츠 · 밀크 : 블루밍 바니 |

  type 1은 첫 틱이 **풀버스트 시작 전에** 떨어질 수 있고, type 2는 첫 틱부터 풀버스트 안이다 — 버스트 버프를 몇 틱이 받느냐가 갈린다. 위 목록에 없는 캐릭터(브래디·레이븐 등)는 **미확인**.

  **계산기는 아직 두 유형을 구분하지 않는다** — `_dot_timers`/`_instant_timers`는 type 2 위상이면서 `t >= expires_at`에서 틱 없이 만료해 **4회**가 되고(만료 프레임 틱 누락), `every:Ns`(`_next_fire`)는 전투 시작 기준 **전역 격자**라 스킬 발동 시점과 위상이 무관하다. 수정 시 해당 캐릭터 baseline이 전부 바뀐다 — 별건으로 처리한다.
- **`[N발 유지]`(`duration_bullets`) 버프를 "발사가 1발을 소모했다"고 셀지는 그 트리거가 대미지 계산보다 앞서는가로 갈린다** (2026-08-07, 아인 파싱 중 발견). 발사 처리 안에서 부여되는 버프는 두 부류다 — `full_charge`(차지 완료 = 발사 **전**)처럼 그 발이 버프를 받는 것은 1발로 세는 게 맞고, `full_charge_hit`(명중 **후**)처럼 이미 계산이 끝난 뒤 붙는 것은 **받지도 못한 발에 소모만 당해 버프가 통째로 사라진다**. 코드에서는 `buff_manager._BULLET_BOUND_TIMINGS` 등록 여부가 이 판정이다. → 새 캐릭터에 발사 트리거 + `duration_bullets` 조합이 나오면 timeline의 `calc_damage` ↔ `notify` 순서를 먼저 확인한다. (아인 `페더 샷` — `full_charge_hit`이 등록돼 있어 차지 대미지 80%가 한 발에도 적용되지 않았다)
- **최대 장탄 증가와 탄환 충전이 같은 블록에 있으면 장탄 증가가 먼저 반영된 뒤 그 최대치를 기준으로 충전한다** (유저 확인, 2026-08-10). 원문 블록 순서 규칙의 한 사례다 — `[최대 장탄 수 N발 ▲]` → `[탄환 충전 M%]` 순서면 충전량·상한 모두 **증가된 최대치** 기준. → 파싱 시 장탄 항목을 충전 항목보다 **앞**에 두고, 충전 핸들러가 읽는 유효 최대 장탄에 `max_ammo_flat`이 포함되어야 한다. (누아르 `래빗 트윈즈 B` — 9발 기준 4발이 아니라 14발 기준 6발)
- **`tick_interval` 주기 instant(회복·게이지 충전·소모 등)의 첫 발동은 현재 등록 +interval이다**(`buff_manager._instant_timers`). 즉시 1회 발동하지 않으므로, 같은 프레임에서 뒤에 오는 항목이 읽는 게이지·스택 값을 앞당겨 바꾸지 않는다. (아크레인저 블랙 — 배터리 드레인이 즉시 1% 깎으면 뒤따르는 `gauge_eq:배터리:100` 긴급 충전 −50%가 발동하지 못해 변신이 10초가 아니라 20초가 된다)
  > ⚠️ **위 type 1/2 분류와 충돌 가능** — 아크레인저 블랙은 type 1(즉시 첫 틱)로 분류됐는데, 배터리 드레인을 즉시 발동으로 바꾸면 변신이 10초 → 20초가 된다. 유형이 **캐릭터 단위인지 효과 단위인지**(주기 *대미지*만 type 1이고 게이지 드레인은 별개인지) 미확인. 주기 틱 수정 작업에서 먼저 확인할 것.

| 관찰 현상 | 의미 |
|-----------|------|
| 풀버스트 사이클 간 긴 갭 (게이지 충전 완료 후 수십 초 대기) | 특정 단계 쿨이 길거나 `burst_cooldown` stat 미반영 |
