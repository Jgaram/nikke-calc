# NIKKE 게임플레이 메커니즘 — 계산기 맥락 참고용

실제 플레이어가 체험하는 전투 메커니즘을 정리한 문서.
개별 스킬 구현 명세(→ MAINTENANCE.md)가 아니라, **시뮬레이션 결과가 "맞다"는 게 어떤 모습인지** 판단하기 위한 기준으로 사용한다.

---

## 전투 기본 설정

- **전투 시간**: 180초. 계산기 기본값 (`DEFAULT_CONFIG["duration"]`).
- **적**: 단일 보스 1명. 복수 적 환경은 현재 시뮬레이터 모델 범위 밖.
- **스쿼드**: 기본 5인. 그 이하도 가능하나 5인이 표준.

---

## 스쿼드 구성

### 버스트 쿨타임 현황

| 단계 | 일반적 쿨타임 | 비고 |
|------|-------------|------|
| B1 | 20초 | 간혹 40초·60초도 있음 |
| B2 | 20초 | 간혹 40초·60초도 있음 |
| B3 | 최소 40초 | 현 니케 풀에 20초짜리 없음 |

### 유효한 스쿼드의 조건

버스트 사이클이 끊기지 않으려면 **각 단계(B1·B2·B3)에 한 사이클 안에 쿨이 도는 캐릭터가 있어야** 한다.

- **B3는 쿨이 최소 40초**이므로 항상 2명 필요 (번갈아 사용).
- **B1·B2가 20초**이면 각 1명으로 충분.
- **B1·B2가 40초**이면 2명 필요. B1 20초 1명 + B1 40초 1명 조합도 가능.

전형적인 5인 구성: **B1×1 + B2×1 + B3×2 + 버스트 미사용×1**

### 버스트 쿨타임 감소

대부분의 실전 스쿼드는 **버스트 쿨타임 감소 캐릭터**(주로 B1·B2)를 포함한다.
게이지 충전 속도가 쿨타임보다 빠르면 대기 구간이 생기기 때문.

- 실전 쿨 감소량: 아군 전체 기준 **약 6~8초**
- 사이클 주기: 쿨 감소 적용 시 약 **12~14초** (대표값 7.48초)
- 180초 기준: 풀버스트 14회 + 종료 직전 15번째 시작

**계산기 구현**: `burst_cooldown` buff stat. `_effective_burst_cool()`에서 반영.

### 더미 캐릭터 "B3"

`parsed_nikke.json`에 **스킬 없는 3버스트 AR 캐릭터** `"B3"`가 등록돼 있다 (쿨 40초).
스킬이 없어 버프·딜에 영향 없이 버스트 사이클 완성 용도로만 사용.
B3 슬롯을 채울 때 씀.

### 표준 테스트 스쿼드

**B1 기준으로는 `리틀 머메이드` (쿨 20초)를 사용한다.**
`아니스 : 스타`는 B1이지만, 팀에 다른 B1이 있으면 B1 재진입이 발동해 사이클이 복잡해지므로 B1 슬롯 대용으로 쓰지 않는다.

**테스트 대상 단계별 스쿼드 구성:**

```python
# 대상이 B3, 쿨 40초
squad = [make_char(n) for n in ["리틀 머메이드", "크라운", TARGET, "B3"]]

# 대상이 B1, 쿨 20초
squad = [make_char(n) for n in [TARGET, "크라운", "B3", "B3"]]

# 대상이 B1, 쿨 40초 (보조 B1 필요 → 5슬롯 모두 사용)
squad = [make_char(n) for n in [TARGET, "리틀 머메이드", "크라운", "B3", "B3"]]

# 대상이 B2, 쿨 20초
squad = [make_char(n) for n in ["리틀 머메이드", TARGET, "B3", "B3"]]

# 대상이 B2, 쿨 40초 (보조 B2 필요 → 5슬롯 모두 사용)
squad = [make_char(n) for n in ["리틀 머메이드", TARGET, "크라운", "B3", "B3"]]
```

### 버스트를 쓰지 않는 캐릭터 지정

```python
result = simulate(squad, config={"no_burst_char": "캐릭터명"})
```

지정된 캐릭터는 `BurstController` 단계 목록에서 제외된다.

### 캐릭터 버스트 정보 확인

```python
import json
nikke = json.load(open("data/parsed_nikke.json", encoding="utf-8"))
print(nikke["캐릭터명"]["burst_stage"])    # "1" / "2" / "3"
print(nikke["캐릭터명"]["burst_cooldown"]) # 초 단위
```

## 풀버스트 사이클

### 기본 구조

```
버스트 게이지 충전 → [B1 발동] → [B2 발동] → [B3 발동] → 풀버스트 상태 (~10초) → 종료 → 충전 재시작
```

- 버스트 게이지는 스쿼드 전체가 공격할수록 쌓인다.
- B1→B2→B3 순서로 연속 발동해야 풀버스트 상태에 진입한다.
- 풀버스트가 끝나면 다시 게이지 충전 단계로.

### 풀버스트 상태의 전투적 의미

니케의 버프와 대미지 스킬 대부분이 풀버스트 구간에 집중된다.
- `full_burst_start`, `burst_cast` 타이밍의 강력한 버프가 이 구간에 몰려 있다.
- 풀버스트 상태 자체에서도 전 스쿼드원 딜 계수 +50% (DealForm ③).
  - 수식상 ③의 한 항목이라 "딜이 1.5배"와는 다르지만 체감상 이 구간이 가장 강하다.

### 버스트 단계 전환·진입 타이밍

유저가 B1→B2→B3 버튼을 연속으로 누르는 행동을 계산기에서는 **단계 간 0.1초** 고정으로 모델링한다 (`burst_switch_delay = 0.1`, timeline.py).

```
idle → stage:1 사용 → switching(0.1초) → stage:2 사용 → switching(0.1초) → stage:3 사용 → full_burst
```

### 버스트 재진입 (Reenter)

일부 캐릭터는 버스트 발동 직후 **같은 단계를 다시 한 번 사용**한다.
- 단계 전환 없이 같은 단계 재사용. 재진입 딜레이: **0.5초** (`burst_reenter_delay = 0.5`).
- 계산기 상태: `stage:N → reenter:N(0.5초 대기) → 재진입 발동 → switching(0.1초) → 다음 단계`

현재 재진입 캐릭터: **아니스 : 스타** (B1, 쿨 20초)
- 스쿼드에 다른 B1 아군이 있으면 자신의 B1 발동 후 B1을 한 번 더 재진입한다.
- 이 때문에 다른 B1과 함께 쓰면 버스트 사이클에 0.5초 딜레이가 추가되고 burst_cast가 1회 더 발생한다.
- 테스트 스쿼드에서 B1 대용으로 쓰지 않는 이유.

## 시뮬레이션 결과 검증 기준

| 관찰 현상 | 의미 |
|-----------|------|
| 풀버스트 사이클 간 긴 갭 (게이지 충전 완료 후 수십 초 대기) | 특정 단계 쿨이 길거나 `burst_cooldown` stat 미반영 |
| 특정 캐릭터가 2~3사이클에 1회 발동 | 쿨타임 정상 (40초 캐릭터가 번갈아 사용되는 것). 의도된 동작인지 확인 |
| 180초 기준 풀버스트 횟수가 14~15회 미만 (쿨 감소 덱 기준) | 사이클 주기 이상 — 쿨 감소 미반영 또는 갭 발생 |
| 풀버스트 상태에서 딜이 비풀버스트 대비 예상보다 낮음 | DealForm ③ `full_burst +50%` 미반영 가능성 |
| 버스트 쿨 감소 스킬이 있는데도 대기 발생 | `_effective_burst_cool()` 반영 오류 또는 timing 불일치 |
