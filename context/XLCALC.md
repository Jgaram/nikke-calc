# 참조 엑셀 계산기 (xlcalc)

유저가 손으로 만든 스프레드시트 딜 계산기. 우리 시뮬레이터와 **독립적으로** 같은
DealForm을 구현하고 있어, 시뮬 결과를 교차 검증하는 기준선으로 쓴다.

| | |
|---|---|
| 원본 | `../계산기.xlsx` (2026-08-03 01:13 스냅샷, 499,735 B, 16시트) |
| 정리본 | `context/xlcalc.xlsx` (233,286 B, 7시트) |
| 구동 도구 | `context/xlcalc.py` |
| 전제 | Windows + Excel 설치 + `pywin32`. 수식 재계산이 필요해 openpyxl로는 불가 |

원본은 유저가 계속 편집한다. **정리본은 스냅샷이며 자동으로 따라가지 않는다.**
원본이 갱신되면 아래 `§원본 재이관`을 따른다.

## 1. 도구 사용법

```bash
python -m context.xlcalc --list                              # 엑셀이 아는 딜러·서포터 이름
python -m context.xlcalc "신데렐라,아니스,마스트,앵커"          # 요약
python -m context.xlcalc "신데렐라,아니스,마스트,앵커" --view cols   # 열별 한발대미지·발수·소계
python -m context.xlcalc "신데렐라,아니스,마스트,앵커" --view buff   # 위상별 버프 합산표
python -m context.xlcalc "라피" --core 1 --enemy-def 40000 --element 1
```

첫 항목이 딜러, 나머지가 서포터1~4. 매 실행마다 임시 사본을 열고 버리므로
`xlcalc.xlsx`는 변하지 않는다 (`--save`를 줘야 반영된다).

**이름이 우리 로스터와 다르다.** 엑셀은 축약명을 쓴다 — 반드시 `--list`로 확인한다.

| 엑셀 이름 | 실제 캐릭터 | 판별 근거 |
|---|---|---|
| 마스트 | 마스트 : 로망틱 메이드 | 엑셀 블록이 지원형 **MG** (기본 마스트는 지원형 SMG) |
| 앵커 | 앵커 : 이노센트 메이드 | 엑셀 블록이 **지원형** RL (기본 앵커는 방어형 RL) |
| 아니스 | 아니스 : 스타 (추정) | 방어형 RL + 공격댐 34.0 + 발사체폭발 92.03 + 시공증 35.01 이 스킬2와 정확히 일치 |

블록 1행의 `클래스`·`무기`가 가장 확실한 판별 수단이다.

## 2. 시트 구성

```
메인 (대시보드 · 입력)
 ├─ 니케스팩       클래스/무기별 기본 스탯, 평타 판정용 무기 목록(M열), 기본 탄착군(P열)
 ├─ 니케목록       메인!F4·G4:J4 드롭다운 유효성 검사 원본 (계산 수식 없음)
 └─ 딜량계산       DealForm 계산부 — 여기가 핵심
     ├─ 버프정리   6위상 × 5인 버프 집계
     │   ├─ 딜러데이터    딜러 자버프 (캐릭당 6열)
     │   └─ 서포터데이터  서포터 팀버프 (캐릭당 6열)
     ├─ 딜러데이터  계수·발수·차지·딜레이·대미지유형
     └─ 니케스팩
```

정리 시 삭제한 시트 (어느 수식도 참조하지 않음을 확인):
`브리드` `딜규칙` `비교` `이사벨` `라피` `헬름` `사격장` `라피(사격장)` `헬름(사격장)`

`딜규칙`은 메모 시트였고 내용은 아래 `§5 계산 규칙 메모`로 옮겼다.

## 3. 계산 구조

### 3-1. 위상 격자 — 이 계산기의 뼈대

`딜량계산` C~U열이 **한 사이클을 6구간 × 최대 4종 대미지로 쪼갠 격자**다.

| 열 | 구간 | 버프정리 위상 | 스킬index | 발수 | 풀버스트 +50% |
|---|---|---|---|---|---|
| C | 버스트 시전 | D 자버직전 | 0 | 10초분 | ❌ |
| D | 버스트 추가 | J 자버전반 | 1 | 10초분 | ✅ |
| E~H | 자버 전반 딜1~4 | J 자버전반 | 2~5 | 5초분 | ✅ |
| I~L | 자버 후반 딜1~4 | P 자버후반 | 2~5 | 5초분 | ✅ |
| M | 자버 이후 | V 자버이후 | 0 | 10초분 | ❌ |
| N~Q | 타버 전반 딜1~4 | AB 타버전반 | 2~5 | 5초분 | ✅ |
| R~U | 타버 후반 딜1~4 | AH 타버후반 | 2~5 | 5초분 | ✅ |

- **자버** = 딜러 본인이 3단 버스트를 쓰는 풀버스트, **타버** = 다른 아군이 채우는 풀버스트
- 풀버스트 보너스는 `IF(스킬index≠0, 0.5, 0)` — 버스트 시전 순간은 풀버스트 직전으로 본다
- `메인!N16` = 1사이클 = 자버 10초 + 타버 10초 = **고정 20초 구성물**
- 총딜 = `1사이클 × 사이클 수` (`메인!L9:Q9`가 6/6.5/7/8/9 사이클을 나열)

### 3-2. 수식

```
대미지 = 평균한발대미지(r19) × 발수(r9)

r19 = MAX(1, ①계수 × ⑦우월 × ②공방차 × ⑤유형별 × ⑥적받는
              × (평타면 ③일반 / 스킬이면 ③스킬)
              × (차지태그면 ④차지) )
```

| 항 | 수식 |
|---|---|
| ① r21 | `계수 × (1 + 일반공격대미지배율)` |
| ② r23 | `딜러ATK×(1+공증합) + 시전자기준공격력합 − 적방어력×(1−MIN(1,방깎))`<br>`방어력무시` 태그면 방어력항 = 0 |
| ⑤ r24 | `1 + 공격대미지 + Σ(히트 태그와 이름이 일치하는 유형별 버프)` |
| ⑥ r25 | `1 + 받는대미지증가 + IF(분배태그, 분배대미지증가, 0)` |
| ③ 평타 r26 | `1 + [풀버스트 0.5] + (0.15+MIN(1,크확+평타크확))×(0.5+크댐+평타크댐)`<br>`+ (코어여부 + 코어댐증가 + [관통&파츠코어 → +1]) × 코어히트율 + [적정거리 0.3 + 적정거리댐증가]` |
| ③ 스킬 r28 | `1 + [풀버스트 0.5] + (0.15+MIN(1,크확))×(0.5+크댐)` — 코어·적정거리·평타전용 크리 제외 |
| ④ r29 | `기본차지배율×(1+소장품차지댐) **+** 차지대미지증가` ← **합산** (우리는 곱셈) |
| ⑦ r22 | `IF(우월코드여부, 1.1 + 우월코드댐증가, 1)` |
| 코어히트율 r27 | `(코어px / MAX(코어px, 기본탄착군 × (1 − 명중률/1.15)))²` |
| 발수 r9 | index 0·1 → 10초분 / 그 외 → `0.5 ×` (차지무기면 `10/(차지시간×(1−차속)+딜레이)`, SG면 `×(1+펠릿증가)`) |

버프 집계(`버프정리`)는 위상마다 **[장비·소장품·큐브 상수 C열] + [딜러 D열] + [서포터1~4]**
를 단순 합산한 스칼라 하나다. 시간축이 없다.

## 4. 엑셀의 핵심 가정

| # | 가정 | 근거 |
|---|---|---|
| 1 | **스택형 스킬은 최고 스택 고정** | `메인!L10` "스택형 스킬의 초반 딜로스는 고려하지 않음" |
| 2 | **재장전·장탄 미고려** | `메인!B38~D40` 메모. 다만 재장속 ≥100%면 실제로 0초라 이 조합에선 타당 |
| 3 | **크리티컬은 기대값** | `(0.15+크확)×(0.5+크댐)` 가산 |
| 4 | **발수는 손입력** | `딜러데이터` r56/r69에 캐릭·위상별로 직접 적는다 |
| 5 | **사이클은 자버/타버 교대 20초** | 3단 버스트가 둘 이상인 조합을 암묵 전제 |
| 6 | **버프는 위상 내내 100% 유효** | 발동 조건·지속시간·중첩 시간축 없음 |
| 7 | **코어는 확률을 배율에 곱함** | 히트별 샘플링 아님 (기대값) |

## 5. 계산 규칙 메모 (삭제한 `딜규칙` 시트 원문)

- **[버스트]추가대미지** — 버스트 보너스 + 풀버스트 시 버프 적용
- 추가대미지가 아니면 보너스·버프 적용 ×, 단 받는 대미지 관련은 적용
- "버스트 스킬 대미지"가 아닌 버스트 스킬은 "버스트 스킬 대미지 버프"를 받지 않음
- **스킬** — 거리 보너스 없음
- **라피 폭발** — 코뎀 ×, 거리 보너스 받음
- **배율** — 기본 스탯에 곱한 후 합산
- **차지** — 발수/횟수 없이 딜레이와 차속만으로 계산
- 기본 딜레이 0.23, 개별 니케가 다르면 따로 입력 (흑련 0.43, 앨리스 0.25~0.27, 레이븐 0.1)
- 명중률 탄퍼짐 공식 — <https://arca.live/b/nikketgv/96243965>
- 무기군별 공격속도 — <https://arca.live/b/nikketgv/93391585>

### 6-3. 설계상 차이 — 고칠 대상 아님

| 항목 | 엑셀 | 우리 |
|---|---|---|
| 시간축 | 위상별 손입력 발수, 20초 고정 사이클 × 사이클 수 | 180초 1/60초 프레임 시뮬 (버스트 쿨·재장전·차지·탄약 추적) |
| 스택 | 최고 스택 고정 | 실시간 중첩 (`scaling: stack_count`) |
| 크리티컬 | 기대값 | 히트별 난수 (`calc_damage_avg`는 기대값 경로 제공) |
| 코어 판정 | 확률 × 배율 | 히트별 베르누이 (SG는 펠릿마다 독립) |
| 재장전 | 무시 | 장탄·재장속 반영 |
| 버프 발동 조건 | 위상 내내 유효 | `full_burst_start_count:N` 등 조건·횟수 추적 |

### 6-4. 사소한 수치 차이

| 항목 | 엑셀 | 우리 |
|---|---|---|
| 코어히트율 지수 | `(r_c/R)²` | `(r_c/R)^2.55` (`weapon_mechanics.json _model_n`) |
| 명중률 → 탄착군 | `D × (1 − 명중/1.15)` | `D − slope×명중` (= `D × (1 − 명중/1.10)`) |
| 기본 탄착군 px | AR 75 / SG 250 / RL 1 | AR 76 / SG 240 / RL 10 |
| 크리 확률 상한 | `0.15 + MIN(1,버프)` → 최대 115% | 클램프 없음 |
| 코어 대미지 기준 | `메인!C4` 0~1 수동 노브 | `weapon.core_dmg_mult` (200% → +1.0) |
| 관통 + 파츠코어 | `+1` 추가 가산 | 미구현 |
| 적정거리 버프 | `0.3 + 적정거리댐증가` | `+0.3` 고정 (`optimal_range_dmg_pct` ❌ — IMPL-STATUS.md) |
| 방어력무시 | 이진 태그 (방어력항 0) | `def_ignore_pct` % + `is_armor_break_damage` 태그 |

## 7. 원본 대비 변경 이력 (레포 기준 정렬)

정리본은 원본에서 시트를 지운 것 외에 아래를 수정했다. 목적은
기본 육성 스펙(`context/spec.py DEFAULT_CHAR`)과 육성·장비 전제를 일치시키는 것.

| 시트!셀 | 원본 | 정리본 | 사유 |
|---|---|---|---|
| `니케스팩!I27` | 1093 | **1367** | 갑(몸통)5 공격력 **지원형**. 원본은 지원형/방어형이 뒤바뀌어 있었다 |
| `니케스팩!J27` | 1367 | **1093** | 갑(몸통)5 공격력 **방어형**. 레포 `equipment_stats.json` = 화력 1639 / 지원 1367 / 방어 1093 |

| `메인!C19` | 0% | **20%** | 장비 옵션 공격력 (`equip_skills.atk_pct`) |
| `메인!C20` | (빈칸) | **120%** | 장비 옵션 최대 장탄 수 (`equip_skills.max_ammo_pct`) |

> 한 번 `=메인!C18`로 지웠다가 되돌렸다. 다시 지우지 말 것.

**소장품 하드코딩은 레포와 이미 완전히 일치**해서 손대지 않았다

## 8. 원본 재이관

원본(`../계산기.xlsx`)이 갱신되면:

1. 원본이 Excel에서 열려 있으면 닫는다 (열려 있으면 `PermissionError`)
2. 스냅샷을 뜨고 → 시트 7개만 남기고 → `§7` 표의 수정을 다시 적용한다
3. `python -m context.xlcalc "..." --view buff`로 기본 스탯이 `calculator/base_stat.py`와
   여전히 일치하는지 확인한다

`§7`의 수정은 **원본에도 반영해 달라고 유저에게 알리는 편이 낫다** —
특히 `니케스팩!I27/J27` 스왑은 원본의 실제 오류다.
