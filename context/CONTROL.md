# 컨트롤 — 유저 조작으로 얻는 딜 이득

니케는 조작 실력에 따라 같은 스쿼드·같은 육성에서도 딜이 달라진다. 이 문서는 계산기가
재현하는 **컨트롤 요소의 정본**이다 — 게임 메커니즘, 계산기 모델, 설정 스키마, 적용 대상.

컨트롤은 **자동(꺼짐)이 기본**이다. 예외는 캐릭터별 기본 레이어에 등록된 니케뿐이며
(아래 §캐릭터별 기본 컨트롤), 이들은 어디서 돌리든 켜진 채로 계산된다. 항상 켜지는 쪽은
앨리스·아인·밀크 : 블루밍 바니, **조합에 따라 켜지는 쪽**은 에이다·미하라 : 본딩 체인·아인이다.

| 컨트롤 | 대상 | 무엇을 바꾸나 |
|---|---|---|
| [톡톡이](#톡톡이) | 차지형(SR/RL) | 차지를 끝까지 하지 않고 짧게 눌렀다 떼기를 반복. 발당 대미지↓ 발사 횟수↑ |
| [장전컨](#장전컨) | 전 무기 | 엄폐로 재장전을 유리한 버프 구간에 밀어 넣는다 |
| [버스트 엄폐컨](#버스트-엄폐컨) | 전 무기 | 본인 버스트 사이클의 풀버스트 동안 엄폐해 한 발도 쏘지 않는다 |
| [홀드](#홀드) | 차지형(SR/RL) | 풀차지 후에도 떼지 않고 들고 있다가 원하는 시점에 발사 |

> **엄폐컨과 홀드는 같은 목적의 두 수단이다** — 둘 다 "쏘지 않는" 컨트롤이고, 발수로
> 소모되는 버프(`duration_bullets`)를 일반 공격에 흘리지 않으려고 쓴다. 차지형은 홀드가
> 낫다: 엄폐는 차지를 버리는데 홀드는 들고 있는 동안 차지 배율까지 챙긴다.

> 실제로는 **같은 시간에 여러 캐릭터를 동시에 컨트롤할 수 없다** (캐릭터를 바꿔가며 하는 건 가능).
> 계산기는 이 제약을 검사하지 않는다 — 여러 캐릭터에 동시에 켜면 그만큼 비현실적인 상한이 된다.

## 조작 원시타입 — 컨트롤은 두 개뿐이다

실제 조작은 **한 니케를 선택한 상태에서 좌클릭을 누르거나, shift로 엄폐시키거나** 둘뿐이다
(에임 이동은 이 계산기가 다루지 않는다). 둘 다 시작점과 끝점을 가진 **구간**이고,
**보고 있지 않은 나머지 4명은 언제나 자동으로 싸운다 — 자동이 디폴트다.**

| 원시타입 | 구간의 의미 |
|---|---|
| `click` | 누르는 동안 차지, **떼는 순간 발사**. 짧게 끊으면 톡톡이, 길게 잡으면 홀드 |
| `cover` | 구간 내내 사격·차징 안 함. 진입 시 재장전이 걸린다 |

**엄폐 중에는 차징도 사격도 물리적으로 불가능하다.** 그래서 두 컨트롤은 애초에 충돌할 수
없고, 계산기도 우선순위를 판정하지 않는다 — 배타는 실행층 한 곳에서만 강제된다.

### 전략과 시퀀스는 같은 입구로 들어간다

계산기는 **2층**이다. 아래층(실행층)은 위 구간만 알고, 그 구간을 누가 만들었는지는 모른다.

```
기본 전략(정책) ─┐
                  ├→ 구간(click · cover) → 실행층 → 물리 배타 강제
명시 시퀀스     ─┘
```

**우리가 정의하는 정책은 기본 전략일 뿐이다.** 실전에는 더 복잡한 시퀀스가 얼마든지
가능하므로, 정책으로 표현되지 않는 조작은 [§명시 시퀀스](#명시-시퀀스)로 시각을 직접 찍는다.
둘은 같은 입구를 쓰기 때문에 표현력에 차이가 없다.

> **엄폐를 연 틱은 거기서 끝난다** — 자세 전환에 최소 1프레임이 든다. 재장전이 0초인
> 구간에서 이 1프레임이 결과를 가르므로(정책 A가 노리는 구간이 정확히 거기다) 임의로 바꾸지 않는다.

## 설정 스키마

캐릭터 config(`squad` 원소)의 `control` 키. 없거나 `{}`면 컨트롤 없음.

```python
{
    "name": "앨리스",
    "stat": {...},
    "control": {
        # 기본 전략 (정책)
        "tap_fire": {"rate": 3.6, "release": 0.03},
        "reload":   {"policy": "before_fb_end", "lead": 0.3},
        "cover":    {"policy": "own_full_burst"},
        "hold":     {"policy": "own_full_burst", "lead": 0.5},
        # 명시 시퀀스 — 정책과 병행 가능
        "sequence": [
            {"t": 45.0, "action": "cover", "duration": 1.5},
            {"t": 60.0, "action": "hold",  "until": 70.0},
        ],
    },
}
```

| 키 | 기본값 | 의미 |
|---|---|---|
| `tap_fire.rate` | — (필수) | 목표 초당 발사 횟수. 3.0(미숙련) ~ 4.2(숙련 상한) |
| `tap_fire.release` | `0.03` | 떼는 시간(초). 컨 실력 축 — 0.02 이론상한 / 0.03 숙련 / 0.04 보통 |
| `tap_fire.full_charge_interval` | `0` (안 씀) | 톡톡이 중 이 간격(초)마다 한 발은 풀차지로 쏜다. `풀 차지 공격 시` 버프 유지용 — [§풀차지 섞기](#풀차지-섞기--tap_firefull_charge_interval) |
| `reload.policy` | — (필수) | `"before_fb_end"` 또는 `"into_fb"` |
| `reload.lead` | `0.3` | (A) 풀버스트 종료 몇 초 전에 엄폐를 시작할지 |
| `reload.margin` | `0.1` | (B) 풀버스트 시작 후 몇 초 뒤에 재장전이 끝나게 할지 |
| `reload.duration` | `None` | 엄폐 지속 시간(초). `None`이면 **재장전이 끝나는 순간까지만** 엄폐 |
| `cover.policy` | — (필수) | 현재 `"own_full_burst"` 하나 |
| `cover.extend` | `0.0` | 풀버스트가 끝난 뒤에도 몇 초 더 엄폐할지 |
| `hold.policy` | — (필수) | `"own_full_burst"` 또는 `"charge_hold_after_fb"`. 차지형 전용 |
| `hold.lead` | `0.5` | `own_full_burst`: 풀버스트 종료 몇 초 **전**에 들고 있던 풀차지를 뗄지.<br>`charge_hold_after_fb`: 풀버스트 종료 몇 초 **후**에 `charge_hold:N` 판정을 놓을지 (권장 0.1) |
| `sequence` | `[]` | 명시 조작 시퀀스. [§명시 시퀀스](#명시-시퀀스) 참조 |

`tap_fire`는 `fire_mode == "charge"`(SR/RL)가 아닌 캐릭터에 주면 무시된다.
`tap_fire.rate`는 곧 "사격 후 딜레이 0.16초를 얼마나 지웠나"다 — §톡톡이 참조.

`reload.duration`을 재장전 시간보다 길게 주면 그만큼 사격이 더 멈춘다. 짧게 주더라도
**재장전이 중간에 끊기지는 않는다** — 엄폐에서 나와도 재장전은 그대로 굴러간다.

`reload`와 `cover`는 같은 원시타입(엄폐)을 쓰는 서로 다른 정책이다. 둘 다 켜면 구간이
겹치는 만큼 **버스트 엄폐컨이 먼저** 걸리고(구간이 훨씬 길다), 장전컨이 노리던 재장전은
그 구간 안에서 어차피 따라온다.

### 캐릭터별 기본 컨트롤 — `data/char_defaults.json`

니케마다 최적 전략이 다르다. 이 파일이 캐릭터별 기본 레이어를 담는다 (컨트롤뿐 아니라
장비 옵션·버스트 패턴 차이분도 같이 — 스펙 운용의 정본은 `HARNESS.md §기본 스펙`).
**여기 없는 캐릭터는 자동(컨트롤 없음)이다.**

| 캐릭터 | 기본 컨트롤 | 조건 |
|---|---|---|
| 앨리스 | 톡톡이 3.6 | 없음 — 언제나 |
| 아인 | 톡톡이 3.6 | 없음 — 언제나 |
| 밀크 : 블루밍 바니 | 톡톡이 3.6 + 풀차지 5.5s + 홀드 `charge_hold_after_fb` | 없음 — 언제나 |
| 에이다 | 홀드 `own_full_burst` (lead 0.5) | **미란다와 함께일 때만** |
| 미하라 : 본딩 체인 | 엄폐 `own_full_burst` | **미란다와 함께일 때만** |
| 아인 | 홀드 `own_full_burst` (lead 0.5) — 톡톡이 위에 얹는다 | **에이다와 함께일 때만** |

#### 조합 조건부 기본 컨트롤 — `_control_rules`

컨트롤이 조합에 달린 경우가 있다. 위 셋은 미란다 `웨이크업! 4`(크리확률·**1발 유지**)를
아끼는 운용이라 **미란다가 없으면 아낄 게 없다.** 그래서 조건부로 적는다.

```jsonc
"에이다": {
  "_control_rules": [
    { "when": { "with_member": ["미란다"] },
      "control": { "hold": { "policy": "own_full_burst", "lead": 0.5 } } }
  ]
}
```

- 조건 어휘는 버스트 패턴과 같다 (`spec._when_ok` — `HARNESS.md §2층`의 조건 키 표).
- **맞는 규칙 전부**가 순서대로 `control`에 병합된다. 버스트 패턴은 값이 하나라 먼저 맞는
  규칙이 이기지만, 컨트롤은 톡톡이+홀드처럼 겹쳐 쓰는 게 정상이기 때문이다
  (아인 = 항상 톡톡이 + 에이다와 함께면 홀드).
- 붙은 규칙은 캐릭터 dict에 그대로 남아 **이탈 보고에 `(레이어)`로 잡힌다.**
- 판정은 `spec.char_layer(name, members)`가 스쿼드를 조립할 때 한다 — `members`를 모르면
  (`build_char`를 이름만으로 부르면) 조건부 레이어는 붙지 않는다.

**`timeline.py`는 이 파일을 읽지 않는다.** `simulate()`는 넘겨받은 `char["control"]`만 본다 —
기본값이 시뮬 결과를 소리 없이 바꾸면 안 되기 때문이다. 레이어를 얹는 건 러너 쪽이며
(`context/spec.py`), 회귀 하네스·단발 CLI·보고서가 전부 그걸 거친다. 즉 **위 셋은 어디서
돌리든 컨트롤이 켜진 채로 계산된다.** 컨트롤 없는 대조군은 `context/sim.py --auto`.

## 톡톡이

### 게임 메커니즘

차지 무기는 누르고 있는 동안 차지되고 떼면 발사된다. 끝까지 차지하지 않고 **짧게 눌렀다 떼기를
반복**하면 발당 대미지는 낮지만(차지 배율 미적용) 발사 횟수가 크게 늘어난다.

게임이 강제하는 하한이 두 개 있다:

| 값 | 의미 |
|---|---|
| 200ms | 최소 조준 시간 — 이보다 짧게 누르면 발사되지 않는다 |
| 20ms | 샷당 최소 딜레이 — 떼는 데 최소로 필요한 시간 |

따라서 한 발의 이론 최소 주기는 **220ms(≈4.5발/s)**. 다만 20ms만 떼는 건 인체공학적으로
매우 어렵다. 떼는 시간이 실력을 결정하는 축이고, 40ms 미만이 꾸준히 나오려면 연습이 필요하다.

10초에 N발을 쏘려면 사이클 주기는 `10/(N-1)`초(첫 발은 미리 차징해 즉발이라 가정). 여기서
필요한 하드웨어 하한 220ms를 빼면 허용 오차가 나온다:

| 목표 | 사이클 주기 | 허용 오차 | 떼기 30ms일 때 실질 판정 |
|---|---|---|---|
| 42톡톡이 | 244ms | 24ms | 14ms — 매우 어려움 |
| 40톡톡이 | 256ms | 36ms | 26ms |
| 36톡톡이 | 286ms | 66ms | 56ms |
| 32톡톡이 | 323ms | 103ms | 93ms |

박자감·피지컬이 준수한 사람의 실질 상한은 **39~40톡톡이(약 3.9~4.0발/s)**.

출처: 커뮤니티 글 (유저 제공). 실측 검증 안 됨 — `DATA_VERIFY.md` 참조.

### fire delay는 두 조각이다 (유저 확인)

`weapon_delays.json`의 `post_fire_delay`(SR/RL 0.38초)는 **하나의 딜레이가 아니라 둘의 합**이다.

| 조각 | 값 | 컨트롤로 지울 수 있나 |
|---|---|---|
| 사격 전 딜레이 | 0.22초 | **불가** — 이 구간이 곧 누름(조준) 구간이다 |
| 사격 후 딜레이 | 0.16초 | **가능** — 톡톡이가 지우는 대상 |
| 합계 | 0.38초 | 컨트롤 없이 쏠 때의 발사 간 딜레이 |

사격 전 0.22초가 누름 구간 그 자체라는 점이 커뮤니티 수치와 맞아떨어진다 —
사격 후 딜레이를 완전히 지우면 주기가 `0.22 + 떼기`가 되어 떼기 30ms에서 **4.0발/s**,
20ms에서 4.2발/s다. 39~42톡톡이가 여기서 나온다.

**얼마나 지우느냐가 실력 요소다.** 다만 별도 파라미터를 두지 않고 `rate`(초당 발사)
하나로 표현한다 — rate가 낮다는 건 곧 사격 후 딜레이를 덜 지웠다는 뜻이기 때문이다.

| 목표 rate (떼기 30ms) | 누름 | 남은 사격 후 딜레이 | 해석 |
|---|---|---|---|
| 4.0발/s 이상 | 0.22 | 0.00 | 0.16초를 전부 지움 (상한) |
| 3.6발/s | 0.22 | 0.03 | 대부분 지움 |
| 3.0발/s | 0.22 | 0.08 | 절반쯤 지움 |
| 2.44발/s 이하 | 0.22 | 0.16 | 못 지움 = 컨트롤 안 한 것과 동일 |
| 1.0발/s | 0.81 | 0.16 | 여유가 남아 누름을 길게 잡은 것 (느린 톡톡이) |

> **일반 발사(컨트롤 없음)는 종전대로 `차지 시간 + 0.38초`다.** 0.22초를 차지 시간과
> 겹치는 것으로 볼지(= `max(0.22, 차지) + 0.16`)는 확인되지 않았고, 바꾸면 컨트롤과
> 무관한 기존 차지형 전원의 결과가 움직인다. 확인 전까지는 건드리지 않는다.

### 계산기 모델

발수를 그냥 고정하지 않고 **누름/뗌 시간**으로 모델링한다. 이렇게 하면 차지속도 버프로
차지 시간이 짧아진 경우가 별도 옵션 없이 자동으로 처리된다.

```
목표 주기를 [사격 전 딜레이 + 차지 + 떼기 + 남은 사격 후 딜레이]로 분해한다:

slack  = max(0, 1/rate - 0.22 - release)  # 최소 구성(사격 전 0.22 + 떼기) 대비 여유
post   = min(0.16, slack)                 # 여유는 먼저 "덜 지운 사격 후 딜레이"로
charge = max(0, slack - 0.16)             # 그래도 남는 만큼만 실제로 차지된다
hold   = 0.22 + charge                    # 누르고 있는 시간

발사 시점의 유효 차지 시간(charge_time_fixed / charge_speed_pct 반영)과 비교:
    charge >= charge_time_eff  →  풀차지 샷  (full_charge_mult·charge_dmg_pct 적용,
                                              full_charge / full_charge_hit 트리거 발동)
    charge <  charge_time_eff  →  논차지 샷  (차지 배율 1.0, 위 트리거 미발동)

발사 주기 = hold + release + post         # 풀차지로 나갔든 아니든 동일
```

**사격 전 0.22초는 차지에 들어가지 않는다.** 그래서 완벽한 0.22 간격 톡톡이는 차지가 0초이고
**차지 배율이 언제나 100%**다 (유저 확인). 톡톡이로 풀차지를 내려면 유효 차지 시간이
0초 근처까지 내려가 있어야 한다 — 아래 §앨리스 참조.

- **톡톡이는 사격 후 딜레이(0.16초)를 지우는 컨트롤이다.** 사격 전 0.22초는 누름 구간
  그 자체라 지울 수 없다. `rate`가 곧 "얼마나 지웠나"를 나타낸다 (위 표 참조).
- `rate`가 상한 `1/(0.22+release)`를 넘으면 실효 rate가 그 상한에 걸린다
  (떼기 30ms → 4.0발/s, 20ms → 4.2발/s).
- 논차지 샷은 `is_full_charge=False`로 `calc_damage()`에 들어간다 — ④ 차지 배율이 1.0이 되고
  `charge_dmg_pct`(차지 대미지 증가)도 곱해지지 않는다.
- 탄약 소모·재장전·`squad_ammo_consume`/`on_attack`/`hit_count`/코어히트 판정은 일반 차지와 동일.

### 손익

**톡톡이는 무조건 이득이 아니다.** 초당 대미지를 `발사 횟수 × 발당 배율`로 놓고 비교하면
갈리는 지점이 보인다 (톡톡이 4.0발/s · 떼기 30ms · 배율 350% 기준):

| 유효 차지 시간 | 홀드(컨트롤 없음) | 톡톡이 4.0발/s | 승 |
|---|---|---|---|
| 1.50초 (버프 없음) | `1/(1.5+0.38)` = 0.53발/s × 350% = **1.86** | 4.0발/s × 100% = **4.00** | 톡톡이 |
| 0.12초 (차지속도 92%) | `1/(0.12+0.38)` = 2.0발/s × 350% = **7.00** | 4.0발/s × 100% = **4.00** | 홀드 |
| **0초 (차지속도 100%)** | `1/(0+0.38)` = 2.6발/s × 350% = **9.21** | 4.0발/s × **350%** = **14.00** | 톡톡이 |

- 차지가 길면 → 톡톡이(논차지 연발)가 이긴다.
- 차지속도 버프가 **어중간하게** 걸리면 → 홀드가 이긴다. 톡톡이는 여전히 논차지인데
  홀드 쪽만 빨라지기 때문이다.
- 차지속도가 **100%에 도달하면** → 톡톡이가 압도한다. 차지가 0초라 톡톡이 한 발 한 발이
  풀차지로 나가고, 배율을 유지한 채 발사 횟수만 늘어난다. **이 지점을 맞추는 게 공략이다.**

**재장전을 하는 조합에서는 또 달라진다** — 탄 소모가 3~5배 빨라져 재장전 빈도가 올라간다.
논차지 구간에서는 `full_charge_hit` 트리거로 걸리는 자·타 버프도 죽는다.
개별 조합의 손익은 시뮬로 확인한다.

### 두 번째 축 — 탄

위 표는 "쏘는 동안"의 비교다. 실전에서 톡톡이의 손익을 가르는 나머지 절반은 **재장전으로
멈춰 있는 시간**이다. 발사 횟수를 3~5배로 늘린다는 건 탄창을 3~5배 빨리 비운다는 뜻이라,
같은 컨트롤이 조합에 따라 이득도 손해도 된다. 판정 순서는 이렇다.

| 조합이 주는 것 | 결과 |
|---|---|
| **재장전 속도 버프 합 100% 초과** | 재장전이 사실상 즉시 끝나 **무한 탄창**이 된다. 톡톡이가 무조건 이긴다 |
| **최대 장탄 버프** (재장전 버프는 없음) | 한 탄창으로 버티는 시간이 늘어 재장전 횟수가 덜 는다. 이득 |
| **둘 다 없음** | 늘어난 재장전 빈도가 이득을 깎는다. 시뮬로 확인해야 한다 |

예 — 재장전 속도: 크라운 `원 포 올 2`(15초, 아군 전체) + 프리바티 `EX 매거진 2`(10초)가
겹치면 100%를 넘어 자동 재장전이 끝나는 즉시 채워진다.
장탄: 리타 `리타 부스트 4`(최대 장탄 %, 5초) · 그레이브 `라이터즈 스포일러 7`(최대 장탄 고정값, 10초).

**차지 축과 탄 축은 곱해진다.** 차지속도가 100%에 못 미치면 톡톡이 한 발 한 발이 논차지라
탄 축이 아무리 좋아도 배율 손실을 메우지 못한다 — 아래 §앨리스가 그 경계 사례다.

### 적용 대상

차지형(SR/RL) 전원이 물리적으로 가능하다. 실제로 이득인지는 캐릭터마다 다르다.

| 캐릭터 | 비고 |
|---|---|
| 앨리스 | 대표 케이스. 조합 무관. **차지속도 장비 옵션 2줄이 전제** (아래) |
| 밀크 : 블루밍 바니 | 톡톡이 기본 + **주기적 풀차지 1발**(아래 §풀차지 섞기) + 부끄러움 홀드컨. 표준 테스트 스쿼드 seed 42에서 382.8M → 482.1M (**+25.9%**) |

#### 풀차지 섞기 — `tap_fire.full_charge_interval`

**논차지 샷은 `full_charge_hit`를 발동시키지 않는다.** 그래서 `풀 차지 공격 시` 버프를 가진
캐릭터에 톡톡이만 켜면 그 버프가 통째로 죽는다. 실제 조작은 톡톡이를 치다가 버프가 끊기기
전에 풀차지 한 발을 섞는 것이다.

`full_charge_interval: N` — 마지막 풀차지로부터 N초가 지났으면 **그 발만 풀차지로** 쏜다.
차지 시작 시점에 결정하므로 톡톡이 리듬을 흐트러뜨리지 않는다.

밀크 : 블루밍 바니는 `관통 특화`가 6초라 **5.5**가 기준값이다. 이 버프가 켜져 있어야
`관통 대미지 ▲`(스킬2 64.7% / 버스트 117.64%)가 딜에 실린다.

> 유저 실전 패턴은 이보다 정교하다 — "본인 버스트는 6초쯤 남았을 때 풀차지 한 번, 부끄러움이
> 끝난 뒤 풀차지 한 번 후 4초 톡톡이, 다시 풀차지". 구간별로 시점을 지정하는 표현은 아직
> 없고, 고정 간격이 그 근사다.

#### 앨리스 — 차지속도 100% 맞추기

앨리스는 버스트 중 자체 차지속도가 **91.82%**다 (`신기하고 이상한 나라` 80.15 +
`힘나는 당근` 11.67). 여기에 **차지속도 장비 옵션 2줄 = 8.18%**를 얹어 정확히 100%를 만드는 것이
공략이다 (유저 확인). 차지 시간이 0초가 되어 톡톡이 한 발 한 발이 풀차지로 나간다.

**이 옵션 2줄(유저 표현 "2차속")은 선택이 아니라 전제다** (유저 확인). 앨리스 톡톡이를
논할 때는 깔고 들어가고, 위 §두 번째 축의 탄 조건은 그 위에서만 의미를 갖는다.

측정 (아니스:스타·앵커:이노센트·마스트:로망틱·앨리스·브래디, 180초 seed 42, 앨리스 딜):

| 차지속도 장비 옵션 | 컨트롤 없음 | 톡톡이 3.0 | 톡톡이 3.6 | 톡톡이 4.0 |
|---|---|---|---|---|
| 0% | 331M | −44.0% | −35.3% | −28.4% |
| **8.18%** | 408M | +9.5% | +26.0% | **+41.4%** |

**차지속도 옵션이 없으면 톡톡이가 손해다.** 이 스쿼드는 풀버스트 가동률이 80%라
버스트 구간(차지 0.12초 → 홀드 우세)이 전투를 지배하기 때문이다. 옵션 2줄로 차지가
0초가 되는 순간 뒤집힌다.

## 장전컨

### 게임 메커니즘

니케는 공격하지 않으면 자동으로 재장전한다. **엄폐(shift 비활성화) 중에는 재장전을 한다.**
탄이 남았는데도 일부러 엄폐해 재장전 시간을 유리한 구간에 밀어 넣는 컨트롤이다.

> 재장전은 **엄폐로 유도되는 결과**이지 직접 거는 조작이 아니다. 계산기도 그렇게 모델링한다 —
> 정책은 엄폐 구간을 열고, 재장전은 그 구간에서 따라온다. 탄이 이미 만렙이면 **엄폐만 하고
> 재장전은 걸리지 않는다**(사격만 멈춘다).

두 패턴이 있다.

**정책 A — 버스트 만료 전 재장전 (`before_fb_end`)**

재장전 시간을 0초로 만드는 조합(크라운+프리바티, 마스트+앵커 + 재장큐브 등)은 보통
**풀버스트 동안만** 재장 0초다. 비버스트에 재장전이 걸릴 것 같으면 풀버스트가 끝나기 전에
미리 재장전해 둔다 — 공짜로 탄창을 채우고 비버스트를 통째로 사격에 쓴다.

무한 장탄 조합이 아니어도 재장전 속도 버프가 풀버스트에 몰려 있으면 같은 전략이 성립한다.

**정책 B — 버스트 시작에 맞춰 재장전 완료 (`into_fb`)**

풀버스트 시작 시점에 **최대 장탄이 늘어나는** 캐릭터(드레이크 등)가 있는 조합에서 쓴다.
비버스트가 끝나갈 때 재장전을 시작해 풀버스트 시작 직후에 완료시키면, **늘어난 최대 장탄으로**
탄창이 채워지고 풀버스트 내내 재장전 없이 사격할 수 있다.

> 재장전 완료가 풀버스트 시작보다 **빠르면 안 된다** — 최대 장탄 증가 버프가 붙기 전에
> 채워져 증가분을 놓친다. 그래서 목표는 "시작 시점"이 아니라 "시작 직후"다.

**버프 구간이 짧을수록 이 정책이 중요해진다.** 노리는 것이 장탄 증가만이 아니라 **그 구간을
한 발도 쉬지 않고 쓰는 것**이기 때문이다. 리타처럼 공격력 버프가 5초짜리면(`리타 부스트 6`·
`더블 부스트`, 최대 장탄 `리타 부스트 4`도 같은 5초) 그 안에서 재장전이 한 번 걸리는 순간
버프 구간의 상당 부분이 날아간다. 시작에 맞춰 채워 두면 늘어난 장탄을 들고 5초를 통째로 쓴다.

> `margin`(완료가 풀버스트 시작 후 몇 초 뒤인가)은 **초 단위 절대값**이라 조합마다 다시
> 잡아야 한다. "시작 시점에 N% 진행"으로 생각한다면 `margin = (1-N) × 그 조합에서의 실제
> 재장전 시간`이다 — 기본 재장전 시간이 아니라 재장 큐브·버프가 반영된 실측값을 쓴다.

### 계산기 모델

정책은 **엄폐 구간을 여는 생산자**다. 아래 조건이 맞으면 `_enter_cover()`를 부르고,
재장전·사격 정지·`event:cover`는 실행층이 처리한다.

**정책 A** — 예측이 필요 없다. 풀버스트에 진입하는 순간 종료 시각이 확정되므로
(`fullburst_duration` 버프 합산까지 반영된 값), 그 시각을 기준으로 뒤에서 센다.

```
풀버스트 중이고  t >= full_burst_end_t - lead  이고  ammo < 최대장탄  →  엄폐 진입
사이클당 1회
```

**정책 B** — 다음 풀버스트 시작을 예측해야 한다. 버스트 상태머신은 반응형(게이지·쿨이
충족되면 진입)이라 미래 시각이 확정돼 있지 않다. **직전 사이클 주기를 관측해 예측한다** —
실제 플레이어가 박자로 맞추는 방식과 같다.

```
관측 주기      = 이번 풀버스트 시작 - 직전 풀버스트 시작
예측 시작      = 이번 풀버스트 시작 + 관측 주기
엄폐 진입      = 예측 시작 - (현재 재장전 시간 - margin)
              →  재장전 완료가 예측 시작 + margin 근처가 된다
사이클당 1회. 첫 사이클은 관측치가 없어 동작하지 않는다
```

두 정책 공통:

- `ammo`가 이미 최대면 걸지 않는다. 재장전 중·재장전 후 딜레이 중이면 걸지 않는다.
- `weapon_change` 모드 중에는 걸지 않는다 (모드 탄창 로직을 흔든다).
- 차지 중이면 차지를 끊고 엄폐한다 (실제 조작과 동일). 들고 있던 홀드도 함께 취소된다.
- 이미 엄폐 중이면 다시 걸지 않는다.
- 로그에는 **엄폐와 재장전이 따로** 남는다 — `엄폐 시작(장전컨)` + `재장전 시작` + `재장전 완료`.
  탄이 만렙이라 재장전이 안 걸린 엄폐도 로그에 보이게 하기 위해서다.

### 적용 조합

| 조합 | 컨트롤 대상 | 정책 | 비고 |
|---|---|---|---|
| 리틀 머메이드·크라운·라피:레드 후드·신데렐라:크리스탈 웨이브·프리바티 | MG 니케들 | A | 같은 시간에 재장전할 필요가 없다 (한 명씩 돌아가며) |
| 아니스:스타·마스트:로망틱 메이드·앵커:이노센트 메이드·홍련:흑영·리버렐리오 | 리버렐리오 | B | 버스트 시작 3초 동안 재장전하지 않는 것이 매우 중요 |
| 토브·아르카나·도로시:세렌디피티·드레이크·솔린:프로스트 티켓 | 도로시:세렌디피티 | B | 드레이크의 풀버스트 장탄 증가를 받는다. 장탄 옵션 필요 |

**장탄이 적은 캐릭터일수록 손해가 크다.** 강제 재장전은 탄창을 다 비우지 않고 채우므로
전투 전체의 재장전 횟수가 늘어난다. 300발 MG는 이 비용이 거의 없지만, 6발 SR/RL은
사이클당 재장전이 한 번씩 더 늘어 이득을 넘어설 수 있다 (`재장전 횟수`를 로그로 확인할 것).

**`reload_time_fixed`를 쓰는 캐릭터는 대상에서 빼라.** 신데렐라:크리스탈 웨이브의
`변경 준비`는 재장전 시간을 3초로 **고정**해 재장전 속도 버프를 무시한다 — 풀버스트 안이라도
강제 재장전이 3초를 통째로 먹는다. 저격 모드를 쓰는 경우(`weapon_mode_swap`)에는
무기 변경 중 장전컨이 걸리지 않으므로 자동으로 무시된다.

## 버스트 엄폐컨

### 게임 메커니즘

**발수로 소모되는 버프(`duration_bullets`)를 일반 공격에 쓰지 않고 아껴, 스킬 대미지 구간까지
끌고 가는 컨트롤이다.** 한 발이라도 쏘면 버프가 사라지므로, 그 발을 쏘지 않는 유일한 방법은
엄폐다. 장전컨과 원시타입은 같지만 **목적이 정반대**다 — 장전컨은 재장전을 밀어 넣으려고
엄폐하고, 이쪽은 아무것도 하지 않으려고 엄폐한다. 재장전은 여기서 부산물이다.

성립 조건이 까다롭다:

1. 아낄 버프가 **시간 만료가 없어야** 한다. 시간 지속이 붙어 있으면 엄폐하는 동안 그냥 만료된다.
2. 그 버프가 붙는 동안 **일반 공격 없이도 나가는 대미지**가 커야 한다 (버스트 스킬 대미지·DoT).
3. 멈춘 일반 공격의 손실을 그 이득이 넘어야 한다.

### 계산기 모델

정책 `own_full_burst` — 정책 A와 마찬가지로 예측이 필요 없다. 풀버스트에 진입하는 순간
종료 시각이 확정되므로(`full_burst_end_t`) 그 시각까지의 길이를 그대로 구간으로 연다.

```
풀버스트 중이고  본인이 이번 사이클에 버스트를 썼으면(burst_casted)  →  엄폐 진입
지속 = full_burst_end_t - 현재 시각 + extend
사이클당 1회 (앵커 = full_burst_end_t)
```

- **탄약 상태를 보지 않는다.** 목적이 재장전이 아니라 "쏘지 않는 것"이기 때문이다.
  재장전 중이어도 엄폐에 들어간다 — 어차피 쏘지 못하는데 자세만 다른 상태다.
- 본인이 버스트를 쓰지 않은 사이클에는 걸리지 않는다. 그 사이클엔 평소대로 사격한다
  (스택·게이지를 쌓아야 하는 캐릭터가 대상이라 이 구분이 중요하다).
- MG처럼 장탄이 큰 캐릭터는 엄폐 중 재장전이 끝나 **만탄으로 나온다** — 사이클당 재장전
  횟수가 오히려 줄어든다(미하라 실측 18회 → 14회).

> **명시 시퀀스로 흉내 내지 마라.** 사격을 멈추면 버스트 게이지 충전이 느려져 **사이클
> 시각 자체가 밀린다.** 시퀀스의 절대 시각은 컨트롤 없는 사이클에 맞춰 적은 것이라
> 뒤 사이클에서 어긋난다(실측 180초 끝에서 0.65초 밀림). 정책은 구조적으로 어긋나지 않는다.

#### 미란다 + 미하라 — 확정 크리 버스트

미란다 `웨이크업! 4`는 풀버스트 시작 시 **자신을 제외한 최종 공격력 1위 아군**에게
크리티컬 확률 +85.42%(10렙)를 주고, **시간 지속이 없다 — `1발 유지`가 전부**다.
그래서 쏘지 않으면 계속 남는다.

미하라는 본인 버스트에 `사슬 당기기`(10초 DoT)와 full_burst_end의 `바디 컨텍 3`(게이지 수만큼
타격)로 대미지 대부분을 스킬로 낸다. 풀버스트 10초를 통째로 엄폐하면 그 스킬 대미지가 전부
크리로 들어간다. 대신 **스택은 쌓아야 하므로**, 미하라가 버스트를 쓰지 않는 다른 B3 사이클에는
평소대로 사격한다 — 정책이 `burst_casted`로 이 구분을 한다.

**전제: 미하라가 미란다를 제외한 공격력 1위여야 한다.** 대표 조합에서 기본값으로는 헬름이
1위라 버프가 헬름에게 가고, 이때 엄폐는 순손해다. 장비 옵션의 공격력으로 순위를 뒤집는 것이
이 조합의 육성 과제다.

|---|---|---|---|
| 옵션 없음 | 헬름 | 936.8M → 916.3M (**−2.2%**) | −1.3% |
| +30% | **미하라** | 1,114.5M → 1,436.1M (**+28.9%**) | +15.6% |

`사슬 당기기` DoT 크리 적중이 12/61 → 56/61로 바뀐다. 전량이 아닌 이유는 이 계산기가
크리확률을 **독립 확률로 합성**하기 때문이다(`1 - ∏(1-p)`; 기본 15% + 85.42% = 87.6%).
인게임이 가산이라면 100.42%로 확정 크리가 된다 — `CALCULATOR.md`의 합성 규칙 문제이고
이 컨트롤과는 별개다.

## 홀드

### 게임 메커니즘

차지 무기는 풀차지에 도달해도 **떼지 않으면 발사되지 않는다.** 계속 누르고 있다가 원하는
시점에 떼서, 풀차지 한 발을 유리한 버프 구간에 꽂는 조작이다. 톡톡이의 반대 방향이다 —
톡톡이가 누름을 짧게 끊는다면 홀드는 길게 잡는다.

| 컨트롤 | click 구간 | 결과 |
|---|---|---|
| 톡톡이 | 짧게 (차지 미완성) | 논차지 샷, 발사 횟수↑ |
| 없음 | 차지 완료 즉시 뗌 | 풀차지 샷, 자동 |
| 홀드 | 길게 (차지 완료 후 대기) | 풀차지 샷을 **원하는 시점으로 이동** |

> **인게임 확인 필요** — 풀차지를 무한정 유지할 수 있는지, 일정 시간 후 강제 발사되는지
> 확인되지 않았다. 현재는 상한을 두지 않는다.

### 정책과 시퀀스 둘 다 있다

**전투 내내 홀드하는 운용은 없다.** 그래서 오래 시퀀스 액션(`until` 절대 시각)뿐이었지만,
"본인 버스트 동안 들고 있다가 끝나기 직전에 쏜다"는 **반복되는 기본 전략**이라 정책으로 뽑았다.

정책 `own_full_burst` — 본인이 버스트를 쓴 사이클의 풀버스트 종료 `lead`초 전을 떼기 시각으로
잡는다. 앵커는 `full_burst_end_t`라 예측이 필요 없고, 버스트 엄폐컨과 같은 구조다.

```
풀버스트 중이고  본인이 이번 사이클에 버스트를 썼으면(burst_casted)
  →  떼기 시각 = full_burst_end_t - lead
사이클당 1회 (앵커 = full_burst_end_t)
```

정책과 시퀀스가 같은 `_hold_release_t`로 들어가고, **시퀀스가 정책보다 우선한다**
(정책을 먼저 굴리고 시퀀스가 같은 틱에 덮어쓴다).

### 계산기 모델

```
풀차지 도달  →  래치(_charge_full_t)에 도달 시각 기록
             →  지정된 떼기 시각까지 발사하지 않는다
             →  대기 중에도 charging=True (「차지 중」 조건 버프 유지)
             →  탄 소모·재장전 없음
```

- **풀차지 도달은 래치한다.** 홀드 중 차지속도 버프가 빠져도 이미 채운 차지는 풀리지 않는다.
- **발사 시점의 버프로 대미지가 계산된다.** 버스트가 시작된 뒤에 떼면 버스트 버프를 다 받는다 —
  홀드의 이득이 여기서 나온다.
- 엄폐가 들어오면 차지가 취소되고 **홀드 지시도 함께 사라진다** (나중 액션이 이긴다).

### 손익

**홀드는 순수 DPS 손해에서 출발한다.** 대기하는 동안 발사가 없으므로, 버프 구간에 몰아넣은
이득이 그 손실을 넘어야 남는다. 풀버스트 가동률이 높은 조합일수록 손해가 커진다 — 어차피
대부분의 발사가 이미 버스트 안에서 나가기 때문이다.

측정 (아니스:스타·앵커:이노센트·마스트:로망틱·앨리스·브래디, 180초 seed 42, 앨리스 딜):

| | 발수 | 풀버스트 내 발사 | 딜 |
|---|---|---|---|
| 컨트롤 없음 | 191 | 87.4% | 330.7M |
| 20~30s 홀드 | 185 | — | 320.1M (−3.2%) |

이 조합은 이미 가동률이 87%라 홀드로 올릴 여지가 13%뿐인데 비버스트 발사를 통째로 버린다.
**차지가 길고 풀차지 배율이 큰 저가동 캐릭터**가 대상이다.

**정책(`own_full_burst`)은 손익 구조가 다르다.** 버리는 게 "비버스트 발사"가 아니라
"본인 버스트 10초의 일반 공격"이고, 그 대가로 발수 소모형 버프를 그 10초 내내 유지한다.
그 구간의 스킬 대미지가 크면 이긴다.

#### 에이다 — 홀드로 스킬딜과 마지막 한 발을 모두 크리로

에이다 버스트는 `섬광 수류탄 투척`(방무 대미지 420%)의 발동 간격을 2초 → 1초로 줄여
**풀버스트 10초 동안 10회** 터뜨린다. 여기에 `특수 개조`(차지속도 −300% / 차지 대미지 +1500%,
**1발 유지**)로 강한 한 발을 준비한다.

미란다의 크리확률 버프도 1발 유지라, 아무 생각 없이 쏘면 첫 일반 공격에 날아간다.
풀버스트 내내 풀차지를 들고 있으면 **`섬광 수류탄 투척` 10회가 전부 크리**로 들어가고,
종료 0.5초 전에 떼면 **`특수 개조`가 실린 한 발까지 크리**로 꽂힌다.

이 조합은 두 컨트롤이 사이클마다 번갈아 붙는다 — 에이다의 `은밀한 지원`이 **직전에 버스트를
쓴 B3**의 공격력을 올려 주므로, 에이다 버스트 사이클엔 에이다가, 미하라 버스트 사이클엔
미하라가 크리 버프를 받는다(성장이 크게 차이나지 않는 한). **에이다는 홀드, 미하라는 엄폐**다.

| 에이다 홀드 + 미하라 엄폐 | **1,994.1M (+18.3%)** | 624.1M | 1,028.2M (**+36.0%**) |

(사이클당 1발, 전부 크리)로 줄지만 그 7발이 종전 32발과 맞먹는다.

### `charge_hold:N` — 홀드가 곧 스킬 발동인 경우

밀크 : 블루밍 바니가 첫 사용 캐릭터다(`부끄러움`). 트리거는 `_notify_charge_hold()`가
`_charge_full_t`로 유지 시간을 재서 발동시킨다. **판정은 한 차지에 1회**다 — 임계를 넘긴
그 순간뿐이고, 계속 들고 있어도 재판정하지 않는다(유저 확인).

여기서 조작이 갈린다. 밀크의 `부끄러움`은 자기 버스트 중에는 `부끄러움 면역`이라 판정이
헛돈다. 그런데 판정이 1회뿐이므로 **버스트 중에 홀드를 시작하면 버스트가 끝나도 발동하지
않는다.** 유저 조작은 그래서 "버스트가 끝나갈 때 차지를 시작"이다.

정책 `charge_hold_after_fb` — 그 조작을 시각 역산으로 표현한다.

```
판정 시각 = 본인 풀버스트 종료 + lead   (기본 lead = 0.1)
차지 시작 = 판정 시각 − 차지 시간 − 유지 임계(N)
```

- 차지 시작 시각까지 **한 발 사이클(차지 시간 + 0.4초)보다 멀면 평소대로 쏜다.** 실제 조작도
  그때까지는 쏘다가, 마지막 한 발이 어차피 안 들어갈 시점부터 손을 뗀다.
- 홀드는 **의도한 차지가 시작되는 순간에만** 건다. 미리 걸어 두면 그 전에 우연히 완성된
  풀차지를 붙잡아 판정이 면역 구간 안에서 헛돌아 버린다.
- **늦게 시작해도 포기하지 않는다.** 재장전이 겹쳐 예정 시각을 놓치는 일이 흔하므로
  (톡톡이면 1.5초마다 재장전한다) 떼기 시각은 예정 판정 시각이 아니라 **이번 차지 기준**
  (`차지 시작 + 차지 시간 + N`)으로 잡는다. 늦은 만큼 판정도 늦어질 뿐, 면역은 이미 끝나 있다.
  이 처리가 없으면 사이클의 절반 이상에서 판정이 통째로 누락된다(밀크 180초에 7회 → 3회).
- 판정 효과가 강제 재장전을 걸면 **그 풀차지 샷은 취소된다**(밀크 인게임 동작과 동일).
- 임계값 N은 캐릭터 효과에서 자동으로 읽는다(`BuffManager.charge_hold_thresholds`).

밀크 기준 이득 (표준 테스트 스쿼드 180초 seed 42, 밀크 딜):

| 조작 | 딜 |
|---|---|
| 없음 | 382.8M |
| 홀드컨만 | 407.7M (+6.5%) |
| 톡톡이 + 풀차지 5.5초 | 466.9M (+22.0%) |
| **톡톡이 + 풀차지 + 홀드컨** | **482.1M (+25.9%)** |

`부끄러움`의 목적은 **공격력 +118.7%(40초)**이고, 본인 버스트가 그 버프를 지운다 —
그래서 사이클마다 다시 걸어야 한다. 자기 버스트 구간은 버스트 자체 버프(+220%)가 대신한다.

## 명시 시퀀스

정책은 기본 전략일 뿐이다. 실전에는 더 복잡한 조작이 가능하므로, 정책으로 표현되지 않는
시퀀스는 **시각을 직접 찍어** 넣는다. 정책과 같은 실행층으로 들어가므로 표현력 차이가 없다.

```python
"control": {
    "sequence": [
        {"t": 45.0, "action": "cover", "duration": 1.5},   # 45.0s에 1.5초 엄폐
        {"t": 60.0, "action": "hold",  "until": 70.0},     # 다음 풀차지를 70.0s까지 홀드
    ],
}
```

| 액션 | 키 | 의미 |
|---|---|---|
| `cover` | `duration` | 엄폐 지속 시간(초). 없으면 재장전이 끝날 때까지 |
| `hold` | `until` | 떼는 **절대 시각**(초). 없으면 홀드하지 않는다 (기준과 동일) |

- `t` 오름차순으로 처리된다. 정렬은 계산기가 한다.
- **명시 시퀀스가 정책보다 우선한다** — 유저가 시각을 콕 집은 것이기 때문이다.
- 정책과 병행할 수 있다. 시퀀스가 엄폐를 열어 둔 동안 정책은 새 엄폐를 열지 않는다.
- `hold.until`은 절대 시각이라 **릴리즈가 오지 않아 영원히 안 쏘는 폭주가 구조적으로 없다.**

> 시각이 절대값이라 **버스트 사이클이 스쿼드마다 다르다는 점에 주의**한다. 조합을 바꿔가며
> 비교하는 용도에는 정책이 맞고, 시퀀스는 특정 상황 재현·디버그에 쓴다.

## 미구현·보류

| 항목 | 상태 |
|---|---|
| 동시 컨트롤 1명 제약 | 검사하지 않음. 여러 캐릭터에 동시에 켜면 비현실적 상한이 된다. 다만 조작이 구간이 되면서 **겹침 검사 자체는 가능해졌다** — 필요해지면 구간 교차로 잡으면 된다 |
| 컨트롤 실패율 | 모델링하지 않음. `rate`·`release`를 낮춰 표현한다 |
| 톡톡이 구간별 켜고 끄기 | 없음. 톡톡이는 전투 내내 켜진다 — "비버스트에만 톡톡이"를 정책으로 표현할 수 없다. 엄폐·홀드는 시퀀스로 구간을 찍을 수 있으나 톡톡이는 아직 `click` 구간 생산자로 옮기지 않았다 |
| 정책 B 첫 사이클 | 관측치가 없어 동작하지 않음 (게이지 기반 예측 폴백 미구현) |
| 엄폐컨 헛발 경고 | 아끼려는 `duration_bullets` 버프가 본인에게 오지 않았는데도 정책이 그대로 엄폐한다(딜만 깎인다). 그 버프의 타겟은 첫 조회 때 결정되는 지연 resolve라, 진입 시점에 미리 들여다보면 결정 시점을 앞당겨 버린다 — 그래서 검사하지 않고 시나리오 체크리스트로 돌린다 |
| 풀차지 유지 상한 | 인게임 미확인. 현재 상한 없음 — §홀드 참조 |
| 구간별 풀차지 시점 지정 | `tap_fire.full_charge_interval`은 **고정 간격**이다. 유저 실전 패턴("본인 버스트 6초 남았을 때 / 부끄러움 종료 직후 / 그 뒤 4초 톡톡이")처럼 사이클 이벤트에 시점을 붙이는 표현은 없다 — §풀차지 섞기 |
