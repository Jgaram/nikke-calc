# 사이트 UX — SPA 불편 제거 계획 (URL 라우팅·상태 복원)

작성 2026-08-26. **계획만 — 착수는 사용자 지시로.** 배경: 사용자가 SPA 방식이 불편하다고 밝힘
(첫 로딩·뒤로가기·새로고침 시 상태 유실·URL이 화면을 안 담음). 전면 MPA/SSR 전환은 하지 않기로 —
덱 짜기는 상태 편집기라 화면 유지가 맞고, 정본이 방문자 localStorage라(프라이버시 설계) 서버 렌더의
이득이 안 나오며, `app.js` 4,510줄 재작성급 공사다. 대신 **불편 지점만** 고친다.

## 할 일 (우선순위 순)

1. **URL 라우팅(히스토리 API)** — 탭·화면(덱/결과/기록/공유 열람/설정 등)을 진짜 URL로.
   뒤로가기·앞으로가기가 화면 전환이 되고, 새로고침해도 보던 화면이 뜬다. 서버는 이미
   «API·확장자 없는 경로 → index.html» 폴백이라(`web/srv` 정적 서빙) 서버 쪽 작업은 없다시피 하다.
   규모: 며칠 (app.js의 탭 전환부에 라우터 한 겹).
2. **상태를 URL 쿼리에** — 보던 필터·정렬·선택 덱 인덱스 같은 가벼운 상태를 쿼리로 실어
   새로고침·공유에서 살아나게. 공유 링크(`/s?c=…`)와 같은 결이다. 무엇을 싣고 무엇을
   localStorage에 둘지 목록부터 정한다(프로필·육성 스펙은 절대 URL에 안 싣는다 — PRIVACY).
3. **새로고침 복원 마감** — 스크롤 위치·펼침 상태 등 1·2로 안 잡히는 잔여를 sessionStorage로.
4. **정적인 화면은 별도 페이지 유지·확대** — 로스터는 이미 `roster.html`로 분리돼 있다. 도움말·
   공지처럼 상태 없는 화면이 늘면 같은 방식으로.
5. (선택) **서버 렌더 섬** — 본체가 Hono(TS)가 됐으므로 새 화면은 서버 렌더(JSX)로 시작하는
   하이브리드도 가능. 기존 화면을 옮기는 건 아니고, 새 것부터 검토.

## 주의

- 라우팅을 넣어도 **기존 URL·공유 링크(`/s?c=…`)는 그대로 살아야 한다.**
- 서버 계약(SERVER-CONTRACT.md)의 «확장자 없는 경로 → index.html + 방문 집계» 규칙과 어긋나지
  않게 — 새 경로가 생기면 집계 규칙이 그 경로도 문서 방문으로 센다(지금 규칙 그대로 동작).
- i18n: 화면 이름이 URL에 드러나면 경로는 언어 중립(영문 슬러그)으로.
