변환 이후는 `profile_convert.py`, 절차·gate는 `.agent/skills/profile-sync/SKILL.md`.

## 결론부터

**익명 조회는 불가능하다.** 로그아웃 상태에서 프로필 페이지를 열면 커뮤니티 프로필(닉네임·
팔로워·게시글)만 렌더되고 니케 관련 요청은 **한 건도 발생하지 않는다.**

**로그인한 사람은 남의 공개 프로필도 읽을 수 있다.** 실측에서 로그인 계정(`…741736`)으로
다른 계정(`…941757`)의 니케 199종을 전부 받았다. 즉 "공개 계정"은 *로그인한 사람에게*
공개라는 뜻이고, 비공개 계정은 누구도 못 읽는다.

그래서 수집 경로는 셋이고, 셋 다 **로그인 세션이 필요하다.**

| 경로 | 누구 세션 | 대상 | 어디서 |
|---|---|---|---|
| `profile_fetch.py` (CLI) | `scraper/.session_cookie` | 본인 + 타인(`--openid`) | 로컬 |
| 북마클릿 (`bookmarklet.js`) | 방문자 자기 세션 | **본인만** | 방문자 브라우저 |
| 서버 (`server.py` `/api/fetch`) | 운영자 세션 | 타인 공개 프로필 | 서버 |

북마클릿을 본인 전용으로 고정한 것은 설계 결정이다 — 남의 프로필을 긁는 도구가 되지 않게
하는 가장 확실한 방법이고, 방문자는 애초에 자기 데이터만 필요하다.

## 익명 vs 로그인 (실측)

같은 프로필 URL(`/user?openid=…`)을 두 상태로 열고 네트워크를 전량 기록한 결과.

| 라우트 | 익명 | 로그인 |
|---|---|---|
| `ugc/direct/…/User/GetUserProfile` | `code=0` (커뮤니티 프로필) | `code=0` |
| `ugc/direct/…/User/GetUserPrivacySetting` | `code=0` | `code=0` |
| `ugc/direct/…/User/GetUserGamePlayerInfo` | `103001 MetaData no user account` | `code=0` |
| `game/proxy/Game/GetUserCharacters` | **호출 자체가 없음** | `code=0` · 15.9KB |
| `game/proxy/Game/GetUserProfileOutpostInfo` | 없음 | `code=0` |

직접 호출해 본 것:

| 시도 | 응답 |
|---|---|
| `game/proxy/*` 쿠키 없이 | `300001 game not login` |
| `game/direct/*` 쿠키 없이 | `220000 not permission` |
| CORS preflight (`OPTIONS`, Origin=github.io) | `405`, `Access-Control-Allow-Origin` 헤더 없음 |

**프론트엔드 번들의 라우트 232개를 전수 확인**했다(`assets/v4-*.js`의 접두사 빌더 17종).
익명 접근용 `…ByTourist` 라우트는 **길드카드 3종에만** 있고 캐릭터에는 없다.

> CORS가 없다는 것은 **브라우저에서 우리 오리진으로는 못 부른다**는 뜻일 뿐이다.
> 서버→서버 호출에는 CORS가 적용되지 않으므로 `profile_fetch.py`는 문제없이 돈다.

## openid 체계 — 세 표기를 구분해야 한다

| 표기 | 예 | 쓰는 곳 |
|---|---|---|
| URL 파라미터 (base64) | `MjkwODAtMTAzNDYzMTQ3MTUwMDc5NDE3NTc=` | 프로필 URL `?openid=` · `?uid=` |
| 디코드 결과 | `29080-10346314715007941757` | `ugc/…` 계열의 `intl_openid` |
| 프리픽스 제거 | `10346314715007941757` | **`game/…` 계열의 `intl_open_id`** |

`29080`은 게임 id다. 세 표기를 원시 숫자로 정규화하는 것은 `server.py`의
`openid_from_input()` 하나뿐이며, 북마클릿도 같은 정규화를 한다.

**본인 openid는 쿠키에서 못 읽는다.** `game_openid`를 포함해 `game_*` 쿠키 8종이 전부
`HttpOnly`다(도메인 `.blablalink.com`). 읽을 필요도 없다 — `credentials:"include"`로
자동 전송되고, 값 자체는 아래에서 얻는다.

| 필요한 값 | 어디서 | 파라미터 |
|---|---|---|
| 본인 openid | `ugc/proxy/standalonesite/User/GetUserInfoNew` | 없음 → `data.info.intl_openid` |
| `nikke_area_id` | `game/proxy/Game/GetSavedRoleInfo` | 없음 → `data.role_info.area_id` |

`GetSavedRoleInfo`가 area를 주므로 **후보 탐색이 필요 없다.** `profile_fetch.py`는 여전히
`[83, 81, 84]`(한섭·일섭·글로벌섭)를 훑는데, 그건 타인 조회에서 대상의 area를 모르기
때문이다(본인 조회라면 낭비 요청이 최대 2회 생긴다). 2026-08-23 기준 79·80·86~90은
`1303001 param invalid`로 존재하지 않는 area였고, 85는 파라미터는 유효하나(code 0)
실측 계정 기준 캐릭터 0개라 후보에서 뺐다.

## 데이터 3종

| 라우트 | 파라미터 | 준다 |
|---|---|---|
| `Game/GetUserCharacters` | `intl_open_id`, `nikke_area_id` | `name_code`·`lv`·`grade`(돌파)·`core`(코강)·`combat` |
| `Game/GetUserCharacterDetails` | + `name_codes[]` (60개씩) | 스킬 1/2/3 레벨·장비 4부위(tier·lv·옵션 3)·큐브·소장품/애장품·호감도 + `state_effects` |
| `Game/GetUserProfileOutpostInfo` | `intl_open_id`, `nikke_area_id` | `recycle_room_researches`(콘솔)·`synchro_level`·`synchro_nonempty_slot_count` |

`GetUserCharacterDetails`는 **페이지가 부르지 않는다** — 로스터 화면에 필요 없기 때문이다.
우리가 명시적으로 불러야 장비·오버로드·스킬 레벨이 온다.

## 조회 비용 (실측, 199종 계정)

| 요청 | 시간 | 수신 |
|---|---|---|
| `GetSavedRoleInfo` | 166ms | 311B |
| `GetUserCharacters` | 245ms | 15.9KB |
| `GetUserCharacterDetails` ×4 | 822·482·516·547ms | 87+95+103+43KB |
| `GetUserProfileOutpostInfo` | 166ms | 857B |
| **합계** | **2.9초** | **345KB** |

본인 조회는 openid 확인 1회가 더 붙어 **7~8요청**이다. 니케가 적은 계정은 상세가 1배치라
5요청·8KB·1.1초로 줄었다(실측).

이 수치가 "운영자 세션으로 남들 조회를 대신해도 되는가"의 판단 근거다. 1인 3초면 하루
100명이 700요청 = 시간당 30요청이고, 육성 데이터는 하루 단위로만 바뀌므로 **openid별 캐시**
(`server.py` `fetch_cached()`, 기본 6시간)를 끼우면 부하가 평탄해진다. 그래도 트래픽이
커지면 그만큼 운영자 계정의 요청이 늘어난다는 사실은 남는다 — `--no-fetch`로 끄고
북마클릿만 안내할 수 있다.

## 하지 않는 것

- **비공개 계정을 뚫으려 하지 않는다.** 막힌 것은 의도된 설정이다.
- **익명 우회를 더 찾지 않는다.** 라우트 232개 전수 확인으로 없음을 확인했다. 사이트가
  개편되면 다시 확인할 일이지만, 그때도 결론이 바뀌기 전까지는 로그인 전제로 만든다.
- **북마클릿에 타인 openid 입력을 넣지 않는다.**
- 세션 쿠키를 서버·프로필·로그 어디에도 복사하지 않는다
  (`.agent/skills/profile-sync/SKILL.md §절대 규칙`).
