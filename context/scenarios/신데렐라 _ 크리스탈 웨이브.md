## 모드 전환 메카닉 — 실측으로 확정

`변경 준비`가 게이트, 진입·해제가 동일 조건인 토글이다.

**표준 스쿼드 60초 실측** (`event:full_reload` / `last_bullet_fire` 시점의 변경 준비 활성 여부):

| t | 이벤트 | 변경 준비 활성 |
|---|---|---|
| 8.450 | `last_bullet_fire` | False (최초 탄창) |
| 9.117 | `event:full_reload` | **False** → 전환 없음. 변경 준비 부여(6s) |
| 14.833 | `last_bullet_fire` | **True** → `변경 준비 해제`가 제거 |
| 15.500 | `event:full_reload` | **False** → 전환 없음. 변경 준비 재부여 |
| 21.233 | `last_bullet_fire` | True → 제거 |
| 21.900 | `event:full_reload` | **False** |
| … | 이하 동일 패턴 반복 | |

탄창 소진 주기 ≈ **5.72s**(328발), 재장전 ≈ **0.667s**(풀버스트 재장전 버프 반영). 변경 준비 6s는 `last_bullet_fire`(부여 후 5.72s) 시점까지 **항상 살아 있어 거기서 제거**되고, 그 0.667s 뒤 도착하는 `event:full_reload`에서는 이미 없다.

→ **자연 재장전만으로는 저격 모드 전환이 구조적으로 불가능하다.** 시뮬 180초 동안 전환 0회, `저격 모드`·`디스트로이`·`모드 스왑 2` 전부 무발동. 원본 텍스트 해석과 실측이 일치한다.

전환하려면 탄이 남은 상태의 **수동 재장전**이 필요하다(변경 준비 6초 안에, 재장전 3초 고정 → 여유 있음).

## 스킬 간 상호작용

- **`모드 스왑 2` / `모드 스왑 3`은 무기 모드에 따라 배타적으로 갈린다**
  - 경로: `저격 모드` weapon_change 활성 여부 → `full_burst_start` 시점 `self_state` / `not_self_state` 평가 → 둘 중 하나만 발동
  - 시점: **풀버스트 진입 시 1회 평가**. 그 순간의 모드가 결정적
  - 위험: 전환이 풀버스트 경계 프레임에서 일어나면 딜이 뒤집힌다. 또한 현재 구현에서는 `self_state:저격 모드`가 **영구 거짓**(weapon_change가 `_active` 미등록)이라 `모드 스왑 2`가 도달 불가능하다

- **`핀 포인트`(core_dmg_pct) → `모드 스왑 3`(core_damage) 스케일링**
  - 경로: `핀 포인트`(battle_start, 영구) → `모드 스왑 3` 계산 시 코어 배율에 합산
  - 이게 이 캐릭터 MG 모드 설계의 핵심 — 코어 대미지 버프와 코어 판정 딜이 짝이다. `core_damage`가 코어 배율을 못 태우면 **무기 200% + 핀 포인트 26%가 통째로 빠진다**
  - 대칭으로 `디스트로이`(part_dmg_pct) → `모드 스왑 2`(파츠 포함 딜)가 저격 모드 쪽 짝

- **`유리 구두 풀 컨텍트 W`/` W 2` → `모드 스왑 3` (실행 순서)**
  - 경로: `burst_cast`(t=3.200)에서 atk_dmg 92 / atk 65 부여 → `full_burst_start`(t=3.250)에서 `모드 스왑 3` 계산
  - 실측상 burst_cast가 full_burst_start보다 **0.05s 먼저** 발생 → 버프가 이미 활성인 상태로 계산된다. 순서 역전 시 딜이 크게 떨어짐

- **`변경 준비` 부여와 모드 전환 판정이 같은 `event:full_reload` (실행 순서)**
  - 판정 먼저면: 이전 변경 준비가 살아있을 때만 전환 (텍스트대로 — 수동 재장전 필요)
  - 부여 먼저면: 매 풀리로드마다 전환 (`마지막 탄환 공격 시 제거` 문구가 무의미해짐)
  - → **판정 먼저**로 확정. impl에서 명시적으로 보장할 것

- **`저격 모드 탄 소비 집계`(+40/발) → 아군 `squad_ammo_consume:N` 소비자**
  - 이 카운터는 **CW 본인만의 것이 아니다.** 리틀 머메이드 `거품 난사`(`squad_ammo_consume:500`, `sequential_damage:10`), 일레그 : 붐 앤 쇼크 `고스트 버스터 2`(`squad_ammo_consume:100`, `damage`), 그리고 CW 자신의 `뷰티-풀 3`(200발)이 모두 이 카운터를 읽는다 → **스쿼드 전체 DPS에 직결**
  - 실측(표준 스쿼드 180초): 스쿼드 총 소비 24,030발 → 리틀 머메이드 `거품 난사` 48회 × 10hit = **480 hit / 158.5M**
  - 모드별 CW 기여: MG 9,257발 vs 저격 모드 ≈150발 × 40 = 6,000 카운트 → **저격 모드로 가면 스쿼드 탄 카운터 기여가 오히려 줄어든다**. 저격 모드 평가 시 반드시 함께 볼 것
  - 벨벳은 `gauge_consume_as_ammo`(✅)로 같은 카운터를 올린다 — 선례이자 구현 참고

- **`디스트로이` ↔ `핀 포인트` 상호 배타**
  - 각 부여 clause에 상대의 `remove_named_buff`가 붙어 있다. 해제 누락 시 파츠·코어 대미지 이중 계상 → 네거티브 검증 필수

- **`디코이`는 이 캐릭터에서 하위 소비자가 없다**
  - 원본 신데렐라의 `아름다움`(디코이 조건 스택)에 해당하는 효과 없음. `decoy` stat 자체도 ❌. 본인 스킬 중 `self_state:디코이`를 읽는 것도 없음

## 유저 확인 사항

- Q1: 모드 전환이 수동 재장전에 의존하는데 시뮬에서 어떻게 모델링하나?
  - A: **실전은 MG 고정이 일반적. 단 수동컨으로 모드 전환하기도 함. 둘 다 염두하고 모델링.**

- Q2: 저격 모드 `최대 장탄 15발` vs `풀 차지 공격 시 탄환 소모 40발` 모순 해석?
  - A: **실제로는 1발씩 소모.** "아군이 소비한 탄의 총합"을 따지는 스킬에 대해서만 40발로 집계.
  - → 독립 instant `squad_ammo_consume_add`(fixed_value 40, `full_charge_hit`)로 분리. 기본 MG 모드는 `full_charge_hit`가 없어 자연 게이팅.
  - → **일반 규칙 승격 완료**: GAMEPLAY §무기 메카닉 `탄환 소모 N발` 표기 항목.

- Q3: 파츠(part) 관련 효과를 어떻게 처리하나?
  - A: **파츠 모델이 도입될 예정이고, 파츠 유무를 구분하는 로직이 있을 것.**
  - → `part_dmg_pct` 그대로 파싱. 현재 `is_part=True` 세팅 경로가 없어 `디스트로이` 딜 기여 0인 상태임을 인지하고 진행.

- Q4: 저격 모드 수치가 스킬 레벨 placeholder 없이 고정값?
  - A: **고정값으로 파싱.**

- Q5: `core_hit` condition이 발동하지 않는 이유는?
  - A: **`core_px`가 1 이상이면 코어 있음, 0이면 없음 판정이라 그럴 것.** 기존에는 기본공격에만 코어 판정이 있었고 명중률 기반 계산이라 괜찮았지만, **이번이 스킬에 코어 판정이 붙는 첫 사례라 다른 방식이 필요할 수 있다.**
  - → 현 코드는 `state["enemy"]["has_core"]`를 보는데 이 키를 세팅하는 경로가 없어 항상 거짓. `core_px >= 1` 기준으로 고쳐야 하고, 스킬 코어 딜은 확률 판정이 아니라 **확정 코어 명중**으로 다뤄야 한다.

- Q6: DPS 관련 여부를 임의 판단하지 말 것 (유저 지적)
  - A: `squad_ammo_consume` 계열을 "게이지 보류라 무효"로 넘겼던 것은 오판. **리틀 머메이드 `거품 난사`·일레그 `고스트 버스터 2`가 이 카운터로 직접 딜을 넣는다.** 벨벳도 탄환 소모 기믹 보유(`gauge_consume_as_ammo`로 이미 파싱됨).
  - → 실측 재확인 결과 `squad_ammo_consume:N` timing은 **구현되어 있다**(IMPL-STATUS의 ❌가 낡음).
